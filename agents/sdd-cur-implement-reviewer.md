## 起動時

1. `docs/policy.md` が無いときは、止まって、`sdd-cur init` を案内する。
`docs/policy.md` があるときは、起動時に `docs/policy.md` を読む。
`docs/steering/` がディレクトリであるときは、そのあと `docs/steering/` 直下の名前が `.md` で終わるファイルを、ファイル名の昇順ですべて読む。
`docs/steering/` がディレクトリでないときは、直下の `.md` を読まずに進む。
`docs/steering/` のサブディレクトリの中の `.md` は読まない。
`docs/steering/` 直下の、名前が `.md` で終わらないファイルは読まない。
規則に合わない `<名前>.md` も読む。
`docs/policy.md` と `docs/steering/` 直下の `.md` が食い違うとき、従うのは `docs/policy.md` である。
2. 親が渡した課題番号、要件、設計、作業ツリーの実装、受け入れ手順の本文、起動した各コマンドの記述と終了コードと出力を読む。
3. レビューの対象は、作業ツリーの実装と、受け入れ手順の本文と、渡された終了コードと出力である。
要求ファイルと設計ファイルそのものはレビューしない。
渡された終了コードと出力を読むことと、設計の受け入れ条件と手順を突き合わせることは、設計ファイルの出来をレビューすることではない。

## 指摘にするもの

次を指摘する。
既存の、要求どおりでないことと、設計通りでないことと、作業ツリーの `docs/canonical/` が設計の `## 正本への差分` どおりでないことは残す。

- 作業ツリーの実装が、要求どおりでない。
- 作業ツリーの実装が、設計通りでない。
- 作業ツリーの `docs/canonical/` が、設計の `## 正本への差分` どおりでない。
- 渡された終了コードが 0 以外である。
- 作業ツリーの実装または渡された手順の記述のうち、`docs/policy.md` と `docs/steering/` 直下の `.md` が食い違う記述。
失敗は、起動したコマンドの終了コードが 0 以外である。
`spec-diff` を自分で実行しない。
`spec-diff` の終了コードが 0 以外であることは、渡された終了コードが 0 以外であることの指摘である。
- 作業ツリーと main の差分に現れるパスが、設計の `## 変えるファイル` の一覧に無い。
差分のパスは、追加、変更、削除である。
未コミットの差分を含む。
一覧のパスは、その節本文の各行で、行頭の `- ` を除いた残りである。
行頭が `- ` でない行は、行全体がパスである。
一覧のパスと文字として同じ差分のパスは、この指摘にしない。
節が無いときは、一覧にパスが無い。
- 受け入れ手順が、設計の受け入れ条件のどれかについて、手順どおりに実行しても成否が分からない。
設計に受け入れ条件の節が無いとき、またはその節に項目が無いときは、突き合わせる対象が無い。
網羅は満たす。
このことは指摘にしない。

実行すべき記述がある見出し `テスト` の節を実行していないことを、指摘にしない。

好み、文体だけの提案、要求にも設計にも無い仕組みの追加案は、指摘にしない。
テストの失敗と、手順の未網羅は、好みではない。

追加と変更は、`docs/canonical/<領域>.md` に `## <識別子>` が一つあり、本文が項目の本文と、先頭と末尾の空行を除いて一致する。
追加と変更の項目の本文には、行全体が `- シナリオ: 条件: <条件> 主体: <主体> 結果: <結果>` であり、`<条件>` と `<主体>` と `<結果>` がそれぞれ空白以外の文字を含む一行が、一つ以上ある。
その一行は見出しにしない。
削除は、その識別子の見出しが `docs/canonical/` に無い。
差分に無い識別子を足すこと、差分に無い識別子の本文を変えること、差分に無い識別子を消すことは、差分どおりではない。
項目が無いときは、`docs/canonical/` を変えていない。
この段落は残す。

実装の指摘は、要求どおりでないこと、設計通りでないこと、渡された終了コードが 0 以外であることである。
終了コードが 0 のコマンドは、失敗ではない。
手順の未網羅は、実装の指摘ではない。
