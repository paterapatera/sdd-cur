# 43 レビュー判定を最後の非空行以外からも読む

対象は [Issue #43](https://github.com/paterapatera/sdd-cur/issues/43)。要求、設計、実装の三つのレビュー手順で、判定の分岐がレスポンスの最後の非空行だけに掛かる。確認行の位置も、手順の文面が揺れる。

## 現状

親は、レスポンスの最後の非空行が `判定: 合格` か `判定: 不合格` かだけで進む。判定のあとに一行でもあると、要求と設計は停止し、実装は失敗で終わる。中身が正しくても、末尾の一行でレビュー全体が止まる。実装は、再試行しても回数を引き継がず、最初からになる。

不合格のとき、要求と設計のスキルは「判定行より前が `確認: あり`」と書く。要求と設計のレビュー役は「直前の非空行」と書く。差分の行が間に入ると、どちらで分岐するかが文面から一通りにならない。

| 手順 | 親が分岐を書く場所 | レビュー役 |
|---|---|---|
| 要求 | `skills/sdd-cur/SKILL.md` の要件 | `agents/sdd-cur-req-reviewer.md` |
| 設計 | `skills/sdd-cur/SKILL.md` の設計 | `agents/sdd-cur-design-reviewer.md` |
| 実装 | `skills/sdd-cur-implement/SKILL.md` | `agents/sdd-cur-implement-reviewer.md` |

実装のレビュー手順に、`確認: あり` と `確認: なし` は無い。設計 22 は、実装の分岐を最後の非空行だけ、と書く。

## 受け入れ条件

- 要求、設計、実装のレビュー手順は、レスポンス本文を下から見て、行全体が `判定: 合格` または `判定: 不合格` と一致する行を探す。最初に見つかった行を判定行とする。
- 判定行が `判定: 合格` のとき、その後ろに非空行があっても、三つの手順は合格として進む。
- 判定行が `判定: 不合格` のとき、その後ろに非空行があっても、三つの手順は不合格として進む。
- 行全体が `判定: 合格` または `判定: 不合格` と一致する行が無いとき、三つの手順は、そのレビューをあと 1 回だけやり直す。同じレビューの起動は、合計最大 2 回である。
- 合計 2 回起動しても、行全体が `判定: 合格` または `判定: 不合格` と一致する行が無いときは、要求と設計はレスポンスを人に見せて止まる。実装は理由 `レビューの判定がありません` で失敗して終わる。
- 判定行が `判定: 不合格` のとき、要求と設計のレビュー手順は、判定行より前を下から見て、行全体が `確認: あり` または `確認: なし` と一致する行を探す。最初に見つかった行で確認を分岐する。
- 判定行が `判定: 不合格` のとき、要求と設計のレビュー役は、確認の位置を、判定行より前を下から探して最初に行全体が一致した行として書く。
- 判定行が `判定: 不合格` なのに、判定行より前に行全体が `確認: あり` または `確認: なし` と一致する行が無いとき、要求と設計はレスポンスを人に見せて止まる。修正は起動しない。
- 実装のレビュー手順は、`確認: あり` と `確認: なし` では分岐しない。

## 決定

判定の印は、レスポンス本文の行のうち、行全体が `判定: 合格` または `判定: 不合格` と一致する行である。要求、設計、実装のレビュー手順は、本文を下から探し、最初に見つかった行を判定行とする。その後ろに非空行があっても、その判定で分岐する。

判定行が `判定: 合格` のときは、合格として進む。判定行が `判定: 不合格` のときは、不合格として進む。

行全体が `判定: 合格` または `判定: 不合格` と一致する行が無いレビューは、印が壊れている。壊れた印のレビューは、同じレビューをあと 1 回だけやり直す。起動は、合計最大 2 回である。やり直したレスポンスも、同じ探し方で判定行を決める。

やり直したあと、合計 2 回起動してもなお行全体が `判定: 合格` または `判定: 不合格` と一致する行が無いときは、現状どおり終わる。要求と設計はレスポンスを人に見せて止まる。実装は理由 `レビューの判定がありません` で失敗して終わる。

判定行が `判定: 不合格` のとき、確認の印は、`確認: あり` と `確認: なし` である。要求と設計のレビュー手順は、判定の印と同じく、行全体が一致する行を読む。探す範囲は、判定行より前である。下から探し、最初に見つかった行で確認を分岐する。

判定行が `判定: 不合格` なのに、判定行より前に行全体が `確認: あり` または `確認: なし` と一致する行が無いとき、要求と設計はレスポンスを人に見せて止まる。修正は起動しない。

要求と設計のレビュー役は、確認の位置を、この同じ読み方で書く。

実装のレビュー手順は、確認の印では分岐しない。

## 範囲外

次は、この要件に含めない。

- 合格と不合格の意味の変更
- 指摘の保存
- 課題の作成とクローズ
- ラベルの変更
- 受け入れ手順
- 完了処理
- Forgejo、Jira、Backlog
