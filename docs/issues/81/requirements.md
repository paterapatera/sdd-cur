# 81 同じアカウントの二つのクローンが同じ課題を実装しないようにする

対象は [Issue #81](https://github.com/paterapatera/sdd-cur/issues/81)。同じアカウントで動く二つのクローンが、同じ課題の着手を同時に取ったとき、続けるのは一つのクローンだけである。

手を入れる対象は、課題ランナー（`src/runner.ts`、`src/github.ts`）である。必要なら `docs/conventions.md` も含む。

## 現状

`poll` は、担当者が自分であり、「実装依頼」があり、「実装中」が無い課題を選ぶ。

`process` は課題を読み直し、ラベルを判定する。実装の着手は、「実装依頼」を外し、「実装中」を付ける。付け替えたあと、ほかのクローンが同時に付け替えていないかは確かめない。

ラベルの付け替えは原子的ではない。二つのクローンが同じ周期で `poll` すると、どちらも判定を通る。どちらも実装に進む。

修正の着手は、「実装完了」を外し、「実装中」を付ける。人を通さずに進める軽微な修正の着手は、「実装中」を付ける。どちらも、付けたあと、ほかのクローンが同時に付けていないかは確かめない。

設計 6 の受け入れ条件「同じ課題を二つのクローンが実装しない」を、今の着手は満たしていない。二つのクローンが同じ作業ブランチへ別々の実装を push しようとし、片方は拒否されるか、マージリクエストが二重にできる。

## 受け入れ条件

- 同じアカウントで動く二つのクローンが、同じ課題の実装、修正、軽微な修正のいずれかの着手を同時に取ったとき、続けるのは一つだけである。
- 続けないクローンは、作業ブランチを変えない。
- 続けないクローンは、マージリクエストを変えない。
- 続けないクローンは、ラベルを変えない。
- 続けないクローンは、次の `poll` に戻る。

## 決め方

どのクローンが続けるかの決め方は、この要件では決めない。設計が決める。

## 範囲外

次は、この要件に含めない。

- 失敗した課題の扱い（#82）
- 別のアカウントで動くクローンどうしの排他。担当者で分かれている。
