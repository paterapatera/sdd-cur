# 36 要求レビューで一意・検証可能・無矛盾を見る

対象は [Issue #36](https://github.com/paterapatera/sdd-cur/issues/36)。要求レビューは、一つの要求が一通りに読め、確かめられ、集まりとして矛盾も未決も無いことを、不合格の理由にする。確認コメントの本文は、決められない点を一度に一つにする。

## 受け入れ条件

- 要求レビューは、一つの要求が一通りに読めないとき、不合格にする。
- 一通りに読めない要求とは、義務を二つ以上含む要求、または二通り以上に読める要求である。
- 要求レビューは、一つの要求が確かめられないとき、不合格にする。
- 確かめられる要求とは、満たされたか満たされていないかを、その要求に書いてある結果で判定できる要求である。
- 要求レビューは、要求の集まりに矛盾があるとき、不合格にする。
- 矛盾とは、集まりの中の要求が同時に満たせないことである。
- 要求レビューは、要求の集まりに未決が残っているとき、不合格にする。
- 未決とは、集まりの中に、まだ一つの結果へ決まっていない点があることである。
- 矛盾と未決を見る集まりは、レビューしている一つの要求ファイルに書いた要求である。
- 要求レビュー役は、見出し、範囲、人が決めた条件、スコアの書き込みに関する従来の指摘を、引き続き指摘する。
- 確認コメントの本文は、決められない点を一つだけ書く。
- 確認コメントの一つの本文に、決定を二つ以上書かない。
- 確認コメントの本文に、スコアを書かない。
- SDD スキルの確認手順は、本要件の「確認」節のとおりである。
- SDD スキルが確認を投稿するとき、決められない点は payload に一つだけ入れる。
- 確認コメントの本文の形は、要件への確認と設計への確認で同じである。
- 確認コメントの本文が扱う決められない点は、一つである。
- 複数の決定とスコアを一つの本文にまとめた確認は、投稿しない。

## 要求レビュー

対象は、要求レビュー役 `sdd-cur-req-reviewer` である。

レビューは、要求ファイルを読み、指摘と修正指示だけを返す。ファイルは変えない。指摘はファイルにも課題コメントにも残さない。

出力の項目は、今の要求レビュー役のままである。指摘、直す箇所と直したあとの文の差分、人の確認が要るか、判定である。
不合格の理由に当たるものが一つでもあるときは、指摘とし、`判定: 不合格` とする。

次に当たるものを指摘する。

- 一つの要求が、義務を二つ以上含む。
- 一つの要求が、二通り以上に読める。
- 一つの要求が、満たされたか満たされていないかを、その要求に書いてある結果で判定できない。
- 要求どうしが、同時に満たせない。
- 要求の集まりに、まだ一つの結果へ決まっていない点が残っている。

集まりは、レビューしている一つの要求ファイルに書いた要求である。

受け入れ条件の一つの箇条に、サブエージェント四つ、配置、レビュー、修正案、人に確認しないことまでが入っている形は、義務を二つ以上含む要求である。この形は指摘する。

未決のうち、課題、計画、人が決めた条件から読める結果があるときは、その結果に直す差分を書く。
未決のうち、課題、計画、人が決めた条件から読めないときは、差分で結果を決めず、`確認: あり` とする。
複数の義務を分けるとき、分けたあとの各文は、課題、計画、人が決めた条件にある義務だけである。
要求レビュー役は、分離や差分の提案に、新しい挙動を足さない。

好み、文体だけの提案、課題に無い仕組みの追加案は、指摘にしない。

## 確認

確認は、課題のコメントだけに書く。種別の印は `sdd-cur: 確認` である。印の行より後ろが本文である。

本文が扱う決められない点は、一つである。その一つの点に選択肢があっても、点は一つである。別の点は、別の確認コメントにする。

一つの本文に、決定を二つ以上書かない。本文にスコアを書かない。

複数の決定とスコアを一つの本文にまとめた確認は、投稿しない。

未回答の確認があるあいだ、次の確認は投稿しない。まだ要求または設計へ反映していない回答があるあいだも、次の確認は投稿しない。これは、約束のままである。

本文の形は、要件への確認と設計への確認で同じである。どちらの本文も、決められない点は一つである。

## 範囲外

次は、この要件に含めない。

- 設計と実装への採点付き質問
- レビュー指摘の保存
- 設計レビュー役の指摘観点
- 実装レビュー役の指摘観点
- 要求を作るときの採点付き質問（#26）
- 生成済みの要求ファイルを、この課題で書き直すこと
- 課題の作成とクローズ
- ラベルの変更
- 実装
- 受け入れ手順
- 完了処理
- Forgejo、Jira、Backlog
