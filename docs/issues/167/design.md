### `## 合格のあとの案内` の並び

次の順で書く。一文を一行のままである。

1. 要件の合格の案内は、Cursor の質問機能で「設計に進む」と「ここで止める」を、この順で出すことである。
2. 設計の合格の案内は、Cursor の質問機能で「実装依頼する」と「ここで止める」を、この順で出すことである。
3. この二つの案内は、閉じるかどうかの確認とは別である。
4. 案内を人に伝えるときは、Cursor の質問機能で上の二択を出す。この質問は、「満たされているかの判断」の節が案内を伝えるとしたときだけ出す。
5. 要件の合格の案内を出す直前の手順（`show` の再実行、判断の直前の一文）は、各節に残す。案内の出し方と選択のあとは、ここに書く。
6. 要件側。「設計に進む」と「ここで止める」の質問を出しているあいだ、人がどちらかを選ぶまで、設計の手順に入らない。「設計に進む」と「ここで止める」の質問を出しているあいだ、人がどちらかを選ぶまで、設計の作成役と設計の修正役を起動しない。選択のあと（ここで止める／設計に進む）は、今の SKILL の意味のままここに集約する。`unanswered` または `nextAnswer` の枝と、`action` が `合格` でない枝は、各節の置き換え囲みの短い枝に残す。
7. 設計側。設計の合格の案内を出すとき、人に伝える前に `show` を改めて実行する、は各節に残してもよいが、案内と禁止の本文はここに集約する。次の段へ進む質問を出しているあいだは、人がどちらかを選ぶまで、作業ブランチを push しないし、「実装依頼」を付けないし、`sdd-cur request <番号>` を実行しない、と一文で書く。
8. 「ここで止める」を選んだとき（設計の合格）は、今の push・ラベル・実装依頼・request・push するブランチの意味のまま。
9. 「実装依頼する」を選んだとき、質問でのみなし、request 実行、gh とラベル、実装・受け入れ手順・完了処理しない、は今のまま。
10. `unanswered` が空でない、または `nextAnswer` が `null` でないとき、および `action` が `合格` でないときの短い枝は、要件・設計・回答の各節の置き換え囲みに残す。意味は今の SKILL のままである。
11. 通常時の三つ。ラベルは変えない。実装依頼は人が付ける。push は人が行う。
12. 設計の合格の案内で人が「実装依頼する」を選んだときの例外（request、みなし、コマンドが push と付与、gh とラベル、実装・受け入れ手順・完了処理しない）。

囲みの外の番号付きリストはスキルへ写さない。実装は、現行 `skills/sdd-cur/SKILL.md` の 168 行から 352 行、429 行から 497 行、509 行から 510 行、547 行から 558 行、585 行から 597 行に相当する一文を、上の節へ移し、意味を欠かさない。
