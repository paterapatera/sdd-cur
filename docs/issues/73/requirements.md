# 73 スカッシュマージ後のコミットメッセージに課題番号を含める

対象は [Issue #73](https://github.com/paterapatera/sdd-cur/issues/73)。完了処理のスカッシュマージで、デフォルトブランチに残るコミットメッセージへ、課題番号を含める。スカッシュマージ後のコミットメッセージから、どの課題のマージかが分かるようにする。

#7 の完了処理は、マージリクエストのスカッシュマージと「マージ済み」を行う。#18 は、そのスカッシュマージのときにブランチを削除する。この要件は、そのスカッシュマージのあと、デフォルトブランチに残るコミットの件名に課題番号を含めることを足す。

## 現状

実装のコミットメッセージは `feat: 課題 <番号> を実装する` である。このメッセージには課題番号がある。

マージリクエストの題は課題の題であり、番号は含まれない。`src/runner.ts` がマージリクエストを作るとき、題は課題の題である。

`src/github.ts` の `squashMerge` は `pr merge --squash --delete-branch` であり、件名も本文も渡さない。スカッシュ後のコミット件名はマージリクエストの題になり、課題番号は残らない。

スカッシュマージは完了処理だけが行う。完了処理は、課題ランナーと、Project A の Cursor で人が起動する完了スキルの、両方から呼ぶ。

## 受け入れ条件

- 完了処理がスカッシュマージしたあと、デフォルトブランチに残るコミットの件名に、その課題の番号が含まれる。
- その件名から、どの課題のマージかが分かる。
- 課題ランナー経由と完了スキル経由の両方で、同じ完了処理がこの件名を残す。

## 範囲外

次は、この要件に含めない。

- すでにマージ済みのマージリクエストを、もう一度マージしないこと（#7）
- 「マージ済み」を付けること（#7）
- 一つのプロジェクトで、課題ランナーと完了スキルを同時には有効にできないこと（#7）
- マージしたブランチの削除（#18）
- 実装のコミットメッセージ `feat: 課題 <番号> を実装する` を変えること
- 不具合修正のコミットメッセージ `fix: 課題 <番号> の不具合を修正する` を変えること
- 「動作確認OK」を付けること。付けるのは人である
- 課題の作成とクローズ
- ラベルの変更
- 受け入れ手順
- 着手、要件、設計、確認、回答の取り込み
- Forgejo、Jira、Backlog
