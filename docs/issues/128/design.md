## 決定

シナリオの一行は、見出しではない。行全体が次で分かれる行だけである。

行は `- シナリオ: 条件: ` で始まる。接頭辞の後ろで、最初の ` 主体: ` より前が `<条件>` である。その ` 主体: ` の後ろで、最初の ` 結果: ` より前が `<主体>` である。その ` 結果: ` の後ろが `<結果>` である。` 主体: ` が無い行と、` 結果: ` が無い行は、シナリオの一行ではない。`<条件>` と `<主体>` と `<結果>` は、それぞれ空白以外の文字を一つ以上含む。空白は、スペース、タブ、改行、復帰、全角スペースである。前後の空白だけを理由に、空白以外の文字がある部分を除かない。

項目の見出しの取り方は、`validateCanonicalDelta` が項目にする行と同じである。見る節は、最初の、行全体が `## 正本への差分` である節だけである。節は、その次の行から、行が `## ` で始まる前までである。項目の本文は、見出しの次の行から、次の項目の見出しの前までである。最後の項目の本文は、節の末尾までである。囲みコードブロックでは分けない。本文の各行を、上の分け方で見る。

追加または変更の項目の本文に、シナリオの一行が一つも無いとき、その項目ごとに違反を一つ返す。違反は `シナリオがありません: <識別子>` である。`<識別子>` は、見出しの `REQ-<番号>` であり、領域は付けない。シナリオの一行が一つ以上ある項目には、違反を足さない。削除の項目には、シナリオの一行が無くても、この違反を足さない。

判定のコードは `src/conventions.ts` の `validateSpecForm` にある。`kind` が `design` であり、印があるときだけ、上の違反を探す。印が無いときは、今どおり空配列を返し、この探索はしない。`kind` が `requirements` のときは、この違反を足さない。`src/cli.ts` は変えない。`cmdValidate` は、今どおり `validateSpecForm` の戻りを、パスを前置して標準エラーへ書く。違反が一つ以上あるときの終了コードは 1 である。シナリオの違反が無いとき、`validateSpecForm` の戻り値は、この課題の前と同じである。違反があるときは、この課題の前の戻りのうしろへ、節の上から下の順に足す。

終了コードを見るフィクスチャは、シナリオの違反以外の `validateSpecForm` の違反が無く、変えるファイルのパスの違反も無く、根拠の引用も無い。この実行は `git` を起動しない。`gh` を起動しない。

七文は、次の七行である。行のあいだに空行は入れない。この順で、節「仕様の正本」と節「要件と設計の形式」の両方へ足す。どちらの節にも、同じ七行がある。

```
シナリオの一行は、行全体が `- シナリオ: 条件: <条件> 主体: <主体> 結果: <結果>` である。
`<条件>` と `<主体>` と `<結果>` は、それぞれ空白以外の文字を含む。
追加と変更の項目の本文には、その一行が一つ以上ある。
シナリオは見出しにしない。
印がある設計で、追加または変更の項目にその一行が無いと、`validate` は失敗する。
既存の要求は、変更されるときにだけシナリオを足し、一括では書き換えない。
削除の項目にはシナリオを要しない。
```

七行を改行でつないだものを塊とする。塊の末尾は、七行目の改行である。塊の中に空行は無い。

節「仕様の正本」では、その節の最後の非空行の次にある空行の次に塊を置く。その最後の非空行は、「課題ごとのファイル」のままである、で終わる。塊の次は空行一つであり、その次は、行全体が `## レビューが読む範囲` である。節「要件と設計の形式」では、ファイル末尾の、囲みを閉じる行の次に空行一つを置き、その次に塊を置く。塊より後ろは書かない。どちらの節でも、今ある行の文言は変えない。

設計作成役と実装レビュー役へ足す二文は、次の二行である。行のあいだに空行は入れない。

```
追加と変更の項目の本文には、行全体が `- シナリオ: 条件: <条件> 主体: <主体> 結果: <結果>` であり、`<条件>` と `<主体>` と `<結果>` がそれぞれ空白以外の文字を含む一行が、一つ以上ある。

設計作成役では、行全体が `項目の本文は、その識別子の要求の内容である。` である行の次に、この二行を置く。実装レビュー役では、先頭と末尾の空行を除いて一致する、で終わる行の次に、この二行を置く。

```

追加と変更の項目の本文には、その一行が一つ以上ある。

行全体が `- 変更または削除の項目に、その識別子の要求の内容が無い。` である行の次に、この四行を置く。三つの役とも、フロントマターと、今ある行の文言は変えない。足す行の前後に、無かった空行は足さない。一文は一行のままである。

## テスト

`bun test` で実行する。`gh` は起動しない。`git` は起動しない。ホームディレクトリと、実行中の Cursor のスキルは触らない。ファイルを作るときは一時ディレクトリを使い、終わったら消す。新しい `test` は `src/128.test.ts` だけに足す。既存の `src/*.test.ts` に、新しい `test` は足さない。

終了コードは、リポジトリの `bun src/cli.ts validate <番号>` を、一時ディレクトリを作業ディレクトリにして実行する。フィクスチャに根拠の引用は無い。

- 印がある設計の追加の項目の本文に、行全体が `- シナリオ: 条件: 見る 主体: 項目 結果: 残る` である行があるとき、`validateSpecForm` は `シナリオがありません` を返さない。条件が空白だけの行、行頭に空白がある行、行全体が `### シナリオ` である行は、シナリオの一行にしない。その行だけの項目は、違反になる。[1][2][3]
- 印がある設計の追加または変更の項目にシナリオの一行が無いとき、`validateSpecForm` は `シナリオがありません: REQ-1` を返す。同じ実行の終了コードは 1 である。標準エラーに、その違反がある。[5]
- 文字列 `シナリオがありません` は `src/conventions.ts` にあり、`src/cli.ts` には無い。`validateSpecForm` は `src/conventions.ts` から import する。[6]
- 印がある設計で、削除の項目にシナリオの一行が無く、追加の項目にはシナリオの一行があるとき、`シナリオがありません` は返らない。終了コードは 0 である。[7]
- 印が無い設計に、シナリオの無い追加の項目があるとき、`validateSpecForm` は空配列を返す。終了コードは 0 である。[8]
- 印がある設計に、追加の項目も変更の項目も無いとき、`シナリオがありません` は返らない。終了コードは 0 である。削除だけの項目も、ここへ含める。[9]
