# 87 既存の仕様を正本へ移し、レビュー役が読む範囲を正本に絞る

対象は [Issue #87](https://github.com/paterapatera/sdd-cur/issues/87)。#86 で作る正本へ、今ある `docs/issues/` の内容を移す。移したあと、要求レビュー役と設計レビュー役が食い違いと巻き戻りを探すとき、読む範囲は、その正本と、対象課題の「関係する課題」に挙げた課題の仕様だけである。

設計 37 は、二つのレビュー役の起動時に、`docs/issues/` にある既存の `requirements.md` と `design.md` を読む、と書いている。この設計は、その読む範囲を差し替える。同じ手順、衝突する文、巻き戻りの定義は、設計 37 のままである。

## 正本の形

正本は `docs/canonical/<領域>.md` である。直下のファイルだけである。`<領域>` は英小文字で始まり、英小文字と数字が続く。区切りのハイフンを含んでよい。ハイフンは先頭、末尾、連続には使わない。

領域ファイルの最初の非空行は `# <領域>` である。`<領域>` は、ファイル名から `.md` を除いたものと一文字も違わない。

## 移行

実装は、作業ツリーにある `docs/issues/<番号>/requirements.md` と `docs/issues/<番号>/design.md` だけを、移す元にする。上の表に無い番号は移さない。`docs/issues/87/requirements.md` は、この表の手順では移さない。#87 の正本への要求は、「この課題の要求」の三件だけである。

移す候補は、次の順で集める。ファイルが無い側は飛ばす。

1. `design.md` の「受け入れ条件」の箇条を、ファイルの上から。
2. `requirements.md` の「受け入れ条件」の箇条のうち、設計の受け入れ条件が同じ結果を述べていないもの。上から。
3. `design.md` の「決定」のうち、ここまでで同じ結果が無いもの。表は行ごと、箇条は箇条ごと、段落は一つの結果ごと。
4. `requirements.md` の「決定」のうち、ここまでで同じ結果が無いもの。同じ単位である。

「現状」「目的」「範囲外」「テスト」「実装の順序」「関係する課題」は移さない。反映済みの記録も移さない。箇条の結果が、範囲外に書かれた事項だけであるときは移さない。

同じ結果とは、同じ主体が、同じ条件で、同じ結果になることである。文言が違っても、その三つが同じなら同じ結果である。

候補は、次の順で落とす。

1. 「置き換わる決定」の書かない結果を含む候補は、書かない。書く結果の側は残す。
2. より大きい番号の課題に、同じ主体の同じ結果の候補があるときは、小さい番号の候補を書かない。大きい番号の候補を残す。
3. 残った候補の結果を、この課題の変更を入れる前の main のコード、`skills/`、`agents/`、`docs/conventions.md` が行わないときは、書かない。「置き換わる決定」の書く側と、「この課題の要求」は、この段で落とさない。

残った候補を、一つずつ要求にする。本文は、次の二行を空行で区切ったものである。

```
もとになった課題は #<番号> である。

<残した候補の結果>
```

`<番号>` は、その候補を残した課題の番号である。結果の文は、箇条の印を除いた、その候補の文である。表の行は、項目と内容が読める一文にする。設計 86 の見出し以外の印は足さない。

`docs/issues/<番号>/` のファイルは、この手順で変えない。
