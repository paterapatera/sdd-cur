# 123 正本が差分どおりに変わったかを CLI で確かめる

<!-- sdd-cur:form -->

対象は [Issue #123](https://github.com/paterapatera/sdd-cur/issues/123)。作業ツリーで、リモートのデフォルトブランチの正本に、設計の `## 正本への差分` を当てた結果と、作業ツリーの `docs/canonical/` が一致するかを、サブコマンド `spec-diff` で確かめる。

`specDiff` は、標準出力にも標準エラーにも書かない。一致のときは空配列を返す。不一致のときは、標準エラーへ書く行の配列を返す。行の中に改行は無い。失敗のときは、`message` がその一行である `Error` を投げる。`src/cli.ts` は、その `message` だけを標準エラーへ書く。配列の各文字列は `console.error` で一行ずつ書く。

```ts
export async function specDiff(options: {
  cwd: string
  issueNumber: number
  git: GitRunner
}): Promise<string[]>
```

`GitRunner` の `options.cwd` は、`specDiff` に渡した `cwd` と一文字も違わない。`src/cli.ts` が渡す `cwd` は `process.cwd()` である。設計ファイルは、`specPaths` の `design` を `cwd` から読んだものである。

ブランチ名を取る二つの git は、次の引数である。リモート名は、一つ目の標準出力から取る。

```ts
;["remote"]
;["symbolic-ref", `refs/remotes/${remote}/HEAD`]
```

一つ目の終了コードが 0 のとき、取れた標準出力からリモート名を取る。二つ目の終了コードが 0 のとき、取れた標準出力から参照を取る。どちらかが例外を投げたとき、または終了コードが 0 でないときは `git を実行できません` である。

基準の一覧とファイルは、参照を `<ref>` として、次の引数である。

```ts
;["ls-tree", "--name-only", ref, "docs/canonical"]
;["show", `${ref}:docs/canonical/<領域>.md`]
```

例外ではなく終了コードが 0 でない `show` のときは、そのファイルに識別子が無い。例外を投げたときは `git を実行できません` である。`show` は、一覧の標準出力のうち、`docs/canonical/<領域>.md` である行だけを、その順に行う。`<領域>` は、差分の見出しの領域と同じパターンである。

## 比較

見出しの領域と識別子は、`### 追加 <領域> REQ-<番号>`、`### 変更 <領域> REQ-<番号>`、`### 削除 <領域> REQ-<番号>` の、行全体がこの形である行から取る。`<領域>` は英小文字で始まり、英小文字と数字が続き、区切りのハイフンを含んでよい。ハイフンは先頭、末尾、連続には使わない。`<番号>` は十進で、先頭の零は無い。この形でない行は、項目にしない。

差分の節は、最初の、行全体が `## 正本への差分` である行の次から、行が `## ` で始まる前までである。この節が無いときは、項目が無いときと同じであり、当てた結果は基準の正本のままである。

項目の本文は、その見出しの次の行から、次の項目の見出しの前までである。最後の項目の本文は、節の末尾までである。項目の本文は、正本の `## REQ-<番号>` の行を含まない。

要求の見出しは、行全体が `## REQ-<番号>` である行である。本文は、その次の行から、次の要求の見出しの前までである。最後の要求の本文は、ファイルの末尾までである。見出しの行は本文に含めない。

本文は、先頭と末尾の空行を除いて一文字も違わないとき一致する。空行は、空白以外の文字が無い行である。

組は、領域と識別子の組である。基準の組は、基準のファイルの要求である。領域は、`docs/canonical/<領域>.md` の `<領域>` である。作業ツリーの組も、同じ取り方である。サブディレクトリは見ない。ファイルであり、名前がこの形であるものだけを見る。

当てる順序は、差分の節の上から下である。追加は、その組の本文を項目の本文にする。変更も、同じである。削除は、その組を除く。無い組の削除は、除いたままである。削除の項目の本文は、比較に使わない。

要求の見出しでも項目の見出しでもない行は、組にしない。ファイルの前文が違っても、組の本文が一致すれば、その組は不一致にしない。

## 出力

不一致一件につき、標準エラーへ一行を書く。行の中に改行は無い。

当てた結果にだけある組は、`正本が一致しません: ` のあとに領域、空白一つ、識別子、空白一つ、`作業ツリーにありません` を書く。

作業ツリーにだけある組は、`正本が一致しません: ` のあとに領域、空白一つ、識別子、空白一つ、`作業ツリーにだけあります` を書く。

本文が違う組は、`正本が一致しません: ` のあとに領域、空白一つ、識別子、空白一つ、`本文が違います` を書く。

同じ組の行は一つである。

一件以上あるとき終了コードは 1 である。一件も無いとき終了コードは 0 であり、標準エラーには書かない。標準出力へは、成功のときも失敗のときも、何も書かない。

失敗の一行を書くときは、不一致の行は書かない。失敗の一行は、次のいずれか一つである。

| とき | 一行 |
|---|---|
| 課題番号が不正 | `番号が不正です` |
| 設計ファイルを読めない | `仕様を読めません` |
| プロセスを起動できない、またはブランチ名を取る git の終了コードが 0 でない | `git を実行できません` |

引数が一つでないときの標準エラーは、この表には入れない。使い方の表示である。

## 例

基準の `docs/canonical/spec.md` は、末尾の改行を含めて、次である。

```
# spec

## REQ-1
基準の本文です。
## REQ-2
消える本文です。
```

設計の `## 正本への差分` の項目は、次である。節の見出しそのものは、この例の行にしない。

```
### 変更 spec REQ-1

変えた本文です。

### 削除 spec REQ-2

消える本文です。

### 追加 spec REQ-3

足す本文です。
```

作業ツリーの `docs/canonical/spec.md` が、末尾の改行を含めて次であるとき、組の順は違っても本文は一致する。終了コードは 0 であり、標準出力も標準エラーも空である。

```
# spec

## REQ-3
足す本文です。
## REQ-1
変えた本文です。
```

このとき `GitRunner` が受ける引数は、次の四回である。`cwd` は渡した作業ディレクトリである。

```ts
;["remote"]
;["symbolic-ref", "refs/remotes/origin/HEAD"]
;["ls-tree", "--name-only", "refs/remotes/origin/main", "docs/canonical"]
;["show", "refs/remotes/origin/main:docs/canonical/spec.md"]
```

一つ目の標準出力は `origin\n`、二つ目は `refs/remotes/origin/main\n`、三つ目は `docs/canonical/spec.md\n`、四つ目は基準のファイルである。終了コードは、いずれも 0 である。

作業ツリーの `spec.md` が基準のファイルのままであるときは、標準エラーには次の三つの行がある。行の順は問わない。終了コードは 1 であり、標準出力は空である。

```
正本が一致しません: spec REQ-1 本文が違います
正本が一致しません: spec REQ-2 作業ツリーにだけあります
正本が一致しません: spec REQ-3 作業ツリーにありません
```

同じ作業ツリーに、末尾の改行を含めて次の `docs/canonical/docs.md` もあるときは、不一致の行が一つ増える。行の順は問わない。

```
# docs

## REQ-9
余です。
```

標準エラーには、`正本が一致しません: docs REQ-9 作業ツリーにだけあります` と、上の三行と同じ字面の行が四つある。

変更の項目の本文が、空行、`変えた本文です。`、空行であるときと、作業ツリーの本文が `変えた本文です。` だけであるときは、その組は一致する。作業ツリーの本文が `変えた本文です。`、空行、`次です。` であり、項目の本文が `変えた本文です。`、`次です。` であるときは、`正本が一致しません: spec REQ-1 本文が違います` である。

設計ファイルが `# 7 題` だけであるとき、項目が無く節だけがあるとき、設計ファイルが無いときは、当てた結果は基準のままである。作業ツリーが基準と一致すれば、終了コードは 0 である。

`docs/canonical/spec.md` の `show` の終了コードが 0 でないときは、基準のそのファイルに識別子が無い。作業ツリーに `REQ-1` があるときは、`正本が一致しません: spec REQ-1 作業ツリーにだけあります` である。

`remote` が例外を投げたとき、または終了コードが 0 でないときは、標準エラーは `git を実行できません` の一行である。標準出力は空であり、終了コードは 1 であり、`symbolic-ref` は呼ばない。

引数が無いときと、引数が `1` と `2` の二つであるときは、標準エラーは使い方の表示と一文字も違わず、その中に行全体が `sdd-cur spec-diff <番号>` である行がある。終了コードは 1 であり、標準出力は空である。引数が `foo`、`0`、`01` のときは、標準エラーは `番号が不正です` の一行であり、終了コードは 1 であり、標準出力は空である。`spec-diff --help` は終了コード 0 であり、標準出力は空であり、標準エラーは使い方の表示である。

設計のパスがディレクトリであるときは、標準エラーは `仕様を読めません` の一行であり、`git` は呼ばない。
