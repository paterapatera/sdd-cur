# 123 正本が差分どおりに変わったかを CLI で確かめる

対象は [Issue #123](https://github.com/paterapatera/sdd-cur/issues/123)。実装の作業ツリーで、リモートのデフォルトブランチの正本に、設計の `## 正本への差分` を当てた結果と、作業ツリーの正本が一致するかを、CLI で確かめる。

課題本文の案は `sdd-cur spec-diff <番号>` である。課題本文は、正本のパスを `docs/spec/` と書く。

手を入れる対象は、`src/cli.ts`、`src/conventions.ts`、`skills/sdd-cur-implement/SKILL.md`、`agents/sdd-cur-implement-reviewer.md`、`docs/policy.md`、`AGENTS.md` である。

重なる課題は #85、#86、#122 である。

比べる相手は、OpenSpec の `openspec archive` である。`openspec archive` は、変更の ADDED、MODIFIED、REMOVED を正本へ機械的に当てる。

## 関係する課題

課題は、次を関係するとする。

- #85（要件と設計の形を決め、CLI で形式を検査する）
- #86（仕様の正本と、課題の差分）
- #122（正本の重複と壊れた文を見つける検査）

#85 の検査は、追加する識別子が反映前の正本にまだ無いことと、変更または削除する識別子がそこにあることを見る。この要件が足すのは、基準の正本に差分を当てた結果と、作業ツリーの正本を、領域と識別子の組で比べる `spec-diff` である。

#86 は、正本を領域ごとのファイルに置き、設計の差分を実装の作業ツリーへ反映し、実装レビュー役が差分どおりかを見ると定める。この要件は、その反映の正否を CLI で確かめる。差分の書式は変えない。

#122 の `spec-check` は、作業ディレクトリの正本そのものについて、近い本文、壊れた文末、空の本文、識別子の重複を見る。この要件は、その検査を変えない。

## 範囲外

次は、この要件に含めない。

- 正本の整理
- 差分の書式の変更（#128）
