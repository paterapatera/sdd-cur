# 90 SDD スキルに、調べるだけの段を足す

対象は [Issue #90](https://github.com/paterapatera/sdd-cur/issues/90)。人が調査を依頼したときだけ、読み取り専用のサブエージェントが今のコード、`show` が返す課題本文とコメント、仕様を調べ、ファイルと行を根拠に答える。要件を書く前の下調べに使う。

比べる相手は、OpenSpec の explore である。取り込む挙動は、この課題の要件にあるものだけである。

重なる課題は #5 と #89 である。#5 の着手、要件、設計、確認、回答は残す。この課題は、そのあいだに調べるだけの段を足す。`docs/issues/5/design.md` は書き換えない。この作業ツリーに `docs/issues/89/` は無い。この設計は、#89 の挙動を足さない。

いまの `skills/sdd-cur/SKILL.md` の段は、着手、要件、設計、確認、回答、禁止である。`subagentFileNames` は九つであり、`install` はその九つだけをコピーする。README の `install` の説明は、その九つをコピーする、と書いている。

## 受け入れ条件

- 人が調査を依頼したとき、SDD スキルは、調べるだけの段の手順を行う。
- 人が調査を依頼していないとき、SDD スキルは、調べるだけの段の手順を行わない。
- `skills/sdd-cur/SKILL.md` の調べるだけの段は、「着手」の後、「要件」の前に置く。見出しは `## 調べる` である。
- 調べるだけの段は、人が課題番号を決めたあとだけ行う。
- 調べるだけの段では、SDD スキルは `bun src/cli.ts show <番号>` を実行する。
- `bun src/cli.ts show <番号>` の終了コードが 0 以外のときは、サブエージェントを起動しない。このときは止まる。
- `show` の終了コードが 0 のあと、`state` が `open` でないとき、業務ラベルが一つでもあるときは、ファイルを変えず、サブエージェントも起動しない。このときは止まる。
- 着手の、`state` が `open` でないときと、業務ラベルが一つでもあるときの止まりの本文は、変えない。
- 課題番号が無いときは、調べるだけの段の手順を行わない。
- 終了コードが 0 であり、`state` が `open` であり、業務ラベルが無いときだけ、調べるだけの段はサブエージェントを一つ起動する。
- そのサブエージェントは、新しいサブエージェントであり、名前は `sdd-cur-explore` である。
- そのサブエージェントのファイルは、`agents/sdd-cur-explore.md` である。
- そのサブエージェントの frontmatter の `name` は `sdd-cur-explore` である。
- そのサブエージェントの frontmatter の `model` は `composer-2.5[fast=false]` である。
- そのサブエージェントは、読み取り専用である。frontmatter に `readonly: true` がある。
- そのサブエージェントは、今のコードを調べる。
- そのサブエージェントは、課題番号に紐づく調査として、`show` が返した課題本文とコメントも調べる。
- そのサブエージェントが仕様として調べる範囲は、システム要求の正本である `docs/canonical/` と、対象課題の `docs/issues/<番号>/` である。
- 起動するときに、課題番号と、人が依頼した調査の内容と、`show` が返した課題本文とコメントを渡す。
- そのサブエージェントは、`show` を実行しない。
- 根拠を示せる点について、そのサブエージェントは、ファイルと行を根拠に答える。
- 根拠を示せない点について、そのサブエージェントは、示せないと答える。
- 調べるだけの段は、ファイルを書かない。
- 調べるだけの段は、課題コメントを書かない。
- 調べるだけの段は、ラベルを変えない。
- 調べるだけの段は、作業ブランチを用意しない。
- `install` は、`sdd-cur-explore.md` を、既存の九つのあとにコピーする。
- README は、調べるだけの段を足す。
- README は、サブエージェント `sdd-cur-explore` を足す。
