# 90 SDD スキルに、調べるだけの段を足す

対象は [Issue #90](https://github.com/paterapatera/sdd-cur/issues/90)。人が依頼したときだけ、読み取り専用のサブエージェントが今のコードと仕様を調べ、ファイルと行を根拠に答える。要件を書く前の下調べに使う。

手を入れる対象は、`skills/sdd-cur/SKILL.md`、新しいサブエージェント、README である。

比べる相手は、OpenSpec の explore である。

重なる課題は #5（SDD スキル）と #89 である。

## 現状

SDD スキルの段は、着手、要件、設計、確認、回答である。要件の前に、今の挙動を調べる段は無い。

サブエージェントは、要求、設計、実装の作成役、レビュー役、修正役の九つである。

## 受け入れ条件

- 人が調査を依頼したとき、SDD スキルは、調べるだけの段の手順を行う。
- 人が調査を依頼していないとき、SDD スキルは、調べるだけの段の手順を行わない。
- `skills/sdd-cur/SKILL.md` の調べるだけの段は、「着手」の後、「要件」の前に置く。
- 調べるだけの段は、人が課題番号を決めたあとだけ行う。
- 調べるだけの段では、SDD スキルは `bun src/cli.ts show <番号>` を実行する。
- 課題番号が無いときは、調べるだけの段の手順を行わない。
- 調べるだけの段では、SDD スキルはサブエージェントを一つ起動する。
- そのサブエージェントは、新しいサブエージェントであり、名前は `sdd-cur-explore` である。
- そのサブエージェントのファイルは、`agents/sdd-cur-explore.md` である。
- そのサブエージェントの frontmatter の `name` は `sdd-cur-explore` である。
- そのサブエージェントの frontmatter の `model` は `composer-2.5[fast=false]` である。
- そのサブエージェントは、読み取り専用である。
- そのサブエージェントは、今のコードを調べる。
- そのサブエージェントが仕様として調べる範囲は、システム要求の正本である `docs/canonical/` と、対象課題の `docs/issues/<番号>/` である。
- 根拠を示せる点について、そのサブエージェントは、ファイルと行を根拠に答える。
- 根拠を示せない点について、そのサブエージェントは、示せないと答える。
- 調べるだけの段は、ファイルを書かない。
- 調べるだけの段は、課題コメントを書かない。
- 調べるだけの段は、ラベルを変えない。
- README は、調べるだけの段を足す。
- README は、サブエージェント `sdd-cur-explore` を足す。

## 決定

新しい読み取り専用サブエージェントの名前は `sdd-cur-explore` である。ファイルは `agents/sdd-cur-explore.md` である。frontmatter の `name` は `sdd-cur-explore` である。frontmatter の `model` は `composer-2.5[fast=false]` である。

`skills/sdd-cur/SKILL.md` の調べるだけの段は、「着手」の後、「要件」の前に置く。調べるだけの段は、人が課題番号を決めたあとだけ行う。調べるだけの段では、SDD スキルは `bun src/cli.ts show <番号>` を実行する。

サブエージェントが仕様として調べる範囲は、システム要求の正本である `docs/canonical/` と、対象課題の `docs/issues/<番号>/` である。

README は、調べるだけの段を足す。README は、サブエージェント `sdd-cur-explore` を足す。
