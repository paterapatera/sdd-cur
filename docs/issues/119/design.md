名前の昇順は、`skillNames.sort()` の既定の並びである。並びは `sdd-cur`、`sdd-cur-complete`、`sdd-cur-create-issue`、`sdd-cur-fix`、`sdd-cur-implement`、`sdd-cur-policy`、`sdd-cur-quick` である。

根拠が無い点と、組が二つ以上ある点は、別である。組がゼロのときは質問である。組が一つである記述だけを、下書きに書く。組が二つ以上の候補は、その記述と、作業ツリー内の一つのファイルと、一つの行番号の組である。人が選んだ組は、明示して起動したときの依頼に含まれる。依頼に無い組は、まだ選んでいない。

一致しない非空行があるときは、先に止まる。このときは、人が候補を選んでもファイルへは書かない。見せる記述は、一つのファイルと一つの行番号があり、その文がまだファイルに無いものである。

`docs/policy.md` が存在し、通常ファイルではないときは、一致しない非空行の手順より先に止まる。内容は変えず、下書きは書かず、理由を人に伝える。非空行の一致は見ない。人が候補を選んでも、そのファイルへは書かない。通常ファイルは、`stat` の結果で `isFile()` が真であるファイルである。

作業ツリーに `package.json` が一つあるときは、そのファイルを読む。複数あるときは、作業ツリーのルートにある `package.json` だけを読む。

作業ツリーに README があるときは、その README を読む。無いときは、README を読まない。README を除き、下書きの手順が読むほかの対象だけで進める。README を根拠にする記述は書かない。

`docs/policy.md` への書き込みが失敗したときは、下書きを完了とみなさない。失敗理由を人に伝えて止まる。失敗したあとの `docs/policy.md` は、書き込みを始める前と同じである。

## 一度に実装できる大きさ

一つの作業が一度に実装できる大きさであるとは、次のとおりである。

- `[<番号>]` を一つ以上持つ作業では、その番号の受け入れ条件に直結する実装を、他の受け入れ条件に直結する実装を含めず、実装作成役の一回の起動で書き終えられる
- `[<番号>]` が無い作業では、その作業の行に書かれた実装を、一回の起動で書き終えられる
