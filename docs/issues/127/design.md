# 127 正本 conventions.md、complete.md、github.md、labels.md、install.md、docs.md の重複と壊れた文を整理する

## 決定

文字数は、行全体が `もとになった課題は #<番号> である。` である行を除いた残りを、一行のときはその行、二行以上のときは改行でつないだ文字列として数える。`<番号>` は十進で、先頭の零は無い。

同じ主体と条件と結果の組は、文字数が多い方を残す。残す識別子は変えない。それ以外は削除する。

- conventions の REQ-103 は 40、REQ-113 は 50。REQ-113 を残し、REQ-103 を除く。課題ランナーが投稿するコメントは、マージリクエストの URL だけであり、題や説明は付けない。
- conventions の REQ-122 は 108、REQ-145 は 126。REQ-145 を残し、REQ-122 を除く。合計 2 回起動しても判定行が無いとき、要求と設計はレスポンスを人に見せて止まり、実装は理由 `レビューの判定がありません` で失敗して終わる。
- conventions の REQ-123 は 104、REQ-146 は 128。REQ-146 を残し、REQ-123 を除く。判定行が `判定: 不合格` のとき、要求と設計のレビュー手順は、判定行より前を下から見て、確認の印で分岐する。
- labels の REQ-78 は 106、REQ-82 は 109。REQ-82 を残し、REQ-78 を除く。`process` が失敗したときの理由の行と、かかった時間の行は、`logError` へ渡る。
- labels の REQ-80 は 42、REQ-91 は 58。REQ-91 を残し、REQ-80 を除く。使い方は `bun src/cli.ts restore <番号>` であり、`<番号>` は課題番号である。

結果が違う近い組は、両方の識別子を残し、正本への差分の文にする。意味は変えない。変えたあと、その組は `本文が近いです` と報告されない。

- conventions の REQ-106 と REQ-115。印の位置に加え、REQ-115 は課題ランナーのコメントに印を書かない。
- conventions の REQ-119 と REQ-120。合格として進むことと、不合格として進むこと。
- conventions の REQ-148 と REQ-149。要求レビュー役が読む範囲と、設計レビュー役が読む範囲。
- conventions の REQ-741 と REQ-745。まだ無いファイルを書いたときと、節が無いとき。
- complete の REQ-691 と REQ-698。ファイルを読まず作らず承認のあと起動することと、人が課題番号を指定して起動すること。
- complete の REQ-695 と REQ-706、REQ-696 と REQ-706。description の旨と、呼び出し元ファイルの条件が無いこと。
- github の REQ-47 と REQ-54。ヘッドを消す主体と、件名を渡す主体。
- github の REQ-53 と REQ-60。プルリクエストの題を課題の題のままにすることと、実装と不具合修正のコミットメッセージを変えないこと。
- install の REQ-19 と REQ-20。公開物に `skills/` が含まれることと、`agents/` が含まれること。
- install の REQ-21 と REQ-22。公開したパッケージの `install` が `skills/` をコピーすることと、`agents/` をコピーすること。
- docs の REQ-712 と REQ-718。別の字面で `bun test` が失敗することと、スキルとサブエージェントへ短名を書かないこと。
- docs の REQ-780 と REQ-815、REQ-780 と REQ-844、REQ-815 と REQ-844。`docs/policy.md` の構成の表が含むサブコマンドが、`request` と `spec-check` と `prepare-branch` で違う。
- docs の REQ-781 と REQ-845、REQ-781 と REQ-874、REQ-817 と REQ-845、REQ-817 と REQ-874、REQ-845 と REQ-874。`AGENTS.md` のコマンドの例が、`request` と `spec-check` と `prepare-branch` と `tasks` で違う。
- docs の REQ-782 と REQ-818。README の開発中の起動の例に無いコマンドが、`request` と `spec-check` で違う。
- docs の REQ-783 と REQ-819。README のスキル呼び出しの表に無い名前が、`request` と `spec-check` で違う。

壊れた文末だけを直す要求は、行末の `である` を外し、`。` で終える。意味は同じ。識別子は変えない。直したあとの文は、正本への差分の本文である。

人が確認した要求は、次のとおり正本への差分にする。

- docs の REQ-713 は、`src/cli.ts` の `main` にある `switch (sub)` の `case` の順で、サブコマンドを全部書く。`default` は含めない。順は `install`、`run`、`labels`、`candidates`、`show`、`branch`、`prepare-branch`、`confirm`、`close`、`reflect`、`validate`、`complete`、`restore`、`review-next`、`request`、`spec-check`、`tasks` である。
- github の REQ-40 は、`squashMerge` が `--delete-branch` と `--subject` を付ける、と書く。`--merge`、`--rebase`、`--admin`、`--auto` は付けない。行末の壊れた `である` は外す。
- github の REQ-49 は、REQ-57 と同じく `--delete-branch` と `--subject` を含む引数列にする。成否の見分けは設計 2 のままである。REQ-57 は、引数の並びと、ヘッドを消す指定が設計 18 のままである、という差分のままである。両方の識別子は残す。この組は `本文が近いです` と報告されない。
- complete の REQ-675、REQ-678、REQ-701、REQ-702 は除く。完了の経路は、REQ-685 から REQ-688 などの現行の記述に任せる。
- conventions の REQ-137、REQ-138、REQ-139、REQ-140 は除く。判定と確認の読み方は、REQ-128 から REQ-134 に任せる。

差分に無い要求の本文は、一文字も変えない。

## テスト

`bun test` で実行する。`gh` は起動しない。ホームディレクトリと、実行中の Cursor のスキルは触らない。新しい `test` は `src/127.test.ts` だけに足す。既存の `src/*.test.ts` に、新しい `test` は足さない。このテストは正本のファイルを読み、`bun src/cli.ts spec-check` を実行する。

- 決定が残す識別子の見出しがあり、由来の行が編集前と同じである。決定が除く識別子の見出しは無い。残した方は、決定に書いた文字数が多い方である。[1][2][15]
- 決定が文を離すと書いた組を、`spec-check` は `本文が近いです` と報告しない。差分で本文を変えた識別子を、`spec-check` は `壊れた文末です` と報告しない。変更した本文は差分の本文と一文字も違わない。差分に無い要求の本文は、編集前と一文字も違わない。壊れた文末だけを直した行は、行末の `である` を外して `。` で終えた文である。結果が違う組の識別子は残る。[3][4][5][6][8]

- `src/spec.ts` に、`n * 5 >= u * 3` と、接尾辞六つと、除外三つが、編集前と同じ字面で残る。[9]
- `src/cli.ts` の `switch` の `case`、`src/github.ts` の `squashMerge` が渡す引数、`src/complete.ts` の `completeIssue`、`src/labels.ts` の `workflowLabels`、`src/install.ts` のコピーは、編集前の該当箇所が残る。[10]

- `docs/canonical/runner.md`、`docs/canonical/sdd.md`、`docs/canonical/git.md`、`docs/canonical/implement.md` の最初の `## REQ-` 見出しは、編集前と同じである。[12]
- `docs/conventions.md` と `skills/sdd-cur/conventions.md` は、編集前と同じパスにあり、本文は編集前と同じである。[13]
