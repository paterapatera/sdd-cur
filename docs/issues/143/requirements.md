# 143 issueスキルで課題タイプに応じたフォーマットを選び質問しながら作成できるようにする

<!-- sdd-cur:form -->

対象は [Issue #143](https://github.com/paterapatera/sdd-cur/issues/143)。`sdd-cur-create-issue` が、課題の本文のフォーマットを数種類使い分ける。人は、作る課題のタイプを選ぶ。課題本文が例に挙げるタイプは、ユーザーストーリーと修正である。起動時の作業ツリーが git リポジトリでないときは、どのタイプの課題を作るかを人に聞くより前に止まる。作業ツリーが git リポジトリであるとき、どのタイプの課題を作るかを、Cursor の質問機能の選択肢で人に聞く。人がタイプを選んだあと、そのタイプの課題にあった質問に、一覧の順に一問ずつ答えながら課題を作る。

起動時に本文用の内容が無いとき、および渡した内容がスペースと改行だけであるときも、作業ツリーが git リポジトリであるときは、同じ順で課題を作る。課題本文が挙げる質問の例は「背景はなんですか？」である。四タイプそれぞれの質問と、答えから組み立てる本文の見出しは、「決定」に書く。

## 決定

使い分ける課題のタイプは、ユーザーストーリー、修正、機能改善、調査の四種類である。

どのタイプの課題を作るかを人に聞くときは、Cursor の質問機能の選択肢で聞く。選択肢は四つであり、この順である。選択肢の ID は `ユーザーストーリー`、`修正`、`機能改善`、`調査` である。人が読む文言は、同じ順で、各 ID と一文字も違わない。人が選んだタイプは、選ばれた選択肢の ID である。選べるタイプはこの四つの ID だけである。

タイプの選択で、自由記述の答えの空白除去は、採用しない。

起動時の作業ツリーが git リポジトリかを、どのタイプの課題を作るかを人に聞くより前に見る。git リポジトリでないときは、課題を作る前にそれを見て、どのタイプの課題を作るかを人に聞くより前に止まる。課題を作らない。git リポジトリでない旨を伝える。`gh issue create` は実行しない。この見方は、#72 の、課題を作る前に見る、である。起動時の作業ツリーが git リポジトリでなく、本文用の内容がスペースと改行以外の文字を含み、渡した内容から題を決められないときは、先に git リポジトリでない旨を伝え、次に題を決められない旨を伝える。この二つの伝達は、どのタイプの課題を作るかを人に聞くより前である。

起動時の作業ツリーが git リポジトリであり、人が本文用の内容をすでに渡している場合も、先にどのタイプの課題を作るかを人に聞く。人がユーザーストーリー、修正、機能改善、調査のうち一つを選び、そのタイプ向けの各質問に、一覧の順に一問ずつ、スペースと改行以外の文字を含む答えをしたあと、その答えから本文を組み立てる。渡した内容は、本文の素材・参考として使う。

起動時に渡した内容を、本文のまま使い、書き換えない手順は、採用しない。

人が内容を渡していることを、課題を作る前提としては採用しない。

起動時の作業ツリーが git リポジトリであり、本文用の内容が無いとき、および起動時の作業ツリーが git リポジトリであり、渡した内容がスペースと改行だけであるときも、先にどのタイプの課題を作るかを人に聞く。人がユーザーストーリー、修正、機能改善、調査のうち一つを選び、そのタイプ向けの各質問に、一覧の順に一問ずつ、スペースと改行以外の文字を含む答えをしたあと、その答えから本文を組み立てる。組み立てた本文から題を決められるときは、課題を作る。内容が欠けていることを理由には、課題を作らない、とはしない。内容が欠けていることを理由には、止まらない。内容が欠けていることを理由には、不足を伝えない。この点は、「現状」の正本が、内容を渡したときだけ課題を作る、と定める点と違う。「現状」のスキルが、内容が欠けているときは課題を作らない、と書く点とも違う。

本文用の内容が無いとき、およびスペースと改行だけのときは、題は、組み立てた本文をもとに、このスキルを実行するエージェントが決める。人は題を指定しない。題を人に尋ねない。組み立てた本文から題を決められないときは、課題を作らない。題を決められない旨を伝える。止まる。`gh issue create` は実行しない。

起動時に本文用の内容がスペースと改行以外の文字を含むときは、題は、渡した内容をもとに、このスキルを実行するエージェントが決める。人は題を指定しない。題を人に尋ねない。渡した内容から題を決められないときは、課題を作らない。題を決められない旨を伝える。止まる。`gh issue create` は実行しない。題を渡した内容をもとに決め、決められないときは課題を作らず、題を決められない旨を伝え、止まる点は、#72 と同じである。起動時の作業ツリーが git リポジトリでなく、本文用の内容がスペースと改行以外の文字を含み、渡した内容から題を決められないときは、先に git リポジトリでない旨を伝え、次に題を決められない旨を伝える。この二つの伝達は、どのタイプの課題を作るかを人に聞くより前である。

課題の本文は、選んだタイプの見出しだけを、この節に書いた順で持つ。見出しは、行頭が `## ` である行である。一つの節は、その見出しの次の行から、次の見出しの直前までである。最後の節は、その見出しの次の行から、本文の終わりまでである。質問の答えがスペースと改行以外の文字を含むとき、節の本文はその答えである。ユーザーストーリーの最初の節だけ、先の質問の答え、改行、後の質問の答え、の順である。
