# 97 同時に進む課題がコンフリクトしにくいよう、スキルとテストの書き方を変える

対象は [Issue #97](https://github.com/paterapatera/sdd-cur/issues/97)。同時に進む課題が同じ行を変えてコンフリクトしないよう、スキル、サブエージェント、テストの書き方を変える。

#96 は、最新のデフォルトブランチを作業ブランチへ取り込む。同じ行を変えた課題どうしは、そのあとでもコンフリクトする。この要件は、変更が同じ行に重ならない書き方にする。

重なる課題は #96、#91（レビューの分岐をコードに移す）、#83（ドキュメントとスキルのずれ）である。

## 現状

ほとんどの課題が、`skills/sdd-cur/SKILL.md` と `src/sdd.test.ts` の同じあたりを変える。

スキルは、一つの段落を一行に書く。同じ段落の別の文を変えただけでも、同じ行の変更になり、コンフリクトする。`skills/sdd-cur/SKILL.md` には、一つの行に複数の文が入る段落がある。

直近のマージリクエスト 31 件のうち、17 件が `skills/sdd-cur/SKILL.md` を、18 件が `src/sdd.test.ts` を変えている。

`src/sdd.test.ts` への最近の変更（#61、#63、#64、#65、#70、課題 69）は、同じ `describe("skills/sdd-cur/SKILL.md")` の中に足している。

`src/agents.test.ts` と `src/runner.test.ts` も、テストを一つのファイルに置いている。

一文を一行に書くことと、テストを同じ場所に足さないことは、まだ `docs/conventions.md` に書いていない。

## 受け入れ条件

- `skills/*/SKILL.md` の本文は、一文を一行に書く。
- `agents/*.md` の本文は、一文を一行に書く。
- Markdown として表示したときは、今と同じである。
- スキルとサブエージェントの文言は変えない。変えるのは、本文を一文一行にするための改行である。
- `src/sdd.test.ts`、`src/agents.test.ts`、`src/runner.test.ts` にあるテストは、別の課題が同じ場所に足さない置き方にする。
- その置き方は、設計で決める。課題ごと、節ごとのファイルなど、どれにするかは、この要件では決めない。
- テストが確かめる内容は変えない。
- テストがスキルまたはサブエージェントの本文を文字列で確かめるとき、期待する文字列の改行は、一文一行の書き方に合わせる。確かめる文言は変えない。
- 書き方の約束の本文は `docs/conventions.md` に書く。
- この書き方は、cc-sdd の steering や Spec Kit の constitution に相当する永続ルールとして、`docs/conventions.md` に集約する。
- この書き方のために `AGENTS.md` が変わる箇所は、着手前の一覧の参照と、構成表の参照だけである。
- 着手前の一覧の参照と、構成表の参照は、この書き方の詳細を `docs/conventions.md` で読む形である。
- この書き方の詳細本文は `AGENTS.md` に書かない。
- 作成役、修正役、実装役は、スキル、サブエージェント、テストを書くとき、`docs/conventions.md` に書いたこの書き方に従う。

## 決定

書き方の約束の本文は `docs/conventions.md` に書き、cc-sdd の steering や Spec Kit の constitution に相当する永続ルールとして `docs/conventions.md` に集約する。

`AGENTS.md` は着手前の一覧と構成表の参照だけを更新し、詳細は `docs/conventions.md` を読む形にする。詳細本文は `AGENTS.md` に書かない。

## 範囲外

次は、この要件に含めない。

- スキルの手順を短くすること（#91）
- 作業ブランチへの取り込み（#96）
