## 範囲外

次は、この設計に含めない。

- 印がある設計の必須の節を増やすこと、または必須の節から外すこと
- 印が無い設計を検査すること
- 曖昧な語の検査を変えること
- 受け入れ条件の項目の形の検査を変えること
- 要件ファイルに、この三つの節の検査を足すこと
- 三つの節が無いことだけで、設計レビューを不合格にすること
- 書く条件を満たさない節があることだけで、設計レビューを不合格にすること
- 節にだけある詳細を、食い違いとして指摘すること
- 課題の大きさで、三つの節を書くかを判定すること
- `validate` が、三つの節の本文の意味を検査すること
- この三つのほかの節を、この課題で足すこと
- Spec Kit の `/plan` のように、`data-model.md`、`contracts/`、`research.md`、`quickstart.md` を別ファイルとして作ること
- #4 の、課題ごとのファイルの置き場所、コメント種別、未反映の回答の判定を変えること
- `docs/conventions.md` の「スキル、サブエージェント、テストの書き方」を変えること
- `docs/canonical/sdd.md` を変えること
- `src/cli.ts` を変えること

## 決定

任意の節の名前は、データモデル、インターフェース、図の三つだけである。見出しは、行全体が `## データモデル`、`## インターフェース`、`## 図` のいずれかと一致する行である。必須の節の一覧は変えない。

本文の切り出しは、既存の `sectionBodies` を使う。節名は、見出しの `## ` の後ろの文字列である。同じ見出しが複数あるときは、`sectionBodies` が返す各本文を、それぞれ検査する。

本文が空かどうかは、切り出した文字列を、改行を `\n` にそろえたあと、前後の空白を除いた長さが 0 であるとき、空である。空白は、スペース、タブ、改行、復帰、全角スペースである。

データモデルとインターフェースの本文が空のときの違反は `節の本文が空です: <節名>` である。`<節名>` は、データモデル、インターフェースのいずれかである。空の本文ごとに、その違反を一つ返す。曖昧な語の検査と同様に、同じ文言でも本文が別なら違反は別である。

`## 図` の各本文について、Mermaid の囲みの個数を数える。数え方は、本文を行に分け、上から見る。行全体がバッククォート三つの直後に `mermaid` を続けたものと一致する行で開き、行全体がバッククォート三つと一致する行で閉じたブロックを一つと数える。開始行の行頭に空白がある行は、開きとして数えない。閉じ行の行頭に空白がある行は、閉じとして数えない。中身が空のブロックも一つと数える。ネストした囲みは、この課題では特別扱いしない。開きと閉じの対応は、上から順に、開いたブロックを閉じる。

節名が図のときは、一般の空違反を足さない。図分岐だけで、各本文について、本文が空なら `節の本文が空です: 図` と `図に Mermaid の囲みがありません` を一組ずつ足す。`節の本文が空です: 図` が二重にならない。本文が空でなく、囲みが一つも無いとき、違反 `図に Mermaid の囲みがありません` を一つ足す。囲みが二つ以上あるとき、個数を理由に違反を足さない。

判定のコードは `src/conventions.ts` の `validateSpecForm` に足す。`kind` が `design` であり、印があるときだけ、三つの任意の節について上の検査をする。`kind` が `requirements` のとき、印が無いとき、必須の節の検査、曖昧な語、受け入れ条件の形、テスト参照、作業の一覧、シナリオの検査は、今どおりである。`src/cli.ts` は変えない。

`validateSpecForm` は、印があり `kind` が `design` のときだけ、次の関数を呼ぶ。Mermaid の囲みの数え方、データモデルとインターフェースの基本の任意節の検査、図の任意節の検査は、それぞれ別の関数に分ける。重複見出しは、基本と図の検査が `sectionBodies` で得た各本文を出現順に見ることで扱う。基本の任意節の検査は、三つの節名のうちデータモデルとインターフェースだけを見る。見出しが無い節は飛ばす。見出しがある節は、各本文について、空なら `節の本文が空です: <節名>` を一つ足す。図の任意節の検査は、見出しが `## 図` のときだけ、各本文について上の図分岐を行う。違反の並びは、節名の順、同じ節の二つ目以降の本文、各本文では空の違反のあとに Mermaid の違反、の順で足す。

節「要件と設計の形式」へ足す文は、次の六行である。行のあいだに空行は入れない。この順で足す。

```
印がある設計には、任意の節 `## データモデル`、`## インターフェース`、`## 図` を書いてよい。節が無いときは `validate` は失敗しない。節があるときは、本文が空でないことを検査する。
`## 図` があるときは、各本文に Mermaid の囲みコードブロックを一つ以上持つことを検査する。
本文は、見出しの次の行から、行が `## ` で始まる次の行の直前までであり、空白と改行だけなら空である。出現する各節の本文をそれぞれ検査する。
本文が空のときの違反は `節の本文が空です: <節名>` であり、節名はデータモデル、インターフェース、図である。
Mermaid の囲みは、行全体がバッククォート三つの直後に `mermaid` を続けたものと一致する開始行で開き、行全体がバッククォート三つと一致する行で閉じたブロックを一つと数える。行頭の空白は無い。中身が空でも数える。
囲みが無いときの違反は `図に Mermaid の囲みがありません` である。
```
