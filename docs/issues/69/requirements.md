# 69 実装するものが無い課題は設計までに閉じ、実装の agent は履歴を書き換えない

対象は [Issue #69](https://github.com/paterapatera/sdd-cur/issues/69)。実装するものが無い課題が実装依頼まで進み、課題ランナーが起動した実装の agent が、作業ブランチの仕様コミットを取り消した。要件と設計の段階で、課題の期待がすでに main で満たされていると根拠つきで示せる課題は、人の承認を受けて閉じる。実装、修正、quick の agent は、ブランチの先頭を動かす git 操作をしない。

重なる課題は #23（この事象が起きた課題）と #27（実装ブランチの作り方）である。

## 現状

SDD スキルとそのサブエージェントは、課題を閉じない。課題の期待がすでに満たされているかを見る手順も無い。

課題 23 の設計は、`src/`、スキル、テストを変えないと定め、巻き戻りを止める変更は #37 の設計が定めるとしている。実装するものが無いまま、実装依頼まで進んだ。

実装作成役が変えるものが無いとき、そのままでは `実装作成が作業ツリーを変えませんでした` か `実装の変更がありません` で失敗する。agent はこれを避けるため、仕様コミットを取り消して差分を作った。

実装、修正、quick の禁止には、コミットと push がある。`reset`、`checkout`、`rebase` など、ブランチの先頭を動かす操作は、禁止に無い。

課題ランナーは、agent の終了後、作業ツリーの変更の有無だけを見る。`HEAD` が起動前と同じかは見ない。

## 受け入れ条件

- 要件の手順が合格し、設計に進めると人に伝える直前、および設計の手順が合格し、実装依頼に進めると人に伝える直前に、課題の期待がすでに main で満たされているかを判断する。課題番号、ファイル、行を根拠として、すでに main で満たされていると示せるときは、その案内の前に、SDD スキルが判断と根拠を人に示す。
- すでに main で満たされていると、課題番号、ファイル、行を根拠として示せるときは、Cursor の質問機能で、閉じるか閉じないかの二択を出す。閉じるを選んだときだけ、判断と根拠を課題のコメントに書き、課題を閉じる。
- そのコメントは、確認、回答、受け入れ手順の印を使わない。本文に判断と根拠を書いた通常のコメントである。
- `AGENTS.md`、SDD スキル、そのサブエージェントにある「課題を閉じない」という定めは、この課題で変える。変えるのは、人が閉じるを選んだときに SDD スキルが閉じる場合だけである。
- 課題ランナーは課題を閉じない。
- すでに main で満たされていると、課題番号、ファイル、行を根拠として示せないときは、二択は出さず、課題を閉じない。
- 閉じないを選んだときは、課題を閉じない。要件と設計の通常の手順を続ける。
- 実装、修正、quick の agent は、ブランチの先頭を動かす git 操作をしない。`reset`、`checkout`、`rebase` のように、先頭を動かす操作を含む。対象は `skills/sdd-cur-implement`、`skills/sdd-cur-fix`、`skills/sdd-cur-quick` と、実装のサブエージェントである。
- 課題ランナーは、起動した agent の起動前と終了後で `HEAD` が変わっていたら、作業コピーは戻さず、コミットも push もせず、失敗で止まる。

## 決定

判断は、要件の手順が合格し、設計に進めると人に伝える直前、および設計の手順が合格し、実装依頼に進めると人に伝える直前に行う。課題番号、ファイル、行を根拠として、すでに main で満たされていると示せるときは、その案内の前に判断と根拠を人に示す。

すでに main で満たされていると、課題番号、ファイル、行を根拠として示せるときは、Cursor の質問機能で、閉じるか閉じないかの二択を出す。閉じるを選んだときだけ、判断と根拠を課題のコメントに書き、課題を閉じる。

閉じないを選んだときは、課題を閉じない。要件と設計の通常の手順を続ける。

その回の要件または設計の手順を止め、ファイルを承認前のままにすることは採用しない。

閉じるときのコメントは、確認、回答、受け入れ手順の印を使わない。本文に判断と根拠を書いた通常のコメントである。

新しい印を先頭行に付けることは採用しない。

`AGENTS.md`、SDD スキル、そのサブエージェントにある「課題を閉じない」という定めは、この課題で変える。変えるのは、人が閉じるを選んだときに SDD スキルが閉じる場合だけである。

`HEAD` が起動前と違っていたときは、作業コピーは戻さない。コミットも push もせず、失敗で止まる。
