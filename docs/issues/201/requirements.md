# 201 設計に任意の節「検討した案」を書けるようにする

<!-- sdd-cur:form -->

対象は [Issue #201](https://github.com/paterapatera/sdd-cur/issues/201)。印がある設計に、任意の節 `## 検討した案` を書けるようにする。節が無くても `validate` は失敗しない。節があるときだけ、本文が空でないことを確かめる。本文は、見出しの次の行から、行が `## ` で始まる次の行の直前までであり、空白と改行だけなら空である。出現する各節の本文をそれぞれ検査する。本文が空であるときの違反は `節の本文が空です: 検討した案` である。項目は、「案」「選んだか退けたか」「理由」が分かる一行である。一行の具体的な記法は、この課題の設計が決める。`validate` はその記法を検査しない。設計作成役は、「決定」に二つ以上の案を比べた結論があるとき、この節に、各案と、選んだか退けたかと、理由を書く。「決定」に二つ以上の案を比べた結論が無いとき、この節を書かない。設計レビュー役は、「決定」と「検討した案」が、同じ事項について、選んだ案、退けた案、または理由が矛盾するとき指摘する。節にだけ詳細があることは、「決定」との食い違いにしない。「決定」に二つ以上の案を比べた結論があるのにこの節が無いことだけでは不合格にしない。指摘してもよい。書く条件を満たさないのにこの節があることだけでは不合格にしない。任意節の過剰は指摘してもよい。この節の規則は、`docs/canonical/conventions.md` へ要求として足さない。

必須の節と、既存の任意の節 `## データモデル`、`## インターフェース`、`## 図` の検査は変えない。印が無い設計を `validate` が検査しないことは変えない。

重なる課題は #170 である。比べる相手は、Spec Kit の `research.md` である。この課題が足すのは、設計ファイルの中の任意の節 `## 検討した案` である。

## 決定

印がある設計の `## 検討した案` の本文は、見出しの次の行から、行が `## ` で始まる次の行の直前までである。切り出しは、既存の `sectionBodies` と同じである。本文が空白と改行だけであるとき、その本文は空である。同じ見出しが二つ以上あるときは、出現する各節の本文をそれぞれ検査する。どれか一つの本文が空なら、検査は失敗する。

本文が空であるときの違反は `節の本文が空です: 検討した案` である。この節には、図の Mermaid の検査は足さない。本文が空かどうかの検査は、データモデル、インターフェースと同じである。

項目は、「案」「選んだか退けたか」「理由」が分かる一行である。一行の具体的な記法は、この要件では決めない。この課題の設計が決める。`validate` は、その記法を検査しない。

設計作成役は、「決定」に二つ以上の案を比べた結論があるとき、この節に、各案について選んだか退けたかと理由を書く。「決定」に二つ以上の案を比べた結論が無いとき、`## 検討した案` を書かない。

設計レビュー役は、「決定」と「検討した案」が、同じ事項について、選んだ案、退けた案、または理由が矛盾するとき指摘する。節にだけ詳細があることは、「決定」との食い違いにしない。

設計レビュー役は、「決定」に二つ以上の案を比べた結論があるのに `## 検討した案` が無いことだけでは不合格にしない。指摘してもよい。この扱いは、#170 の任意節が書いていないことだけでは不合格にしないことと同じである。

設計レビュー役は、書く条件を満たさないのに `## 検討した案` があることだけでは不合格にしない。任意節の過剰は指摘してもよい。

`skills/sdd-cur/conventions.md` の「要件と設計の形式」へ、この節の文を足す。必須の節と、データモデル、インターフェース、図の検査を書く既存の文は変えない。書く条件と、結論が無いときに書かないことは、`skills/sdd-cur/design.md` と `agents/sdd-cur-design-author.md` に書く。「決定」と「検討した案」が同じ事項について選んだ案、退けた案、または理由が矛盾するとき指摘すること、節にだけ詳細があることは「決定」との食い違いにしないこと、「決定」に二つ以上の案を比べた結論があるのに `## 検討した案` が無いことだけでは不合格にしないこと、指摘してもよいこと、書く条件を満たさないのに `## 検討した案` があることだけでは不合格にしないこと、任意節の過剰は指摘してもよいことは、`agents/sdd-cur-design-reviewer.md` に書く。

`docs/canonical/conventions.md` へ、この節の規則を要求として足すことは、採用しない。`docs/canonical/conventions.md` は変えない。

この課題が足すのは、設計ファイルの中の任意の節 `## 検討した案` である。Spec Kit の `research.md` のような別ファイルは作らない。

## 範囲外

次は、この要件に含めない。

- 印がある設計の必須の節を増やすこと、または必須の節から外すこと
- 印が無い設計を検査すること
- 節が無いことだけで、`validate` を失敗させること
- データモデル、インターフェース、図の検査を変えること
- 要件ファイルに、この節の検査を足すこと
- 項目の一行の記法を、`validate` が検査すること
- この節に、Mermaid の検査を足すこと
- 曖昧な語の検査を変えること
- 受け入れ条件の項目の形の検査を変えること
- Spec Kit の `research.md` のように、比べて退けた案の記録を別ファイルとして作ること
- #170 の、三つの任意の節の規則を変えること
- `docs/conventions.md` の「スキル、サブエージェント、テストの書き方」を変えること
- `docs/canonical/conventions.md` を変えること
- 「決定」に二つ以上の案を比べた結論があるのに `## 検討した案` が無いことだけで、設計レビューを不合格にすること
- 書く条件を満たさないのに `## 検討した案` があることだけで、設計レビューを不合格にすること
- 節にだけある詳細を、「決定」との食い違いとして指摘すること
