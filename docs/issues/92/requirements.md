# 92 実装レビューも、同じ指摘が 2 回続いたら止める

対象は [Issue #92](https://github.com/paterapatera/sdd-cur/issues/92)。要件と設計のレビューは、同じ指摘が 2 回続くと止まる。実装レビューにはこの止まりが無く、不合格を 10 回まで繰り返す。実装レビューにも、同じ指摘が 2 回続いたときの止まりを入れる。

手を入れる対象は `skills/sdd-cur-implement/SKILL.md` である。

重なる課題は #40（実装レビューでテストを実行する）である。

## 現状

`skills/sdd-cur/SKILL.md` の要件のレビュー手順と設計のレビュー手順は、確認行が `確認: なし` の不合格のとき、直前の不合格レビューと、今回のレビュー応答の「指摘」にある番号付き指摘の本文を比べる。本文が同じなら、2 回連続として止まる。その止まりでは、修正を起動しない。

`skills/sdd-cur-implement/SKILL.md` の実装レビューは、不合格を数える。増やした回数が 10 のとき、理由 `実装レビューが不合格のまま10回に達した` で失敗する。直前の不合格レビューの番号付き指摘の本文との比較は無い。

## 受け入れ条件

- 実装レビューで、今回のレビュー応答の「指摘」にある番号付き指摘の本文が、直前の不合格レビューと同じとき、`skills/sdd-cur-implement/SKILL.md` の agent は修正役を起動しない。
- そのとき、次のレビューを起動しない。
- そのとき、手順本文を書き直さない。
- そのとき、agent は失敗で終える。
- その失敗の終了コードは 0 以外である。
- その失敗の理由は、日本語の一行である。
- 同じ指摘とは、二つの不合格レビューの、レビュー応答の「指摘」にある番号付き指摘の本文が同じことである。
- 観点ごとの短い評価、差分、確認行、判定行は、この比べ方に含めない。
- 2 回連続とは、同じ一回の agent 起動の中で、直前の不合格レビューと今回の不合格レビューが同じ指摘であることである。
- 今回の不合格レビューが、その 2 回目である。
- 直前の不合格レビューが無いときは、2 回連続ではない。
- 今回の番号付き指摘の本文が直前と違うときは、2 回連続ではない。
- この agent 起動の開始時、直前の不合格レビューは無い。
- 判定行が `判定: 不合格` のレビューの、番号付き指摘の本文を、次の比較の直前として、この agent 起動の中だけで覚える。
- 印が壊れているレスポンスは、直前にしない。
- 判定行が `判定: 合格` のレビューは、直前にしない。
- 直前は、ファイルに書かない。
- 直前は、課題コメントに書かない。
- 要求のレビュー手順の直前は、実装レビューの比較に使わない。
- 設計のレビュー手順の直前は、実装レビューの比較に使わない。
- 直前より前の不合格レビューとは比べない。
- ランナーが `implement` を再試行した別の agent 起動へ、直前は引き継がない。
- この止まりの条件は、番号付き指摘の本文が直前の不合格レビューと同じことである。
- 確認行は、この止まりの条件に含めない。
- 2 回連続ではなく、増やした不合格回数が 9 以下であり、レスポンスに「実装の指摘なし」が無いとき、差分だけを修正役へ渡す。
- そのとき、修正のあと、レビューに戻る。
- 2 回連続ではなく、増やした不合格回数が 9 以下であり、レスポンスに「実装の指摘なし」があり、手順未網羅があるとき、修正役は起動しない。
- そのとき、親が手順本文を書き直したあと、レビューに戻る。
- 2 回連続ではなく、テスト節の実行省略だけがあるとき、不合格回数は増やさない。
- そのとき、同じレビューをもう一度起動する。
- 増やした不合格回数が 10 のときは、agent は失敗で終える。
- そのとき、修正役を起動しない。
- そのとき、次のレビューを起動しない。
- そのとき、手順本文を書き直さない。
- 増やした不合格回数が 10 のときの理由は、`実装レビューが不合格のまま10回に達した` である。
- 不合格を数える上限は、10 回のままである。

## 決定

実装レビューの番号付き指摘の本文が、直前の不合格レビューと同じときは、修正役を起動せず、失敗で終える。理由は日本語の一行である。

比べるのは、要件と設計のレビューと同じく、レビュー応答の「指摘」にある番号付き指摘の本文である。観点ごとの短い評価、差分、確認行、判定行は比べない。

10 回の上限は残す。

## 同じ指摘

同じ指摘とは、二つの不合格レビューについて、レビュー応答の「指摘」にある番号付き指摘の本文が同じことである。比べるのは、その番号付き指摘の本文である。観点ごとの短い評価、差分、確認行、判定行は除く。

2 回連続とは、同じ一回の agent 起動の中で、直前の不合格レビューと今回の不合格レビューの番号付き指摘の本文が同じことである。今回の不合格レビューが、その 2 回目である。手順の最初の不合格レビューには、直前が無い。直前が無いとき、および本文が直前と違うときは、2 回連続ではない。

直前は、その agent 起動の中で、今回より前の最後の、判定行が `判定: 不合格` のレビュー一つである。それより前とは比べない。印が壊れているだけのレスポンスは含まない。合格は含まない。開始時は直前が無い。親が、この agent 起動の中だけ覚える。ファイルにも課題コメントにも書かない。要求のレビュー手順と設計のレビュー手順の直前は使わない。ランナーが `implement` を再試行した別の agent 起動は、別の実行であり、開始時の直前は無い。

本文が直前と同じときは、修正役を起動しない。次のレビューを起動しない。手順本文を書き直さない。agent は失敗で終える。終了コードは 0 以外である。理由は日本語の一行である。

この止まりの条件は、番号付き指摘の本文が直前と同じことである。確認行は、この止まりの条件に含めない。

## 関係する課題

課題は、次を関係するとする。

- #40（実装レビューでテストを実行する）
- #45（要求と設計のレビューが収束しないときは人に戻す）

#40 は、実装レビューの不合格を 10 回まで繰り返す。本文が直前と違うとき、および直前が無いときは、その繰り返しを残す。本文が直前と同じときは、この要件が、修正役を起動せず失敗で終える。

#45 は、要求と設計のレビューで、番号付き指摘の本文を比べる。実装レビューが比べる対象は、それと同じである。実装レビューの止まりは、agent が失敗で終えることである。

## 範囲外

次は、この要件に含めない。

- 上限の回数を変えること
- テストの実行をレビュー役の外に出すこと（#93）
