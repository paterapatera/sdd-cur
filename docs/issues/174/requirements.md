# 174 途中で止まった実装を、終わった作業の次から再開する

<!-- sdd-cur:form -->

対象は [Issue #174](https://github.com/paterapatera/sdd-cur/issues/174)。課題ランナーは、実装を始めるときに「実装依頼」を外して「実装中」を付ける。`selectImplementationIssue` は「実装中」が付いた課題を選ばない。agent の再試行も失敗したとき、またはランナーのプロセスが途中で落ちたとき、課題は「実装中」のまま残る。人がラベルを手で戻すまで、どのクローンもその課題を拾わない。

`sdd-cur run` の起動時に一度だけ、次をすべて満たす課題を探す。開いていて、「実装中」がある。着手は、実装の着手である。`isQuickTarget(issue)` が真（ラベル「quick 対象」がある）課題は、再開の対象にしない。最新の `sdd-cur: 着手` コメントのクローン識別子が、このクローンのものである。このクローンの識別子は、作業ディレクトリに永続化した文字列であり、再起動後も同じ文字列を使う。作業ブランチ `task-<番号>` のマージリクエストがまだ無い。ローカルに `task-<番号>` がある。当てはまる課題が一つあるときは、ラベルを変えずに、そのローカルの作業ブランチから実装をやり直す。当てはまる課題が二つ以上あるときは、課題番号の昇順で、番号が最小の一つだけをやり直す。残りは、この起動では再開しない。やり直した一つが成功したあとは、今の `poll` と `process` の繰り返しに入る。終わった作業は #173 の `done` により飛ばす。一つのクローンでは処理が一つずつ進むので、起動時に「実装中」で残っているこのクローンの課題は、落ちた処理の残りである。上のうちローカルに `task-<番号>` が無い課題は、再開しない。失敗にもしない。再開の対象が無いときは、失敗にせず、今の `poll` と `process` の繰り返しに入る。再開が失敗したときは、「実装中」のまま止める。標準エラーへ書くのは、課題番号と理由の一行だけである。かかった時間と起動回数の括弧だけの一行は書かない。課題コメントは出さない。同じ課題を、そのプロセスの中で二度は再開しない。

作業のコミットを途中で push して、別のクローンでも再開できるようにするかは、この要件では決めない。設計が決める。

重なる課題は #173（作業ごとのコミット。この課題の前提）と #6（課題ランナー）である。比べる相手は無い。

手を入れる対象は、`src/run.ts`、`src/runner.ts`、`docs/canonical/runner.md` である。

## 決定

作業のコミットを途中で push し、別のクローンが同じ課題を再開できるようにするかは、この要件では決めない。設計が決める。

識別子は、作業ディレクトリに永続化する。作業ディレクトリに識別子がまだ無いときは、`randomUUID` で一つ作り、その文字列を作業ディレクトリへ永続化する。あるときは、新しく作らず、その文字列を使う。再起動後も、同じ文字列を使う。正本が定める、識別子をファイルから読まない、は、この課題で変える。識別子を環境変数から読むことは、この課題では変えない。

再開の条件をすべて満たす課題が二つ以上あるときは、課題番号の昇順で、番号が最小の一つだけを再開する。残りは、この起動では再開しない。最小の一つの再開が成功したあとは、今の `poll` と `process` の繰り返しに入る。残りを、その繰り返しより前に再開しない。

開いていて、「実装中」があり、最新の着手コメントのクローン識別子がこのクローンの識別子と一致し、着手が実装の着手であり、作業ブランチ `task-<番号>` を head とするマージリクエストが一件も無いが、ローカルに `task-<番号>` が無いときは、その課題を再開しない。失敗にもしない。ラベルを変えない。受け入れ条件 8 の課題が無いときは、今の `poll` と `process` の繰り返しに入る。

再開の対象は、実装の着手だけである。`isQuickTarget(issue)` が真（ラベル「quick 対象」がある）課題は、再開候補に含めない。quick を再開対象にすることは、採用しない。

再開が失敗したとき、標準エラーへ書くのは、課題番号と理由の一行だけである。課題番号は十進であり、先頭の零は付けない。かかった時間と起動回数の括弧だけの一行は、採用しない。課題コメントを出すことは、採用しない。

## 範囲外

- 他のクローンが着手した課題を再開すること
- 課題を作ること
- 課題を閉じること
- `issue edit` の `--add-label` と `--remove-label` 以外でラベルを変えること

- 実装スキルの本文を変えること
- #173 の `done` の判定を変えること
- `poll` が探す種類の順を変えること
- 同じプロセスの中の、agent の再試行の回数を変えること
- quick を再開すること
- 実装の着手以外を再開すること
- 起動時に、再開の対象を二つ以上再開すること
- ローカルに `task-<番号>` が無い課題を再開すること
- ローカルに `task-<番号>` が無い課題を、失敗にすること

- 識別子を環境変数から読むこと
