# 93 設計のテスト節の実行を、実装レビュー役の外に出す

対象は [Issue #93](https://github.com/paterapatera/sdd-cur/issues/93)。設計の「テスト」節のコマンドは、今は実装レビュー役が実行する。これをレビュー役の外で決まった手順で実行し、終了コードと出力をレビュー役に渡す。レビュー役は結果を読んで判定する。

レビュー役は LLM なので、実行を省いたり、節を飛ばしたりする。そのため、スキルには、実行の省略を見つけてレビューをやり直す手順がある。読み取り専用のレビュー役が、テストのために一時ファイルを触ることを例外として許す規則もある。

この要件の「テスト」節は、見出しが `テスト` の節である。

手を入れる対象は、`skills/sdd-cur-implement/SKILL.md` と `agents/sdd-cur-implement-reviewer.md` である。実行する主体が課題ランナーになるときは、課題ランナーも対象である。

重なる課題は #40（実装レビューでテストを実行する）と #92 である。

## 現状

`skills/sdd-cur-implement/SKILL.md` は、設計の「テスト」節の実行を実装レビュー役が行い、親は実行しない、と定める。

同スキルは、実装レビュー役の `readonly: true` を維持する。テストの実行が触るのは、一時ディレクトリと、既存のテスト用一時ファイルだけである。実装の意図的な編集はしない。

同スキルは、実装レビュー役がテスト節の実行を省いたとき、回数を増やさずにレビューをやり直す。

実行すべき記述は、バッククォートまたはコードフェンスの中のコマンド行と、明示的な手順の箇条書きである。それ以外の文は実行しない。実行すべき記述が無い節は実行しない。節が無いときは実行しない。

見出しが `テスト` の節が複数あるときは、実行すべき記述がある節を、書かれた順にすべて実行する。一つの節の失敗で、残りの節を飛ばさない。

失敗は、起動したコマンドの終了コードが 0 以外である。終了コードが 0 のコマンドは、失敗ではない。終了コードが 0 以外のコマンドが一つでもあるとき、その実行は失敗であり、実装の指摘である。

`agents/sdd-cur-implement-reviewer.md` も、設計の「テスト」節を作業ツリーで実行する、と定める。

## 受け入れ条件

- 実行すべき記述がある「テスト」節があるとき、その節の実行は、実装レビュー役の起動より前である。
- 実行すべき記述がある「テスト」節があるとき、その節の実行は、実装レビュー役を起動するたびにある。
- 実行すべき記述がある「テスト」節は、書かれた順に実行する。
- 実行すべき記述がある「テスト」節は、すべて実行する。
- 一つの節の実行で、終了コードが 0 以外のコマンドがあっても、残りの節を実行する。
- 実行すべき記述は、バッククォートまたはコードフェンスの中のコマンド行と、明示的な手順の箇条書きである。
- 実行すべき記述以外の文は、実行しない。
- 実行すべき記述が無い「テスト」節は、実行しない。
- 「テスト」節が無いときは、実行しない。
- 設計の「テスト」節を実行する主体は、実装の agent の親か、課題ランナーかである。
- 主体が実装の agent の親と課題ランナーのどちらであるかは、設計で決める。この要件では決めない。
- 各コマンドの終了コードを、実装レビュー役に渡す。
- 各コマンドの出力を、実装レビュー役に渡す。
- 実装レビュー役は、判定のとき、渡された終了コードと出力を読む。
- 終了コードが 0 以外のコマンドがあるとき、その結果は、今と同じく、実装の指摘である。
- 実装レビュー役は、設計の「テスト」節を実行しない。
- 実行の省略によるやり直しの手順は、無い。
- レビュー役向けの、一時ディレクトリと既存のテスト用一時ファイルを触ってよいとする例外規定は、無い。
- 実装レビュー役の `readonly: true` は維持する。
- 実装レビュー役の `readonly` の説明は、一時ディレクトリと既存のテスト用一時ファイルの例外規定を含まない。

## 決定

テストの実行を実装レビュー役の外に出すため、レビュー役向けの、一時ディレクトリと既存のテスト用一時ファイルを触ってよいとする例外規定は、削除する。

実装レビュー役の `readonly: true` は維持する。その説明は、一時ディレクトリと既存のテスト用一時ファイルの例外規定を含まない形に整理する。

## 関係する課題

課題は、次を関係するとする。

- #40（実装レビューでテストを実行する）
- #92

#40 は、設計の「テスト」節の実行の主体を実装レビュー役としている。この要件は、その主体を、実装の agent の親か課題ランナーかに変える。どちらにするかは、設計で決める。実行すべき記述の決め方は、#40 のままである。実行の省略によるやり直しは、この要件で無くなる。

#92 は、実装レビューの止まり方である。この要件は、その止まり方を変えない。

## 範囲外

次は、この要件に含めない。

- 何を実行すべき記述とするかを変えること
- 実装レビューの止まり方（#92）
