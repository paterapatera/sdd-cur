# 23 変えた仕様が巻き戻らないようにする

対象は [Issue #23](https://github.com/paterapatera/sdd-cur/issues/23)。すでに変えた仕様は、巻き戻さない。

分割元は #16 である。#16 の該当項目も、SDD を長く使うと、古い spec と整合が取れなくなり、すでに変えた仕様が巻き戻ることがあるので、巻き戻さないことである。

重なる課題は #37 である。

## 目的

すでに変えた仕様は、巻き戻さない。

SDD を長く使うと、古い spec と整合が取れなくなり、すでに変えた仕様が巻き戻ることがある。この要件の目的は、その巻き戻りを防ぐことである。

## 現状

SDD を長く使うと、古い spec と整合が取れなくなる。すでに変えた仕様が、あとから巻き戻ることがある。

巻き戻りを防ぐ手順の受け入れは、要求レビューと設計レビューについての #37 の受け入れ条件にある。

## 受け入れ条件

- すでに変えた仕様は、巻き戻さない。
- 巻き戻りは、同じ手順を定める既存の要件・設計と突き合わせ、すでに書いてある決定を消す差分である。
- 巻き戻りの定義は、#37 にそろえる。
- 巻き戻りを防ぐ手順は、要求レビューと設計レビューである。
- その手順が不合格にする条件は、#37 の受け入れ条件である。
- この要件が書くのは、目的、現状、および #37 との関係である。

## 決定

巻き戻りは、同じ手順を定める既存の要件・設計と突き合わせ、すでに書いてある決定を消す差分である。定義は #37 にそろえる。

巻き戻りを防ぐ手順は、要求レビューと設計レビューである。その手順が不合格にする条件は、#37 の受け入れ条件である。

この要件が書くのは、目的、現状、および #37 との関係である。

## 巻き戻り

巻き戻りは、同じ手順を定める既存の要件・設計と突き合わせ、すでに書いてある決定を消す差分である。定義は #37 にそろえる。

突き合わせる相手は、同じ手順を定める既存の要件と、同じ手順を定める既存の設計である。

差分は、その相手にすでに書いてある決定を消すものである。

すでに変えた仕様は、この巻き戻りをしない。防ぐ手順は、要求レビューと設計レビューである。その手順が不合格にする条件は、#37 の受け入れ条件である。

## #37 との関係

重なる課題は #37 である。

#37 は、要求レビューと設計レビューで、先行する仕様との矛盾と巻き戻りを止める。巻き戻りを防ぐ手順は、その要求レビューと設計レビューである。

巻き戻りの定義は、#37 にそろえる。巻き戻りは、同じ手順を定める既存の要件・設計と突き合わせ、すでに書いてある決定を消す差分である。

その手順が不合格にする条件は、#37 の受け入れ条件である。#37 は、別課題の受け入れとして参照する。

#23 が書くのは、目的、現状、およびこの関係である。

## 範囲外

次は、この要件に含めない。

- 要求を作ったあとの要求のレビューとレビュー指摘（#20）
- 設計を作ったあとの設計のレビューとレビュー指摘（#21）
- 実装のあとの実装のレビューとレビュー指摘（#22）
- 要求を作るとき、課題に書いていない部分を決めずに人へ質問し、選択肢に評価スコアを添えること（#26）
- マージ時のブランチ削除（#18）
- 使いたくないプロジェクトでスキルを止めること（#19）
- ランナーのアサイン対象（#24）
- `sdd-cur.completion` の廃止（#25）
- 課題のために作るブランチ名（#17）
- 要求と設計をデフォルトブランチへ入れず、作業ブランチに載せたまま実装すること（#27）
- 課題の作成とクローズ
- ラベルの変更
- 実装
- 受け入れ手順
