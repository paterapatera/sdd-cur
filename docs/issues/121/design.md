- 既存の `src/*.test.ts` に新しい `test` を足すこと
- 依存パッケージ。トークンと環境変数の読み取り。`gh` の起動

## 決定

| 項目 | 内容 |
|---|---|
| サブコマンド名 | `tasks` |
| 呼び出し | `bun src/cli.ts tasks <番号>`。スキルが呼ぶときは `sdd-cur tasks <番号>` |
| 置き場所 | `src/cli.ts` が `src/conventions.ts` の関数を呼ぶ。作業の一覧の範囲と作業の行の判定と `refs` の抽出の写しは、`src/cli.ts` に置かない |
| 引数 | 課題番号が一つ。`--help` と `-h` を除いた残りを数える。残りが一つでないときは、`cmdValidate` と同じく `printUsage` を書き、終了コード 1、標準出力は空 |
| 使い方の例外 | 引数に `--help` または `-h` があり、最初の引数が `spec-check` でないときは、今の `main` が使い方を出して終了コード 0 で戻る。`tasks` を、`spec-check` と同じ例外にしない |
| 番号 | `parseIssueNumberString` が拒否するときは、標準エラーへ `番号が不正です` の一行、終了コード 1、標準出力は空。使い方は書かない |
| パス | 作業ディレクトリの `docs/issues/<番号>/design.md`。`specPaths` の `design` |
| 読めない | `readSpecFile` が `仕様を読めません` で拒否するとき、その一行、終了コード 1、標準出力は空 |
| 無いファイル | `readSpecFile` が存在しないとして空の本文を返すときは、見出しが無いときと同じである |
| 作業の一覧 | `firstSectionBody(markdown, "作業の一覧")`。null のときは `設計に作業の一覧がありません`。作業の行が一つも無いときは `作業の一覧に作業がありません`。どちらも終了コード 1、標準出力は空、標準エラーはその一行 |
| 作業の行 | `isWorkListItemLine` が真の行だけ。印が無くても取る。複数の見出しは最初だけ |
| 成功 | 終了コード 0。標準エラーは空。標準出力は下の JSON の一行と、末尾の改行一つ |
| `testCommands` | コマンド行だけ。明示的な手順の箇条書きは入れない。要件の受け入れ条件 34 の条件は、この設計では成り立たない |
| テストの起動順 | 親は、実行すべき記述がある「テスト」節を、書かれた順にすべて実行する。コマンド行は `testCommands` の要素を配列の順に起動する。明示的な手順の箇条書きは `testCommands` に入れず、実行すべき記述として、その節の書かれた順で扱う |
| `gh` | 起動しない。`git` も起動しない。要件ファイルは読まない |

`main` の `switch` では、`spec-check` の次に `case "tasks"` を足す。`default` より前である。`printUsage` は、今の最後の行 `sdd-cur spec-check` の次に、`sdd-cur tasks <番号>` を足す。今ある行の字面は変えない。

`docs/policy.md` の構成の表の `src/cli.ts` の行は、サブコマンドの列挙の末尾に `` `tasks` `` を足す。今あるバッククォートの名前は残す。そのセルに、サブコマンド名以外のバッククォートは足さない。

`AGENTS.md` の「コマンド」の最初のコードフェンスでは、`bun src/cli.ts spec-check` の次、`bun test` の前に、`bun src/cli.ts tasks <番号>` の行を足す。他の行の字面は変えない。

成功の JSON は、`tasks`、`testCommands` の順のキーだけを持つオブジェクトを、`JSON.stringify` したものである。キーとキーのあいだに、手で空白は足さない。`tasks` の各要素は、`number`、`line`、`refs` の順のキーだけを持つ。`number` は、`- ` の直後から最初の `. ` の前までの数字列の `Number` である。`line` は、その行の文字列であり、改行は含めない。`refs` は、その行を `extractTestRefs` に渡した戻り値である。受け入れ条件の節とは突き合わせない。`extractTestRefs` は、`Number` が安全な整数であり、`String(n)` が括弧内の数字列と一致するものだけを返す。この条件は変えない。

`sectionBodies` を `src/conventions.ts` に足して export する。引数は markdown と節の名前である。行全体が `## ` の直後にその名前があり、それ以外の文字が無い見出しを、上からすべて見つける。各見出しの次の行から、行頭が `## ` である行の直前までを本文とする。そのような行が無いときは、ファイルの末尾までである。本文は、その行を `\n` で結んだ文字列であり、末尾に `\n` は足さない。見出しが無いときは空の配列である。`## ` はハッシュ二つと、その直後の空白である。行頭が `### ` である行は、本文を終えない。改行は、今の `firstSectionBody` と同じそろえである。`firstSectionBody` は、この配列の最初の要素を返し、要素が無いときは null を返す。`isWorkListItemLine` と `extractTestRefs` も export する。三つの関数の条件は変えない。

`tasks` は、設計の本文を読んだあと、作業の一覧を `firstSectionBody` で取る。`testCommands` は、`sectionBodies(markdown, "テスト")` の各本文から、下のコマンド行を、節の順、節の中では上から順に集める。失敗で戻るときは、`testCommands` を標準出力へ書かない。

### コマンド行

コマンド行は、見出しが行全体 `## テスト` である節の本文だけから取る。印の有無では変えない。節が無いときは、`testCommands` は空の配列である。

コードフェンスの開閉は、先頭の空白を除いてバッククォート三つで始まる行である。三つより多くても開閉である。節の本文の先頭では、フェンスは閉じている。開いたあと、次の開閉の行より前がフェンスの中である。開閉の前に節が終わるときは、残りはフェンスの中である。開閉の行は、コマンド行にしない。フェンスの中の、空白以外の文字がある行は、その行の文字列をコマンド行とする。空白だけの行と空行は、入れない。行末の改行は含めない。行の途中と端の空白は残す。フェンスの中では、インラインのバッククォートを別に取らない。

フェンスの外では、バッククォートが一つだけ連続する開きと、その後の、バッククォートが一つだけ連続する閉じで区間を作る。二つ以上連続するバッククォートは、開きにも閉じにもしない。区間の中の文字列にスペースまたはタブが一つ以上あるとき、その文字列をコマンド行とする。中が空である区間、空白だけではないがスペースもタブも無い区間は、入れない。同じ行に複数あれば左から順である。行頭が `- ` である行は、インラインの区間を取らない。行頭より前に空白がある行は、この除外に当たらない。継続行は、行頭が `- ` でないので、除外しない。

この抽出は、行が明示的な手順の箇条書きであるかを判定しない。行頭が `- ` である行を、コマンド行のインラインから除くだけである。親は、その箇条書きを、今の実装スキルのとおり実行すべき記述として扱う。
