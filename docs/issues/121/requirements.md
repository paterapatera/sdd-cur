- 80. 条件: 行頭が `<番号>. ` であり、`- ` で始まらない行を見る 主体: `tasks` 結果: 作業の行に含めない

## 決定

作業の一覧の本文の範囲は、`firstSectionBody` が「作業の一覧」から取る範囲と同じである。この範囲は、`validate` が作業の一覧を見る範囲と一致する。`tasks` は、その範囲を `src/conventions.ts` の `firstSectionBody` で取る。`src/cli.ts` は、その範囲の取り方の写しを持たない。

作業の一覧の見出しのあとに、行頭が `## ` である行が無いときは、本文はファイルの末尾までである。行頭が `### ` である行は、行頭が `## ` ではない。`## ` はハッシュ二つと、その直後の空白である。その行では本文を終えない。`validate` と同じである。

引数の件数が一つでないときは、`cmdValidate` と同じである。標準エラーは `printUsage` の表示と一文字も違わない。終了コードは 1 である。標準出力には書かない。

課題番号が不正なときは、`cmdValidate` と同じである。不正かどうかは、`parseIssueNumberString` が拒否するかどうかである。標準エラーへ書く一行は `番号が不正です` と一文字も違わない。終了コードは 1 である。標準出力には書かない。

設計ファイルのパスが無く、`readSpecFile` が存在しないとして空の本文を返すときは、見出しが無いときと同じである。終了コードは 1 である。標準エラーへ書く一行は `設計に作業の一覧がありません` と一文字も違わない。標準出力には書かない。

設計ファイルを読めないときは、`validate` と同じである。読めないとは、`readSpecFile` が `仕様を読めません` で拒否することである。標準エラーへ書く一行は `仕様を読めません` と一文字も違わない。終了コードは 1 である。標準出力には書かない。

実装スキルが `sdd-cur tasks <番号>` を実行し、終了コードが 1 で標準エラーが `仕様を読めません` であるときは、`設計に作業の一覧がありません` および `作業の一覧に作業がありません` と同じである。実装作成役を起動しない。その一行を失敗の理由にする。agent の終了コードは 0 以外である。

`tasks` が作業の行に含めるのは、`isWorkListItemLine` が真の行だけである。作業の行の判定は、`validate` と同じ関数を使う。行頭が `<番号>. ` であり、`- ` で始まらない行は、作業の行に含めない。

## 関係する課題

課題は、次を関係するとする。

- #88（設計に作業の一覧を持たせ、実装を作業ごとに進める）
- #91（レビューの判定と回数の数え方をコードに移す）
- #93（設計のテスト節の実行を、実装レビュー役の外に出す）

#88 は、実装の agent が作業の一覧の順に実装作成役を起動する、と定める。この要件は、その一覧の取り出しを `tasks` に移し、起動の順を、返った `tasks` の並びにする。作成役を同時に起動しないこと、作業ツリーを変えなかったときの止まりは、#88 のままである。

#91 は、実装レビューの分岐を `review-next` に置く。この要件は、その分岐を変えない。

#93 は、テスト節を実行する主体を、実装の agent の親とする。この要件は、実行する主体と場所を変えない。親が起動するコマンドの記述は、`testCommands` から取る。`testCommands` に明示的な手順の箇条書きを入れるかは、設計で決める。

## 範囲外

次は、この要件に含めない。

- 作業の起動順とレビューの分岐（#91）
- テスト節を実行する場所（#93 で決めたまま）
- 正本 `docs/canonical/` の本文をこの要件へ書くこと（設計の「正本への差分」で行う）
