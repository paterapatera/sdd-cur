# 47 作成役は仕様の全文を返信せずパスを返す。。

対象は [Issue #47](https://github.com/paterapatera/sdd-cur/issues/47)。要求作成役と設計作成役が、書いた仕様ファイルの全文を親への返信に載せる。仕様が長いとき、同じ全文がレビューと修正のたびに会話に残り、手順の読む範囲を超える。作成役はパスと変えた節だけを返し、親は作業ツリー上のファイルを読む。

重なる課題は無い。

## 現状

| 役 | ファイル | 親への返信（現状） |
|---|---|---|
| 要求作成 | `agents/sdd-cur-req-author.md` | 書いたファイルの全文、質問する未記載、質問しない未記載 |
| 設計作成 | `agents/sdd-cur-design-author.md` | 書いたファイルの全文、ファイルへ書かなかった決められない点 |

`skills/sdd-cur/SKILL.md` の要件と設計の手順は、作成役がディスクへ書いたあと、返信の全文を仕様の内容の根拠として使う想定になっている。レビューと修正指示は、設計 30 のとおり差分だけであり、全文は書かない。

`skills/sdd-cur/SKILL.md` 自体は短い。伸びるのは、作成役の返信に載る仕様の全文である。

## 節

この要件での節は、仕様ファイルの `#` 見出しの直下にある、各 `##` 見出しと、その見出しから次の `##` 見出しの直前までの本文の塊である。`#` 見出しの一行だけを変えたときは、その一行を変えた節として扱う。

## 受け入れ条件

- `agents/sdd-cur-req-author.md` の `## 親への返信` は、書いたファイルの全文を求めない。
- `agents/sdd-cur-design-author.md` の `## 親への返信` は、書いたファイルの全文を求めない。
- 要求作成役と設計作成役の返信には、当該起動で書いた仕様ファイルの、リポジトリルートからの相対パスを含める。
- 要求作成役と設計作成役の返信には、当該起動で新規に書いた、または本文を変えた節だけを含める。変えていない節の本文は含めない。
- 要求作成役は、従来どおり、質問する未記載と、依存または保留のため質問しない未記載を返す。
- 設計作成役は、従来どおり、ファイルへ書かなかった決められない点を返す。
- `skills/sdd-cur/SKILL.md` の要件と設計の手順は、作成役の返信から仕様の全文を読まない。仕様の内容を確認するときは、作業ツリー上のパスからファイルを読む。
- 要求のレビュー役、設計のレビュー役、要求の修正役、設計の修正役の、差分だけを返す扱いは変えない。
- 実装作成役の親への返信は、この要件の対象に含めない。

## 決定

作成役の返信は、仕様ファイルの相対パスと、当該起動で変えた節の本文だけである。全文は返さない。

親は、作成役の返信に載った全文を、仕様の正本として使わない。正本は作業ツリー上のファイルである。確認のために読む。

節は、仕様ファイルの `#` 直下の各 `##` 見出しの塊である。`#` 見出しの一行だけを変えたときは、その一行を変えた節として扱う。

要求作成役が返す質問する未記載と質問しない未記載、設計作成役が返す決められない点の扱いは、従来どおりである。

## 範囲外

次は、この要件に含めない。

- スキル本文を複数ファイルへ分割すること。設計 5 は手順を `SKILL.md` に置くと定めている。
- 実装作成役の返信
- レビューと修正指示の差分の形式の変更
- `reflect` が標準入力から受け取る全文（約束どおり、反映用の入力である）
- 課題の作成とクローズ
- ラベルの変更
- 受け入れ手順
- 完了処理
