# 171 「課題全体が大きすぎる」で止まるとき、分割案を返す

対象は [Issue #171](https://github.com/paterapatera/sdd-cur/issues/171)。設計レビュー役が、作業をどう分けても一回の実装作成役で書き終えられないとき、行 `課題全体が大きすぎる` のあとに、書き終えられない受け入れ条件を列挙する。その番号を一つだけ子に入れても目安を満たせるときは、レビューしている設計の受け入れ条件の番号が二つ以上あるときだけ、列挙のあとに分割案を書く。満たせない番号があるとき、または番号が一つだけのときは、列挙だけを書く。SDD スキルは、分割案があるときはそれを人に見せて止まる。課題を作るのは、人が明示して `sdd-cur-create-issue` を起動したときだけである。Spec Kit の `/tasks` と cc-sdd の `spec-tasks` は作業を分けるが、課題そのものは分けない。本課題が返すのは、子の課題への分割案である。

## 決定

行 `課題全体が大きすぎる` の文言は変えない。この行があるとき、SDD スキルは返った `action` と `kind` には従わない。

行 `課題全体が大きすぎる` のあとに、どの受け入れ条件が、分けても一回の実装作成役では書き終えられないかを列挙する。この列挙は残す。分割案を書くときは、その列挙のあとに、次の形で書く。

```
分割案:
- 1. 題: <題> 受け入れ条件: <番号の列> 依存: なし
- 2. 題: <題> 受け入れ条件: <番号の列> 依存: 1
```

`<題>` は、その子の課題の題であり、空白以外の文字を含む。`<番号の列>` は、その子にだけ入れる、レビューしている設計の受け入れ条件の番号である。番号は、それぞれ一度だけ、昇順に固定する。二つ以上のときは、`1, 3, 5` のとおりカンマと空白で区切る。番号が一つのときは、その番号だけを書く。設計の受け入れ条件の各番号は、ちょうど一つの子に入る。依存先は一つだけである。`<依存>` は、依存が無いときは `なし` である。依存があるときは、同じ分割案にある他の子の番号を一つだけ書く。例は `依存: 1` である。子の並びの番号は 1 から 1 ずつ増え、GitHub の課題番号ではない。分割案の中では、子の課題の題を書いてよい。分割案の外では、課題の題の案も、課題の番号の案も、課題を作る文も、書かない。

レビューしている設計の受け入れ条件の番号が二つ以上あり、受け入れ条件の番号を一つだけ子に入れても、一回の実装作成役で書き終えられる大きさの目安を満たせない番号が無いときだけ、列挙のあとに分割案を書く。番号が一つだけのとき、または番号を一つだけ子に入れても目安を満たせない番号があるときは、分割案を書くことは採用しない。そのときは、列挙だけを書く。

分割案を書くとき、各子は、一回の実装作成役で書き終えられる大きさの目安を満たす。この目安は、レビューしている設計の「一度に実装できる大きさ」節のとおりであり、件数、行数、ファイル数などの固定の数値や式では判定しない。子は二つ以上である。

`目安を超える` のときは、行 `課題全体が大きすぎる` も分割案も書かない。直す差分は、作業の一覧の中で作業を分ける修正のままである。

行 `課題全体が大きすぎる` があるとき、差分は「差分なし」、確認は `確認: なし`、判定は `判定: 不合格` のままである。分割案は差分に書かない。

SDD スキルは、レビュー応答を人に見せる。分割案があるときは、分割案を人に見せて止まる。人が聞く文は一つで、字面は `sdd-cur-create-issue` に分割案を渡して起動すれば子の課題を作れる。である。分割案が無いときは、その一文は伝えず、人の判断を待って止まる。この止まりで SDD スキルは課題を作らず、`sdd-cur-create-issue` を起動しない。設計修正役も設計作成役も起動しない。確認コメントは投稿しない。実装依頼に進めるとは伝えない。分割案はファイルにも課題コメントにも残さない。反映後の設計レビューは、設計の節のこの止まりに従う。

要求レビュー役に同じ止まりを足すかは、この要件では決めない。設計が決める。

この要件の分割案と止まりは、`docs/canonical/sdd.md` へ足す追加として、設計の `## 正本への差分` に書く。

## 範囲外

- 行 `課題全体が大きすぎる` の文言を変えること
- その行があるときに、返った `action` と `kind` に従うこと
- `目安を超える` のとき、作業の一覧の中で作業を分ける扱いを変えること
- 人が明示して `sdd-cur-create-issue` を起動していないときに、課題を作ること
- この止まりで `sdd-cur-create-issue` を起動すること
- 分割案をファイルまたは課題コメントに残すこと
- 分割案に、子の GitHub の課題番号を書くこと
- 受け入れ条件の番号を一つだけ子に入れても、一回の実装作成役で書き終えられる大きさの目安を満たせない番号があるときに、分割案を書くこと
- 一つの子に、依存先を二つ以上書くこと
- `受け入れ条件:` の番号を、昇順以外で書くこと
- 二つ以上の番号を、`1, 3, 5` のカンマと空白以外の区切りで書くこと
- `skills/sdd-cur-create-issue/SKILL.md` を変えること
- `skills/sdd-cur-quick/SKILL.md` を変えること
