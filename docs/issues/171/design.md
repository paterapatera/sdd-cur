対象は [Issue #171](https://github.com/paterapatera/sdd-cur/issues/171)。設計レビュー役が、作業を作業の一覧の中で分けても一回の実装作成役で書き終えられないとき、行 `課題全体が大きすぎる` のあとに列挙し、条件を満たすときだけ分割案を書く。SDD スキルは、分割案があるときは人に見せて止まり、`sdd-cur-create-issue` に分割案を渡して起動すれば子の課題を作れる、と一文で伝える。課題を作るのは、人が明示して `sdd-cur-create-issue` を起動したときだけである。

## 分割案の書式

分割案は、列挙の直後に書く。最初の行は、行全体が `分割案:` と一文字も違わない行である。その次の行から、子の行を書く。

子の行は、次の形である。

```
- <番号>. 題: <題> 受け入れ条件: <番号の列> 依存: <依存>
```

`<番号>` は、分割案の中の子の並び番号であり、1 から始まり 1 ずつ増える。GitHub の課題番号ではない。`<題>` は、その子の課題の題であり、空白以外の文字を含む。`<番号の列>` は、その子にだけ入れる、レビューしている設計の受け入れ条件の番号である。番号は、それぞれ一度だけ、昇順に固定する。二つ以上のときは、`1, 3, 5` のとおりカンマと空白で区切る。一つのときは、その番号だけを書く。設計の受け入れ条件の各番号は、ちょうど一つの子に入る。子は二つ以上である。各子は、一回の実装作成役で書き終えられる大きさの目安を満たす。

`<依存>` は、依存が無いとき `なし` である。依存があるときは、同じ分割案にある他の子の番号を一つだけ書く。例は `依存: 1` である。

例は、次である。

```
分割案:
- 1. 題: 前半の CLI を足す 受け入れ条件: 1, 2 依存: なし
- 2. 題: 後半のスキル手順を変える 受け入れ条件: 3 依存: 1
```

## 設計の手順

変えるファイルは、`agents/sdd-cur-design-reviewer.md` と `skills/sdd-cur/SKILL.md` の「設計」および反映後設計レビューの一文である。フロントマターは変えない。`src/agents-files.test.ts` と `src/sdd-skill-sdd-cur.test.ts` が今求める、設計レビュー役の既存の必須文言は残す。

### 設計レビュー役

作業をどう分けても目安を満たせないときのブロック（行 `課題全体が大きすぎる`、列挙、差分なし、確認なし、不合格、課題を作る文と題と番号の案を書かない）は、#88 のとおり残す。

そのブロックの列挙のあとに、次を足す。

- レビューしている設計の受け入れ条件の番号が二つ以上あり、受け入れ条件の番号を一つだけ子に入れても、一回の実装作成役で書き終えられる大きさの目安を満たせない番号が無いときだけ、列挙のあとに分割案を書く。分割案の書式は、本設計の「分割案の書式」のとおりである
- 受け入れ条件の番号が一つだけのとき、または番号を一つだけ子に入れても目安を満たせない番号があるときは、分割案は書かない。列挙だけを書く
- 分割案を書くとき、各子は目安を満たす。子は二つ以上である
- 分割案の中では子の題を書いてよい。分割案の外では、課題の題の案、課題の番号の案、課題を作る文、子の GitHub の課題番号は書かない

`目安を超える` の指摘のときは、行 `課題全体が大きすぎる` も分割案も書かない、という既存の定めは残す。

### SDD スキル

`skills/sdd-cur/SKILL.md` の「設計」で、行全体が `課題全体が大きすぎる` と一文字も違わない行があるときの止まりは、#88 のとおり残す。そのブロックの直後に、次を足す。

- レビュー応答に、行全体が `分割案:` である行があるときは、分割案を人に見せて止まる。人に伝える文は一つで、字面は `sdd-cur-create-issue` に分割案を渡して起動すれば子の課題を作れる。である。`sdd-cur-create-issue` を起動しない
- 行 `課題全体が大きすぎる` があるが、行 `分割案:` が無いときは、人の判断を待って止まる。`sdd-cur-create-issue` に分割案を渡す文は伝えない
- 分割案をファイルにも課題コメントにも残さない

反映後の設計レビューについて、行 `課題全体が大きすぎる` の止まりと返った `action` の扱いは、設計の節と同じである、という既存の一文は残す。上の分割案の止まりも、設計の節と同じである、と書く。

要求の段は変えない。設計の段の、作成役を起動する回数は変えない。
