# 37 先行する仕様との矛盾と巻き戻りをレビューで止める

対象は [Issue #37](https://github.com/paterapatera/sdd-cur/issues/37)。要求レビューと設計レビューは、同じ手順を定める既存の仕様と衝突する文を不合格にする。すでに書いてある決定を消す差分を不合格にする。四役と三役はサブエージェント役の構成が違うため同じ手順ではなく、その違いを衝突する文にしない。

## 受け入れ条件

- 同じ手順とは、手順の種別が同じであり、かつサブエージェント役の構成が同じことである。
- 手順の種別は、要求、設計、実装のレビューなどである。
- 構成が同じとは、起動する役の名前の集合が同じことである。順序は無視する。
- 四役と三役は、サブエージェント役の構成が違うため、同じ手順ではない。四役は修正案作成役を含む。三役は修正案作成役を起動しない。四役の仕様と三役の違いは、衝突する文にせず、不合格にしない。同じ手順の比較対象外である。
- 同じ手順を定める既存の要件または設計と食い違う新しい決定は、衝突する文である。
- すでに書いてある決定を消す巻き戻りは、衝突する文である。
- 巻き戻りは、すでに書いてある決定を消す差分である。同じ手順を定める既存の要件と設計の決定等と、レビューしているファイルを突き合わせ、その差分を探す。
- 要求レビューは、レビューしている要求ファイルに、同じ手順を定める既存の要件または設計と食い違う新しい決定があるとき、不合格にする。
- 設計レビューは、レビューしている設計ファイルに、同じ手順を定める既存の要件または設計と食い違う新しい決定があるとき、不合格にする。
- 要求レビューは、レビューしている要求ファイルに、すでに書いてある決定を消す巻き戻りがあるとき、不合格にする。
- 設計レビューは、レビューしている設計ファイルに、すでに書いてある決定を消す巻き戻りがあるとき、不合格にする。
- 要求レビュー役と設計レビュー役の、今ある指摘、出力の四項目、判定と確認の行は残す。
- `skills/sdd-cur/SKILL.md` の親の手順は変えない。
- `bun test` は `gh` を起動しない。ホームディレクトリと、実行中の Cursor のスキルおよびサブエージェントは触らない。

## サブエージェント

二つのレビュー役の frontmatter は変えない。要求レビュー役の `name` は `sdd-cur-req-reviewer`、設計レビュー役の `name` は `sdd-cur-design-reviewer` である。どちらも `readonly: true` を残す。

本文は日本語である。どちらの役も、課題を作らない。課題を閉じない。ラベルを変えない。実装しない。ファイルを変えない。`gh` を直接起動しない。受け入れ手順を投稿しない。完了処理をしない。確認コメントを投稿しない。

起動のタイミング、指摘の置き場所、出力の四項目、判定行と確認行の書き方は残す。今ある「指摘にするもの」の箇条は残す。好み、文体だけの提案、課題に無い仕組みの追加案は、指摘にしない、という既存の一文は残す。

### 要求レビュー

`agents/sdd-cur-req-reviewer.md` の「起動時」に、次を足す。

`docs/issues/` にある既存の `requirements.md` と `design.md` を読む。レビューしている要求ファイル以外は、同じ手順の決定と比べるために読む。同じ手順かどうかは、手順の種別と、起動する役の名前の集合で決める。順序は無視する。四役と三役は集合が違うので、比べない。それらをレビューしない。設計と実装のレビューは、今どおりしない。

「指摘にするもの」の前に、次の段落を置く。

同じ手順とは、手順の種別が同じであり、かつサブエージェント役の構成が同じことである。手順の種別は、要求、設計、実装のレビューなどである。構成が同じとは、起動する役の名前の集合が同じことである。順序は無視する。四役は修正案作成役を含む。三役は修正案作成役を起動しない。四役と三役は、サブエージェント役の構成が違うため、同じ手順ではない。四役の仕様と三役の違いは、衝突する文にしない。同じ手順の比較対象外である。既存の仕様は、同じ手順を定める既存の要件と設計である。

「指摘にするもの」の箇条に、次を足す。

- 同じ手順を定める既存の要件または設計と食い違う新しい決定がある。この新しい決定は、衝突する文である。四役の仕様と三役の違いは、この新しい決定にしない。
- すでに書いてある決定を消す巻き戻りがある。巻き戻りは、同じ手順を定める既存の要件と設計の決定等と、レビューしている要求ファイルを突き合わせ、すでに書いてある決定を消す差分を探すことである。この巻き戻りは、衝突する文である。四役の仕様と三役の違いは、この差分にしない。

直す差分は、その衝突する文を消す。すでに書いてある決定は残す。

### 設計レビュー

`agents/sdd-cur-design-reviewer.md` の「起動時」に、次を足す。

`docs/issues/` にある既存の `requirements.md` と `design.md` を読む。レビューしている設計ファイル以外は、同じ手順の決定と比べるために読む。同じ手順かどうかは、手順の種別と、起動する役の名前の集合で決める。順序は無視する。四役と三役は集合が違うので、比べない。それらをレビューしない。要求と実装のレビューは、今どおりしない。その課題の要件を読むことは残す。

「指摘にするもの」の前に、要求レビューと同じ段落を置く。

同じ手順とは、手順の種別が同じであり、かつサブエージェント役の構成が同じことである。手順の種別は、要求、設計、実装のレビューなどである。構成が同じとは、起動する役の名前の集合が同じことである。順序は無視する。四役は修正案作成役を含む。三役は修正案作成役を起動しない。四役と三役は、サブエージェント役の構成が違うため、同じ手順ではない。四役の仕様と三役の違いは、衝突する文にしない。同じ手順の比較対象外である。既存の仕様は、同じ手順を定める既存の要件と設計である。

「指摘にするもの」の箇条に、要求レビューと同じ二つを足す。

- 同じ手順を定める既存の要件または設計と食い違う新しい決定がある。この新しい決定は、衝突する文である。四役の仕様と三役の違いは、この新しい決定にしない。
- すでに書いてある決定を消す巻き戻りがある。巻き戻りは、同じ手順を定める既存の要件と設計の決定等と、レビューしている設計ファイルを突き合わせ、すでに書いてある決定を消す差分を探すことである。この巻き戻りは、衝突する文である。四役の仕様と三役の違いは、この差分にしない。

直す差分は、その衝突する文を消す。すでに書いてある決定は残す。要求ファイルは変えない。
