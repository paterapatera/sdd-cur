# 39 設計の未決が残るあいだは実装依頼へ進まない。。

対象は [Issue #39](https://github.com/paterapatera/sdd-cur/issues/39)。設計作成が親への返信に残した決められない点があるあいだ、`sdd-cur` の設計の手順はレビューに入らず、合格として実装依頼へ進める旨を伝えない。決められない点を人に見せて止まる。

対象の手順は、`skills/sdd-cur/SKILL.md` の「設計」である。

## 現状

設計作成役は、決められない点を設計ファイルへ書かず、親への返信に列挙する。`agents/sdd-cur-design-author.md` は、親への返信に「ファイルへ書かなかった、決められない点」を含める。

親の設計の手順は、設計作成役を起動し、ファイルを書いたあと、設計レビューと修正指示を起動する。設計作成役が返した決められない点の列挙を見ない。列挙が空でないときもレビューに入る。設計レビューが合格したとき、実装依頼に進めることができる、と人に伝えて終わる。

要求の手順は、要求作成役が返した質問する未記載があるとき、レビューに入る前に Cursor の質問機能で質問する。設計の手順に、設計作成役の決められない点に相当する止まりは無い。

## 受け入れ条件

- 設計作成役の返信に含まれる、ファイルへ書かなかった決められない点の列挙が、一つでもあるとき、親は設計レビューを起動しない。
- 上のとき、親は設計修正指示を起動しない。
- 上のとき、親は、判定が合格なら実装依頼に進めることができる、と人に伝えない。
- 上のとき、親は、列挙された決められない点を人に見せ、設計の手順を止まる。
- 上のとき、決められない点は設計ファイルへ書かない。
- 設計作成役の返信の決められない点の列挙が空のときだけ、設計ファイルを書いたあと、設計レビューと修正指示に入ってよい。
- 人が答えたあとは、その答えを人が決めた条件として、設計作成役を再び起動する。決められない点の列挙が空になるまで、設計レビューに入らない。
- 設計の手順の、回数、モデル、印が壊れているときのやり直し、判定行と確認行、`確認: なし` の修正、二択でないときの止まりは、本要件で変えない。

## 設計の手順

対象は、`skills/sdd-cur/SKILL.md` の「設計」である。

設計作成役を起動したあと、返信の「ファイルへ書かなかった、決められない点」を読む。列挙が空でないときは、列挙を人に見せ、設計レビューと修正指示を起動しない。実装依頼に進めることができる、と伝えない。設計ファイルを書いたあとでも同じである。

列挙が空のときは、今の手順どおり、設計ファイルを書いたあと、設計レビューと修正指示を起動する。

人が答えたあとは、その答えを人が決めた条件として、設計作成役を再び起動する。列挙が空になるまで、設計レビューに入らない。

- 設計レビュー役の指摘観点の変更
- quick の設計の段（#56 で扱う）
- 課題の作成とクローズ
- ラベルの変更
