# 172 課題作成スキルで、分割案から複数の課題を作れるようにする

<!-- sdd-cur:form -->

対象は [Issue #172](https://github.com/paterapatera/sdd-cur/issues/172)。`sdd-cur-create-issue` は、一回の起動で課題を 1 件作る。渡した内容がこの要件でいう分割案の形であるときは、一回の起動で、子の行ごとに課題を作る。分割案の形でないときは、作る課題は 1 件のままである。人が明示して起動したときだけ課題を作る。四つのタイプと、各タイプの見出しは、#143 のままである。

分割案の形とは、渡した内容の非空行が次だけであることである。最初の非空行は、行全体が `分割案:` である。その後の非空行は二つ以上である。各行は、行全体が `- <番号>. 題: <題> 受け入れ条件: <番号の列> 依存: <依存>` である。最初の子の番号は 1 であり、次の子の番号は 1 ずつ増える。`<題>` は空白以外の文字を含む。`<番号の列>` は、番号が一つのときはその番号だけである。番号が二つ以上のときは、昇順であり、`1, 3, 5` のとおりカンマと空白で区切る。`<依存>` は、依存が無いときは `なし` である。依存があるときは、同じ分割案にある他の子の番号を一つだけ書いたものである。

## 現状

`sdd-cur-create-issue` の description は、起動時の作業ツリーの git リポジトリに GitHub の課題を 1 件作る、と書く（`skills/sdd-cur-create-issue/SKILL.md` の 3 行）。`gh issue create` は 1 回であり、内容が複数の話題でも、作る課題は 1 件である（`skills/sdd-cur-create-issue/SKILL.md` の 103 行）。本文用の内容が無いかスペースと改行だけであり、組み立てた本文から題を決められるときは、`gh issue create` を 1 回実行し、課題を 1 件作る（`skills/sdd-cur-create-issue/SKILL.md` の 99 行）。課題が 1 件できたとき、その番号と URL をチャットで人に伝える（`skills/sdd-cur-create-issue/SKILL.md` の 110 行）。作った課題は閉じない（`skills/sdd-cur-create-issue/SKILL.md` の 114 行）。コメントを投稿しない（`skills/sdd-cur-create-issue/SKILL.md` の 117 行）。ラベル、担当者、マイルストーンは付けない（`skills/sdd-cur-create-issue/SKILL.md` の 110 行）。

使い分ける課題のタイプは、ユーザーストーリー、修正、機能改善、調査の四種類である（`skills/sdd-cur-create-issue/SKILL.md` の 12 行）。作業ツリーが git リポジトリであるとき、どのタイプの課題を作るかを、Cursor の質問機能の選択肢で人に聞く（`skills/sdd-cur-create-issue/SKILL.md` の 17 行）。人が四つのうち一つを選んだあと、そのタイプ向けの質問を、一覧の順に一問ずつ聞く（`skills/sdd-cur-create-issue/SKILL.md` の 18 行）。課題の本文にある、行頭が `## ` の行は、選んだタイプの見出しだけであり、そのタイプで定めた順だけである（`docs/canonical/sdd.md` の 2317 行）。

正本は、件数は条件を満たすとき 1 件であり、内容が複数の話題でも 1 件であり、`gh issue create` は 1 回である、と定める（`docs/canonical/sdd.md` の 1989 行）。起動は、人が Cursor のチャットで、このスキルを明示して起動したときである（`docs/canonical/sdd.md` の 1977 行）。人が明示して起動したときに、`skills/sdd-cur-create-issue` が課題を作る（`docs/policy.md` の 41 行）。

`src/create-issue.test.ts` は、description が課題を 1 件作る、と書くことを確かめる（`src/create-issue.test.ts` の 17 行）。同じファイルは、スキル本文に `1 件` があることを確かめる（`src/create-issue.test.ts` の 33 行）。`src/143.test.ts` は、`gh issue create` を 1 回実行し、課題を 1 件作る、とスキルに書いてあることを確かめる（`src/143.test.ts` の 264 行）。

#171 の分割案では、子の行は `- <番号>. 題: <題> 受け入れ条件: <番号の列> 依存: <依存>` の形である（`docs/canonical/sdd.md` の 2512 行）。`sdd-cur-create-issue` は、内容が複数の話題でも作る課題は 1 件である、と書く（`skills/sdd-cur-create-issue/SKILL.md` の 103 行）。

## 決定

承認前に人へ見せる各件の `## 重なる課題` には、元の課題の番号を書く。その字面は、一件を作るときに人がその節へ答える形式を、得たままである。`#171` も `#171（説明）` も、得たままである。その子の `依存` が他の子の番号であるときは、`#子` の直後にその子番号を続けたものを書く。例は `#子1` である。`依存` が `なし` であるときは、依存先の子番号は書かない。

人が全件の題と本文を承認したあと、各件の `gh issue create` の直前に、承認された本文の `## 重なる課題` にある `#子` の直後の依存先の子番号を、`#` の直後に、その子としてすでに作った課題の GitHub の課題番号を続けたものに置き換える。置き換えた本文で `gh issue create` を実行する。元の課題の番号は置き換えない。置き換えた本文を、人の承認のためには見せ直さない。

分割案と `sdd-cur show` で埋められる節は、人に問わず埋める。埋められない節だけを、件ごとに質問する。見出しごとの対応は、この要件では決めない。元の課題の番号の入手は、この要件では決めない。どちらもこの課題の設計が決める。

複数の課題を作るとき、タイプを聞く質問の選択肢は五つであり、上から `ユーザーストーリー`、`修正`、`機能改善`、`調査`、`一件ずつ選ぶ` である。人が読む文言は、各 ID と一文字も違わない。`一件ずつ選ぶ` を選んだあとは、件ごとに、選択肢の ID が上から `ユーザーストーリー`、`修正`、`機能改善`、`調査` である質問でタイプを聞く。

見せた題と本文の承認は、Cursor の質問で `この内容で課題を作る` を選ぶことである。選ばないときは、課題を作らず、止まる。`gh issue create` は実行しない。人はチャットで直した全文を渡す。スキルは渡された全文を人に見せる。その全文について `この内容で課題を作る` を選ぶまで、`gh issue create` を実行しない。

作る順は、依存先を先にするトポロジカル順である。`依存` が `なし` である子どうしは、分割案の子番号の昇順で作る。`依存` が他の子の番号であり、依存先の課題がすでに作られていて同時に作れる子どうしも、分割案の子番号の昇順で作る。子の `依存` を追うと循環があるとき、および `依存` が `なし` でなく同じ分割案にある子の番号でもないときは、課題を作らない。`gh issue create` は実行しない。止まり、理由を伝える。

分割案の形で全件の `gh issue create` が成功したときは、作った課題の番号と URL を人に伝える。
分割案の形で起動時の作業ツリーが git リポジトリでないときは、タイプを聞くより前に止まる。課題を作らない。git リポジトリでない旨を伝える。`gh issue create` は実行しない。
分割案の形で件ごとに質問したあと、答えが空またはスペースと改行だけの質問が一つでもあるときは、課題を作らない。足りない質問として伝え、止まる。`gh issue create` は実行しない。
分割案の形でタイプを聞くとき、五つの ID 以外が選ばれたときは、同じ五つの ID で聞き直す。その ID では課題を作らず、`gh issue create` は実行しない。`一件ずつ選ぶ` のあと件ごとにタイプを聞くとき、四つの ID 以外が選ばれたときは、#143 と同様に同じ四つの ID で聞き直す。

## 範囲外

- 人が `sdd-cur-create-issue` を明示して起動していないときに、課題を作ること
- 分割案の形でない内容で、課題を 2 件以上作ること
- 分割案の形でないときに、タイプを聞き、そのタイプの質問を一問ずつ聞いてから 1 件作る手順を変えること
- ユーザーストーリー、修正、機能改善、調査の見出しの文言または順を変えること
- 元の課題へコメントを投稿すること
- 元の課題のラベルを変えること
- 元の課題に担当者を付けること
- 作った課題を閉じること
- #171 の分割案の行の形を変えること
