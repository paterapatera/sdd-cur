# 7 完了処理の共通化と完了スキル

対象は [Issue #7](https://github.com/paterapatera/sdd-cur/issues/7)。完了処理を一つにし、課題ランナーと、Project A の Cursor で人が起動する完了スキルの両方から呼ぶ。

依存は #2 と #6 である。#6 までで、実装の結果であるマージリクエストが存在する。

人が受け入れテストに合格した課題へ「動作確認OK」を付ける。完了処理は、その課題のマージリクエストをスカッシュマージし、同時に「マージ済み」を付ける。課題は閉じない。お客さまの確認が取れてから、人が閉じる。

課題ランナーはクローンで「動作確認OK」を見る。完了スキルは Project A の Cursor で人が起動する。

## 受け入れ条件

- 課題ランナー経由と完了スキル経由の両方で、同じ完了処理が動く。
- すでにマージ済みのマージリクエストは、もう一度マージしない。残っている「マージ済み」だけを揃える。
- 一つのプロジェクトで、課題ランナーと完了スキルを同時には有効にできない。
- 完了処理を終えた課題は、次の「動作確認OK」の探索から外れる。

## 完了処理

完了処理は一つである。行うことは、次である。

- 対象は「動作確認OK」が付いた課題である。
- その課題のマージリクエストをスカッシュマージする。
- スカッシュマージと同時に「マージ済み」を付ける。
- 課題は閉じない。

すでにマージ済みのマージリクエストは、もう一度マージしない。行うのは「マージ済み」を揃えることだけである。

完了処理を終えた課題は、次に「動作確認OK」を探す対象から外れる。すでにマージ済みで「マージ済み」を揃えただけのときも、同じである。

スカッシュマージは完了処理だけが行う。受け入れテストのあいだ、マージリクエストは開いたままである。

## 呼び出し元

同じ完了処理を、次の二つの入口から呼べる。

- 課題ランナーが「動作確認OK」を見て行う。
- 人が Project A の Cursor で、完了スキルから行う。

一つのプロジェクトで有効にする入口は、どちらか一つである。両方を同時には有効にしない。この選択を一つのプロジェクトに持たせる土台を作る。

このプロジェクトでどちらを有効にするかは、計画の未決である。要件では決めない。

## 範囲外

次は、この要件に含めない。

- 受け入れテストが不合格のとき、ラベルを何にし、課題ランナーが直すのか、Project A の Cursor で直すのか（計画の未決）
- このプロジェクトで有効にする呼び出し元の選択（計画の未決）
- 「動作確認OK」を付けること。付けるのは人である
- 「実装依頼」から「実装完了」まで。受け入れ手順のコメント（#6）
- 課題の作成とクローズ
- 着手、要件、設計、確認、回答の取り込み
- Forgejo、Jira、Backlog
