## 決定

同じことを言う要求が複数あるとき、本文がいちばん具体的な要求を残す。残す要求の識別子は、今の識別子のままである。ほかの要求は、削除の差分にする。

REQ-499 は、変更の差分にする。その変更は、作業ブランチ名を `task-<番号>` に直す。識別子 REQ-499 は残す。

`spec-check` が近いと出す組のうち、述べることが違う組は、別の要求のまま残す。意味は変えない。本文は、近さが下がるように書き分ける。書き分けは、変更の差分にする。その識別子は、今の識別子のままである。書き分けたあと、`spec-check` はその組を報告しない。例は、REQ-595 と REQ-596、REQ-647 と REQ-648 である。述べることが同じ組だけを、一つの要求にする。

## 関係する課題

課題は、次を関係するとする。

- #122（正本の重複と壊れた文末の検査）
- #17（作業ブランチ名）
- #28（`poll` の優先順と、マージリクエストの件数）
- #81（二つのクローン）
- #96（agent の前のマージ）
- #129（設計の合格のあとの push と「実装依頼」）

#122 は、`spec-check` が同じファイルの中の近い本文と、壊れた文末を見つける、と定める。今の正本全体を、検査の終了コードが 0 になるように直すことは、#122 の範囲外である。この要件は、三つのファイルについて、近い本文と壊れた文末の報告が無いところまで整理する。述べることが同じ組は、本文がいちばん具体的な要求を残して一つにする。述べることが違う組は、意味を変えずに本文を書き分け、検査が報告しないようにする。検査の規則は変えない。

#17 は、作業ブランチ名を `task-<番号>` とする。この要件は、その挙動を変えない。正本の REQ-499 は、作業ブランチ名を `sdd-cur/<番号>` と書く。この要件は、REQ-499 を変更の差分にし、作業ブランチ名を `task-<番号>` に直す。識別子 REQ-499 は残す。

#28 は、`poll` の優先順と、マージリクエストの件数の扱いを定める。正本の `docs/canonical/runner.md` には、その定めが複数の要求として入っている。この要件は、同じことを言う要求のうち、本文がいちばん具体的な要求を残し、ほかは削除の差分にする。#28 が定めた挙動は変えない。

#81 は、同じアカウントの二つのクローンが同じ課題の着手を同時に取ったとき、続けるのは一つだけである、と定める。この要件は、その挙動を変えない。#81 に由来する要求の壊れた文末は、意味を変えずに直す。

#96 は、実装の agent の前と、修正の agent の前で、デフォルトブランチを作業ブランチへマージする、と定める。正本では、REQ-647 が実装の前、REQ-648 が修正の前を書く。この二つは、述べることが違う。別の要求のまま残す。意味は変えない。本文は、近さが下がるように書き分ける。この要件は、その挙動を変えない。

#129 は、設計の合格の案内で「ここで止める」を選んだときと、「実装依頼する」を選んだときを、分けて定める。正本では、REQ-635 と REQ-641 が、その定めを書く。この要件は、その挙動を変えない。
