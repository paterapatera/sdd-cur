# 6 課題ランナー: 実装依頼から実装完了まで

対象は [Issue #6](https://github.com/paterapatera/sdd-cur/issues/6)。クローン上の `run` が、「実装依頼」から「実装完了」までを行う。

人が `docs/issues` をリモートへ push し、課題に「実装依頼」を付けてから、クローンが作業する。課題ランナーは Project A の作業ディレクトリでは動かさない。

## 受け入れ条件

- クローン一つで、「実装依頼」の課題を「実装完了」まで進められる。
- 二つのクローンが、別々の「実装依頼」を同時に進められる。同じ課題を二つのクローンが実装しない。

## 探索と着手

`run` は、「実装依頼」があり、「実装中」が無い課題を探す。要件や設計の途中の課題は実装しない。

着手するクローンは、実装を始める前に「実装依頼」を外し、「実装中」を付ける。「実装中」の課題は、他のクローンの探索対象から外れる。

処理のあいだは次の課題を取らない。処理が終わったら、再び探索する。

## 実装

作業ブランチは、push 済みの `docs/issues` を含むリモートの状態から作る。クローンはその `docs/issues` を読んで実装する。

ラベルを変えたあと、そのクローンで実装のスキルを Cursor に実行させる。実装の結果はマージリクエストにする。受け入れテストのあいだ、マージリクエストは開いたままにする。

## 実装完了

実装が終わったら、課題ランナーが受け入れ手順を課題のコメントに書く。コメントの最初の非空行は `sdd-cur: 受け入れ手順` であり、印の行より後ろが手順の本文である。

コメントのあと、ラベルを「実装完了」に変える。「実装中」を外し、「実装完了」を付ける。課題は閉じない。

## 範囲外

次は、この要件に含めない。

- 完了処理。スカッシュマージと「マージ済み」は完了処理が行う
- 「動作確認OK」を付けること。付けるのは人である
- 課題の作成
- Forgejo、Jira、Backlog
