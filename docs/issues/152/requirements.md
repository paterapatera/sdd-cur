# 152 設計の決められない点を Cursor の質問機能で聞く

## 決定

設計作成役の返信に、ファイルへ書かなかった決められない点の列挙が一つでもあるとき、SDD スキルの親は、確認待ち以外の点があるときだけ、Cursor の質問機能で人に質問する。質問の形式が要求の手順と同じとは、受け入れ条件 9、受け入れ条件 10、受け入れ条件 11 の採点ラベル、選択肢、末尾の確認選択肢の形式に限る。通常の選択肢は、先頭を `[スコア `、1 以上 5 以下の整数、`]` の順で始め、続けて選択肢本文とする。通常の選択肢を 1 つ以上並べ、最後に `課題のコメントで確認する` を置く。最後の選択肢には、通常の選択肢の形式を付けない。

設計の決められない点を Cursor の質問機能で聞くとき、質問文と選択肢は SDD スキルの親が作る。要求の未記載を聞くのと同様に質問するとは、親が設計作成役の列挙を読んで Cursor の質問機能で質問することに限る。設計作成役は質問を出さない。

設計作成役の返信に、ファイルへ書かなかった決められない点が複数あるとき、SDD スキルの親は、人が `課題のコメントで確認する` を選び、その確認が `reflect` で終わる前に列挙に残っている点を除いた決められない点ごとに、Cursor の質問を一つ出す。

設計の決められない点について、人が `課題のコメントで確認する` を選んだときの、要求の手順と同じ扱いとは、受け入れ条件 15 から受け入れ条件 24 までの確認待ちの扱いに限る。その点は決定として書かない。課題コメントの確認手順に回す。確認の手順に入る前に `show` を改めて実行する。確認の節に従い、payload を人に見せ、人がその本文を承認したあとだけ `sdd-cur confirm <番号>` を実行する。印の行は入れない。人が直したときは、直した文字列を改めて見せ、その文字列の承認があるまで `confirm` を実行しない。`unanswered` が空でないとき、および `nextAnswer` が `null` でないときは、次の確認は投稿しない。その点は、依存の判断では待ちの点として扱う。

#39 の、決められない点の列挙を人に見せる手段を、Cursor の質問機能に置き換える。止まること、人が答えたあと設計作成役を再び起動すること、列挙が空になるまで設計レビューに入らないことは、#39 のとおり維持する。

設計の決められない点について、人が通常の選択肢を選んだときは、選ばれたラベル全体（先頭の `[スコア `、1 以上 5 以下の整数、`]`、選択肢本文の順）を人が決めた条件として設計作成役を再び起動する。決められない点の列挙が空になるまで、設計レビューと修正指示に入らない。

課題本文の「要件の場合も同様」は、設計の列挙を Cursor の質問機能に変えることの比喩である。要求の手順の変更は本課題の範囲外である。
