# 122 正本の重複と壊れた文を見つける検査を足す

対象は [Issue #122](https://github.com/paterapatera/sdd-cur/issues/122)。`docs/canonical/` 全体を検査するサブコマンドを足す。言い換えの重複、壊れた文末、空の本文、識別子の重複を見つける。

手を入れる対象は `src/cli.ts` と、`src/conventions.ts` または新しい `src/spec.ts` である。

重なる課題は #85、#86、#87 である。

比べる相手は、OpenSpec の `openspec validate --strict` である。

## 受け入れ条件

- `src/cli.ts` のサブコマンド名は `spec-check` である。
- 使い方の表示は `sdd-cur spec-check` である。
- 起動は `bun src/cli.ts spec-check` である。
- `spec-check` に、引数は無い。
- `spec-check` に引数が一つでもあるときは、検査しない。
- そのとき、終了コードは 1 である。

- 引数が一つでもあるときの、その一行の字面は、設計で決める。
- 引数が一つでもあるとき、標準出力には書かない。
- 検査する正本は、作業ディレクトリの `docs/canonical/` である。
- 作業ディレクトリに `docs/canonical/` が無いときは、見つけたものが一件も無いときと同じである。
- そのとき、終了コードは 0 である。
- そのとき、標準出力には書かない。
- そのとき、標準エラーには書かない。

- 読み取りに失敗したときの、その一行の字面は、設計で決める。
- 読み取りに失敗したとき、標準出力には書かない。
- `spec-check` は、同じ `docs/canonical/<領域>.md` にある二つの要求で、本文が近い組を見つける。
- 比較する本文は、行全体が「もとになった課題は #N である。」である行を除いた残りである。
- 近さは、その残りの文字 2-gram の Jaccard 係数で測る。
- しきい値の数値は、今の正本で試して設計で決める。
- 壊れた文末の検出は、行末が `(ない|する|いる|ある|る|う)である` に合う行から始める。
- 誤検出を除く規則は、設計で決める。
- 壊れた文末は、誤検出を除いたあとに残った行ごとに一件である。
- 同じ要求に壊れた文末が二行あるときは、二件である。
- `spec-check` は、本文が空の要求を見つける。
- 本文が空とは、行全体が `## REQ-<番号>` である見出しの次の行から、次のその見出しの前まで、またはファイルの末尾までに、空白以外の文字が無いことである。
- `spec-check` は、識別子の重複を見つける。
- 識別子の重複とは、行全体が同じ `## REQ-<番号>` である見出しが、`docs/canonical/` の `.md` に二度以上あることである。
- 識別子の重複は、重複している識別子ごとに一件である。
- 同じ識別子が三回以上あるときも、一件である。
- 見つけたもの一件につき、標準エラーへ日本語の一行を書く。
- その一行の字面は、設計で決める。
- 近い要求の組は、その組を一件として数える。
- 種類が違う見つけたものは、別の一件である。
- 見つけたものが一件以上あるとき、終了コードは 1 である。
- 見つけたものが一件も無いとき、終了コードは 0 である。
- 見つけたものが一件も無いとき、標準エラーには書かない。
- 見つけたものは、標準出力には書かない。
- 見つけたものが一件も無いとき、標準出力には書かない。
- テストは、一時ディレクトリを作業ディレクトリにして、`bun src/cli.ts spec-check` を実行する。
- 今のリポジトリの `docs/canonical/` がこの検査を通ることは、受け入れ条件にしない。
- 検査の関数は、`src/conventions.ts` か、新しい `src/spec.ts` のどちらかに置く。どちらにするかは、設計が選ぶ。

## 関係する課題

課題は、次を関係するとする。

- #85（要件と設計の形を決め、CLI で形式を検査する）
- #86（仕様の正本と、課題の差分）
- #87（既存の仕様を正本へ移す）

#85 の `validate` は、課題番号の要件と設計の形式を検査する。この要件が足すのは、正本 `docs/canonical/` 全体を見る別のサブコマンドである。

#86 は、正本を `docs/canonical/<領域>.md` に置き、同じ識別子は正本に一度だけある、と定める。差分の識別子が正本にあるかは、`validateCanonicalDelta` が見る。この要件が足すのは、正本そのものを見る別の検査である。

#87 は、課題の要件と設計の両方から正本へ移した。この要件は、その移行をやり直さない。

## 範囲外

次は、この要件に含めない。

- 正本の整理そのもの（整理は #124 などで行う）
- 正本とコードの食い違いの検出
