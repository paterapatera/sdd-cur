# 29 受け入れ手順は PR の概要に書き課題コメントは PR のリンクだけにする

対象は [Issue #29](https://github.com/paterapatera/sdd-cur/issues/29)。課題ランナーが投稿するコメントは、マージリクエストの URL だけである。受け入れ手順は、マージリクエストの本文に書く。課題の URL も本文に残す。

## 現状

課題ランナーは、受け入れ手順を課題コメントに書く。印は `sdd-cur: 受け入れ手順` である。マージリクエストの本文は、課題の URL である。

## 受け入れ条件

- 課題ランナーが投稿するコメントは、マージリクエストの URL だけである。
- 確認と回答の課題コメントは変えない。
- 受け入れ手順は、マージリクエストの本文に書く。
- マージリクエストの本文には、課題の URL も残す。
- 本文の並びは、課題の URL、印、受け入れ手順の順である。
- 印 `sdd-cur: 受け入れ手順` は、本文にある受け入れ手順の最初の非空行である。
- 課題の URL は、印の行より後ろの手順に含めない。
- 現在の手順は、本文の印の行より後ろから取る。
- 課題ランナーが投稿するコメントには、印を書かない。

## 決定

課題ランナーが投稿するコメントは、マージリクエストの URL だけである。題や説明は付けない。

確認と回答の課題コメントは変えない。

課題に付くコメントをすべて、マージリクエストのリンクだけにすることは、採用しない。

概要は、マージリクエストの本文である。本文には、受け入れ手順を書く。課題の URL も残す。

印 `sdd-cur: 受け入れ手順` は、本文にある受け入れ手順の最初の非空行である。課題ランナーが投稿するコメントには、印を書かない。

本文の並びは、課題の URL、印、受け入れ手順の順である。課題の URL は印より前なので、印の行より後ろの手順には含めない。現在の手順は、本文の印の行より後ろから取る。

## 課題コメント

課題ランナーが投稿するコメントは、マージリクエストの URL だけである。題や説明は付けない。印 `sdd-cur: 受け入れ手順` は書かない。受け入れ手順は、このコメントに書かない。

確認と回答の課題コメントは変えない。

## マージリクエストの概要

概要は、マージリクエストの本文である。

本文の並びは、課題の URL、印 `sdd-cur: 受け入れ手順`、受け入れ手順の順である。課題の URL も残す。

印 `sdd-cur: 受け入れ手順` は、本文にある受け入れ手順の最初の非空行である。課題の URL は印より前なので、印の行より後ろの手順には含めない。現在の手順は、本文の印の行より後ろから取る。

## 範囲外

次は、この要件に含めない。

- ラベルの変更
- 課題の作成とクローズ
- 完了処理。スカッシュマージと「マージ済み」
- 不具合と修正の会話コメント（#28）
- 受け入れ手順が受け入れ条件を一通り確かめられるかの検査（#40）
- Forgejo、Jira、Backlog
