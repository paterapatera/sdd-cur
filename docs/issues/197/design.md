# 197 実装スキルが正本を手で書かず spec-apply を使う

<!-- sdd-cur:form -->

対象は [Issue #197](https://github.com/paterapatera/sdd-cur/issues/197)。実装スキルは、設計の `## 正本への差分` を `docs/canonical/` へ反映することを、実装作成役に任せている。実装レビュー役は、作業ツリーの `docs/canonical/` が差分のとおりかを読む。この課題では、実装スキルが `sdd-cur tasks <番号>` に成功したあと、`sdd-cur spec-apply <番号>` を一度だけ実行する。`done` が偽の作業があるときは、最初の実装作成役を起動する直前である。各未完了作業の直前には実行しない。`tasks` より前には実行しない。すべての作業の `done` が真で実装作成役を一度も起動しないときも、レビューに入る前に一度実行する。実装作成役と実装修正役は `docs/canonical/` を書かない。`spec-apply` の終了コードが 0 以外のときは、人に見せる一行を、標準エラーの最初の非空行、それが空のときは標準出力の最初の非空行とし、その一行を人に見せて止まる。実装作成役、実装修正役、実装レビュー役は起動しない。agent は失敗で終える。実装レビュー役は、正本の本文を自分で突き合わせず、正本が差分どおりかを、親が渡す `spec-diff` の終了コードだけを見る。

重なる課題は #196 と #123 である。#196 は `spec-apply` を足し、実装スキルとサブエージェントの手順は範囲外とする。#123 は `spec-diff` を足し、実装スキルが実行して終了コードをレビュー役へ渡す。

比べる相手は、OpenSpec の `/opsx:apply` と `/opsx:archive` の分担である。OpenSpec では、実装はエージェントが行い、正本への統合は archive が行う。この課題が変えるのは、実装スキルが `tasks` の成功のあと `spec-apply` を一度実行し、作成役と修正役が正本を書かないことである。

手を入れる対象は、`skills/sdd-cur-implement/SKILL.md`、`agents/sdd-cur-implement-author.md`、`agents/sdd-cur-implement-fixer.md`、`agents/sdd-cur-implement-reviewer.md` である。`skills/sdd-cur-quick/SKILL.md` と `skills/sdd-cur-fix/SKILL.md` は、正本を書く手順があるときだけ手を入れる。今の二つのファイルには、その手順が無い。
