# 197 実装スキルが正本を手で書かず spec-apply を使う

<!-- sdd-cur:form -->

対象は [Issue #197](https://github.com/paterapatera/sdd-cur/issues/197)。実装スキルは、設計の `## 正本への差分` を `docs/canonical/` へ反映することを、実装作成役に任せている。実装レビュー役は、作業ツリーの `docs/canonical/` が差分のとおりかを読む。この課題では、実装スキルが `sdd-cur tasks <番号>` に成功したあと、`sdd-cur spec-apply <番号>` を一度だけ実行する。`done` が偽の作業があるときは、最初の実装作成役を起動する直前である。各未完了作業の直前には実行しない。`tasks` より前には実行しない。すべての作業の `done` が真で実装作成役を一度も起動しないときも、レビューに入る前に一度実行する。実装作成役と実装修正役は `docs/canonical/` を書かない。`spec-apply` の終了コードが 0 以外のときは、人に見せる一行を、標準エラーの最初の非空行、それが空のときは標準出力の最初の非空行とし、その一行を人に見せて止まる。実装作成役、実装修正役、実装レビュー役は起動しない。agent は失敗で終える。実装レビュー役は、正本の本文を自分で突き合わせず、正本が差分どおりかを、親が渡す `spec-diff` の終了コードだけを見る。

重なる課題は #196 と #123 である。#196 は `spec-apply` を足し、実装スキルとサブエージェントの手順は範囲外とする。#123 は `spec-diff` を足し、実装スキルが実行して終了コードをレビュー役へ渡す。

比べる相手は、OpenSpec の `/opsx:apply` と `/opsx:archive` の分担である。OpenSpec では、実装はエージェントが行い、正本への統合は archive が行う。この課題が変えるのは、実装スキルが `tasks` の成功のあと `spec-apply` を一度実行し、作成役と修正役が正本を書かないことである。

手を入れる対象は、`skills/sdd-cur-implement/SKILL.md`、`agents/sdd-cur-implement-author.md`、`agents/sdd-cur-implement-fixer.md`、`agents/sdd-cur-implement-reviewer.md` である。`skills/sdd-cur-quick/SKILL.md` と `skills/sdd-cur-fix/SKILL.md` は、正本を書く手順があるときだけ手を入れる。今の二つのファイルには、その手順が無い。

- 25. 条件: 正本が、実装スキルは作成役を起動する前に `sdd-cur tasks <番号>` を一度実行し、すべての作業がもともと `done` であるときもレビューに入る、と定めている 主体: この課題 結果: その進め方へ、`sdd-cur spec-apply <番号>` を `tasks` の成功のあとに一度実行する位置を足す。`done` が偽の作業があるときは、最初の実装作成役を起動する直前である。すべての作業の `done` が真で実装作成役を一度も起動しないときは、レビューに入る前である。各未完了作業の直前には実行しない。`tasks` より前には実行しない。終了コードが 0 以外のときは、人に見せる一行を標準エラーの最初の非空行、それが空のときは標準出力の最初の非空行とし、その一行を人に見せて止まり、実装作成役、実装修正役、実装レビュー役を起動せず、agent は失敗で終える。agent の終了コードは 0 以外である。`tasks` を一度実行すること、`done` が真の作業は起動しないこと、並びの順に同時には起動しないこと、`task-done`、`task-done` 以外はコミットしないこと、すべての作業のあと一度だけレビューすることは、変えない
- 26. 条件: `skills/sdd-cur-fix/SKILL.md` を見る 主体: `sdd-cur-fix` 結果: `spec-apply` を実行しない

## 決定

`sdd-cur spec-apply <番号>` は、`sdd-cur tasks <番号>` が成功したあと、一度だけ実行する。`<番号>` は、実装スキルに渡された課題番号である。`done` が偽の作業があるときは、最初の実装作成役を起動する直前である。各未完了作業の直前には実行しない。`tasks` より前には実行しない。すべての作業の `done` が真で、実装作成役を一度も起動しないときも、レビューに入る前に一度実行する。

`spec-apply` の終了コードが 0 以外のとき、人に見せる一行は、標準エラーの最初の非空行であり、それが空のときは標準出力の最初の非空行である。その一行を人に見せて止まる。実装作成役、実装修正役、実装レビュー役は起動しない。agent は失敗で終える。agent の終了コードは 0 以外である。

`spec-apply` の終了コードが 0 であり、`done` が偽の作業があるときは、作業の一覧の今の進め方で実装作成役を起動する。終了コードが 0 であり、すべての作業の `done` が真で実装作成役を一度も起動しないときは、レビューに入る。

実装作成役と実装修正役は `docs/canonical/` を書かない。

実装レビュー役は、正本の本文を設計の `## 正本への差分` の項目の本文と突き合わせない。正本が差分どおりかは、親が渡す `spec-diff` の終了コードだけを見る。

## 範囲外

次は、この要件に含めない。

- `spec-apply` と `spec-diff` のコマンド実装を変えること
- 実装スキルが `spec-diff` を実行し、記述、終了コード、出力をレビュー役へ渡す手順を変えること
- 終了コードが 0 以外でもレビュー役を起動することを変えること
- レビュー役が `spec-diff` を自分で実行しないことを変えること
- 作業の一覧の進め方のうち、作成役を起動する前の `sdd-cur tasks <番号>`、`done` が真の作業は起動しないこと、並びの順に同時には起動しないこと、作成役が作業ツリーを変えたあとの `task-done`、変えなかったときは `task-done` を実行しないこと、`task-done` 以外はコミットしないこと、すべての作業が終わったあと一度だけレビューすること、を変えること
- `task-done` 以外のコミットを足すこと
- テスト節を親が実行する手順を変えること
- 要求ファイルと設計ファイルを書かない定めを変えること
- `skills/sdd-cur-quick/SKILL.md` と `skills/sdd-cur-fix/SKILL.md` の本文を変えること
- 完了処理に、正本をまとめ直す段を足すこと
- 要求どおりでないこと、設計通りでないこと、渡された終了コードが 0 以外であること、`## 変えるファイル`、受け入れ手順の網羅、という指摘を外すこと
- 実装スキルと三つの実装サブエージェントの frontmatter の `name`、`description`、`model`、`readonly` を変えること
- `src/196.test.ts` と `src/123.test.ts` に新しい `test` を足すこと
