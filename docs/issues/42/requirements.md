# 42 作業ブランチ名を返し設計前に今のブランチを確認する

対象は [Issue #42](https://github.com/paterapatera/sdd-cur/issues/42)。作業ブランチの名前を sdd-cur の要件と設計の手順が得られず、設計時に今のブランチを確かめない。

設計をデフォルトブランチへ書く事象が再発する。手順は `skills/sdd-cur/SKILL.md` の要件と設計である。

## 現状

要件の手順は、ブランチ名を `implementationBranch` の戻り値とする。`show` の JSON にブランチ名は無く、名前を返すサブコマンドも無い。関数の実体は `task-<番号>` である。設計の手順は、要求のときに用意したブランチへ書く、とだけあり、今のブランチがそれかを見て止まらない。

## 受け入れ条件

- `bun src/cli.ts branch <番号>` が、標準出力に `task-<番号>` の文字列だけを返す。末尾の改行のみ可である。
- sdd-cur の要件と設計の手順は、作業ブランチ名を、このサブコマンドの戻り値として得る。
- 要件と設計のどちらのファイルを書く手順でも、書く前に今のブランチを見る。今のブランチが、その戻り値でないときは、ファイルを書かない。

## 決定

作業ブランチ名を返すサブコマンドは `branch <番号>` である。`show` と同様に番号を引数に取る。

戻り値は、標準出力に `task-<番号>` の文字列だけを書く。末尾の改行のみ可である。

今のブランチが `task-<番号>` でないときは、要件・設計のどちらのファイルを書く手順でも同じ確認をし、ファイルを書かない。

## 作業ブランチ名

`branch <番号>` の戻り値は `task-<番号>` である。sdd-cur の要件と設計の手順は、作業ブランチ名を、この戻り値として得る。

ブランチ名の規則は変えない。

## 書く前

要件と設計のどちらのファイルを書く手順でも、書く前に今のブランチを見る。比べる名前は、`branch <番号>` が返す `task-<番号>` である。

今のブランチがそれでないときは、ファイルを書かない。

## 範囲外

次は、この要件に含めない。

- ブランチ名の規則の変更
- 実装ランナーの `fetch`
- クローン同士の同時実装（#8）
- 「実装中」でクローン同士を分けること（計画）
- 課題の作成とクローズ
- ラベルの変更
- 受け入れ手順
- 完了処理
- Forgejo、Jira、Backlog
