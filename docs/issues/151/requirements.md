# 151 処理開始前にローカルブランチを削除する

<!-- sdd-cur:form -->

対象は [Issue #151](https://github.com/paterapatera/sdd-cur/issues/151)。ランナーをずっと起動していると、ローカルに対応済みのブランチが大量に残る。毎回、処理の開始前に、ローカルブランチを削除する。

## 現状

`run` は、作業ディレクトリで `createGit` を作る（`src/cli.ts` の 356 行）。

`runLoop` は、仕事があるとき `処理を開始します: <id>` を書く（`src/run.ts` の 122 行）。そのあと `process` を呼ぶ（`src/run.ts` の 125 行）。

`runLoop` は、仕事が無いとき、間隔を待ってから次の `poll` へ進む（`src/run.ts` の 150 行）。

`logError` へ渡した一行は、標準エラーへ書く（`src/cli.ts` の 375 行）。

`process` は、「実装依頼」があり「実装中」が無いとき、実装へ進む（`src/runner.ts` の 618 行）。`issueHasFixLabels` が真のとき、修正へ進む（`src/runner.ts` の 623 行）。quick の対象のとき、quick へ進む（`src/runner.ts` の 634 行）。「動作確認OK」があるとき、完了処理へ進む（`src/runner.ts` の 639 行）。

作業ブランチの名前は `task-<番号>` である（`src/runner.ts` の 297 行）。

実装は `checkoutFetched` で作業ブランチを取り込む（`src/runner.ts` の 892 行）。quick は `checkoutFetched` で作業ブランチを取り込む（`src/runner.ts` の 675 行）。修正は `checkoutFetched` で作業ブランチを取り込む（`src/runner.ts` の 1059 行）。完了処理は `checkoutFetched` で作業ブランチを取り込む（`src/complete.ts` の 131 行）。

`checkoutFetched` は `checkout -B` で `FETCH_HEAD` をそのブランチ名のローカルブランチにする（`src/git.ts` の 92 行）。この操作は、他のローカルブランチを削除しない。

`GitClient` が宣言する最後の操作は `push` である（`src/git.ts` の 23 行）。この型に、ローカルブランチを削除する操作は無い。

正本は、作業ツリーがリモートブランチを `fetch` し、その `FETCH_HEAD` をローカルブランチとして checkout する、と定める（`docs/canonical/runner.md` の 31 行）。

## 受け入れ条件

- 1. 条件: `runLoop` で `poll` が仕事を返した 主体: 課題ランナー 結果: `処理を開始します` を書く
- 2. 条件: `runLoop` で `poll` が仕事を返した 主体: 課題ランナー 結果: `process` を呼ぶ
- 3. 条件: `runLoop` で `poll` が仕事を返した。チェックアウト中のブランチが `task-` で始まり、未コミットの変更があるときを除く 主体: 課題ランナー 結果: `処理を開始します` を書くより前かつ `process` を呼ぶ直前に、名前が `task-` で始まるローカルブランチのすべてに対して削除を行う
- 4. 条件: `runLoop` で `poll` が仕事を返し、チェックアウト中のブランチが `task-` で始まり、未コミットの変更がある 主体: 課題ランナー 結果: 名前が `task-` で始まるローカルブランチは削除しない
- 5. 条件: `runLoop` で `poll` が仕事を返し、チェックアウト中のブランチが `task-` で始まり、未コミットの変更がある 主体: 課題ランナー 結果: 本処理を走らせない見送りを、`process` 内またはその入口の共通処理の即終了とする
- 6. 条件: 名前が `task-` で始まるローカルブランチの削除のいずれかが失敗した 主体: 課題ランナー 結果: エラーログを書く（`logError` へ渡す一行を標準エラーへ書く）
- 7. 条件: 名前が `task-` で始まるローカルブランチの削除のいずれかが失敗した 主体: 課題ランナー 結果: 本処理を走らせない見送りを、`process` 内またはその入口の共通処理の即終了とする
- 8. 条件: 名前が `task-` で始まるローカルブランチが無い 主体: 課題ランナー 結果: 削除の失敗にしない

## 決定

処理の開始前に、名前が `task-` で始まるローカルブランチをすべて削除する。チェックアウト中のブランチが `task-` で始まり、未コミットの変更があるときを除く。

名前が `task-` で始まるローカルブランチを削除するときは、その削除を `処理を開始します` を書くより前に行う。この時点は、`runLoop` が `process` を呼ぶ直前である。この削除は、`checkoutFetched` より前である。

`runLoop` で `poll` が仕事を返したら、未コミットの変更がある場合や名前が `task-` で始まるローカルブランチの削除が失敗した場合でも、`処理を開始します` を書き、必ず `process` を呼ぶ。本処理を走らせない見送りは、`process` 内（またはその入口の共通処理）で扱う。

チェックアウト中のブランチが `task-` で始まり、未コミットの変更があるときは、名前が `task-` で始まるローカルブランチの削除は行わない。`process` は呼ぶ。本処理は走らせない（`process` 内、またはその入口の共通処理で即終了する）。

名前が `task-` で始まるローカルブランチの削除のいずれかが失敗したときは、エラーログを書く。`process` は呼ぶ。本処理は走らせない（`process` 内、またはその入口の共通処理で即終了する）。

エラーログは、`logError` へ渡す一行である。この一行は標準エラーへ書く。

名前が `task-` で始まるローカルブランチが無いときは、削除の失敗にしない。
