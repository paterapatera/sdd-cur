# 173 実装を作業の一覧の一項目ずつコミットし、終わった作業を記録する

<!-- sdd-cur:form -->

対象は [Issue #173](https://github.com/paterapatera/sdd-cur/issues/173)。`sdd-cur-implement` は、作業の一覧の項目ごとに実装作成役を順に起動する。各作業が終わったら `task-done` でコミットし、`tasks` の `done` と `Sdd-Cur-Task` トレーラーで終わった作業を読む。課題ランナーは、作業用コミットだけが増えた agent では失敗せず、未コミットの変更が無く作業用コミットだけがあるときは `feat: 課題 <番号> を実装する` を作らない。

手を入れる対象は、`src/cli.ts`、`src/git.ts`、`src/runner.ts`、`skills/sdd-cur-implement/SKILL.md`、`docs/policy.md`、`AGENTS.md`、`docs/canonical/implement.md`、`docs/canonical/runner.md`、`docs/canonical/git.md`、`docs/canonical/sdd.md` である。

重なる課題は #6（課題ランナー）、#69（agent はブランチの先頭を動かさない）、#73（実装のコミットメッセージ）、#121（`tasks` の JSON）である。

## 範囲外

- 作業を起動する順を変えること
- 作業を同時に起動すること
- 作業ごとにレビューすること
- 作業ごとに修正すること
- スカッシュマージ以外で完了すること
- 作業ごとに push すること
- push の時期を変えること
- 不具合修正のコミットメッセージ `fix: 課題 <番号> の不具合を修正する` を変えること
- 不具合修正の agent のあとの `実装の変更がありません` の条件を変えること
- quick と不具合修正のスキルにある、ブランチの先頭を動かす操作をしない定めを変えること
- 実装作成役、実装レビュー役、実装修正役にコミットさせること

## 決定

| 項目 | 内容 |
|---|---|
| `task-done` の引数 | 課題番号と作業番号が二つ。`--help` と `-h` を除いた残りを数える。残りが二つでないときは、`cmdValidate` と同じく `printUsage` を書き、終了コード 1、標準出力は空 |
| 番号 | 課題番号と作業番号は、どちらも `parseIssueNumberString` が拒否するときは、標準エラーへ `番号が不正です` の一行、終了コード 1、標準出力は空 |
| 変更が無い | `hasChanges` が偽のとき、`task-done` は `git add` も `git commit` も呼ばず、終了コード 1、標準エラーは `作業の変更がありません` の一行、標準出力は空 |
| コミット | 変更があるときは `git add -A` のあとコミットし、終了コード 0。push しない。`gh` は起動しない |
| 件名 | `feat: 課題 <番号> 作業 <作業番号>`。`<番号>` は第一引数、`<作業番号>` は第二引数であり、十進で先頭の零は付けない |
| トレーラー | 行全体が `Sdd-Cur-Task: <作業番号>`。`<作業番号>` は第二引数を十進で先頭の零を付けずに書いたもの |
| メッセージの形 | 件名、空行、トレーラーの三行だけ。`git commit` は `-m` を三回使い、順に件名、空文字、トレーラーを渡す |
| `tasks` の `done` | 各作業の `number` に対し、作業ブランチ上だけにあるコミットのメッセージに、行全体が `Sdd-Cur-Task: <作業番号>` があるとき真。`<作業番号>` はその `number` を十進で先頭の零を付けずに書いたもの。別番号のトレーラーだけでは偽 |
| 作業ブランチ上だけ | `git rev-list` で、今の `HEAD` から届き、デフォルトブランチの先端から届かないコミット。先端は `refs/remotes/<remote>/<デフォルトブランチ>` が参照できるときそのコミット。参照できないときは `git ls-remote <remote> <デフォルトブランチ>` の先頭の SHA |
| デフォルトブランチ名 | `prepare-branch` と同じく、リモートが一つであるときその名前を `<remote>` とし、`git ls-remote --symref <remote> HEAD` の `ref: refs/heads/` 行から名前を取る。取れないときは `tasks` 全体が終了コード 1、標準エラーは `デフォルトブランチを特定できません` |
| リモートが一つでない | `task-done` は触れない。`tasks` は `done` 判定の前に、既存の `remoteName` と同じく `git remote` の空行を除いた名前が一つかを見る。一つでないときは `prepare-branch` と同じく、標準エラーへ `リモートを特定できません` と一行書き、終了コード 1、標準出力は空。`done` を判定しない |
| `HEAD` の確認 | before から届かず after から届くコミットが無いとき成功。あるときは、各コミットのメッセージに、行全体が `Sdd-Cur-Task: ` のあとに十進で先頭の零の無い 1 以上の整数が続く行が一つ以上あるときだけ成功。一つでも無いときは `agent がブランチの先頭を変えました` で失敗し、再試行に進まない |
| agent のあと | `hasChanges` が真なら従来どおり `feat: 課題 <番号> を実装する` で `commitAll`。偽で、作業用コミットが branch-only に一つ以上あるなら `実装の変更がありません` にせず、`feat` コミットは作らず push とマージリクエスト。偽で作業用コミットも無いなら `実装の変更がありません` |
| 実装スキル | 作成役の前に `tasks` を一度実行。`done` が真の作業は起動しない。作業ツリーを変えた作成役のあとだけ `task-done`。`task-done` 以外はコミットしない。`task-done` は先頭を進めてよい。レビューと修正の変更は `task-done` しない |
| サブコマンドの列挙 | `task-done` を `src/cli.ts` の `switch`、`docs/policy.md` の表、`AGENTS.md` の「コマンド」に足す。`tasks` の次に `task-done` の行を `printUsage` に足す |

`Sdd-Cur-Task` の行は、コミットメッセージを改行で分けた各行のうち、行全体が `Sdd-Cur-Task: ` のあとに十進で先頭の零の無い 1 以上の整数だけが続く行である。前後の空白は除いて比べない。

`tasks` の成功時 JSON は、`tasks` の各要素に `done` を足すだけであり、`number`、`line`、`refs` の意味と並びは変えない。キー順は `number`、`line`、`refs`、`done` である。

実装スキルは、最初の `tasks` のあと、同じ agent 起動の中で `task-done` に成功した作業の `done` を真として扱い、レビューに入る前にその一覧を更新する。ランナーが実装の agent を再試行するときは、実装スキルは改めて `tasks` を実行し、その JSON の `done` を使う。
