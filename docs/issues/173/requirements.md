# 173 実装を作業の一覧の一項目ずつコミットし、終わった作業を記録する

<!-- sdd-cur:form -->

対象は [Issue #173](https://github.com/paterapatera/sdd-cur/issues/173)。`sdd-cur-implement` は、作業の一覧の項目ごとに実装作成役を順に起動する。どの作業が終わったかは残らない。作業の一覧の一項目が終わるたびに、その作業のコミットを作り、どの作業が終わったかを git の履歴から読めるようにする。

重なる課題は #6（課題ランナー）である。

比べる相手は、Spec Kit の `tasks.md` と、cc-sdd の `spec-impl` である。前者は作業ごとのチェックボックスで終わった作業を残す。後者は作業の番号を指定して実装できる。

手を入れる対象は、`src/cli.ts`、`src/git.ts`、`src/runner.ts`、`skills/sdd-cur-implement/SKILL.md`、`docs/canonical/implement.md`、`docs/canonical/runner.md`、`docs/canonical/git.md` である。サブコマンド名の集合は、`src/cli.ts` の `switch` と、`docs/policy.md` の構成の表と、`AGENTS.md` の「コマンド」の例とで一致する（`src/docs.test.ts` の 112 行）。`task-done` を足すときは、この三か所の集合へその名前を入れる。

## 決定

`hasChanges` が偽のとき、`task-done` は何もせず失敗する。`git add` も `git commit` も実行しない。終了コードは 1 である。標準エラーは `作業の変更がありません` と一文字も違わない。標準出力には書かない。

`task-done` が作る作業のコミットメッセージは、一行目とトレーラー行だけである。一行目は `feat: 課題 <番号> 作業 <作業番号>` であり、受け入れ条件 10 と一文字も違わない。その直後は空行であり、その次の行がトレーラー行である。トレーラー行は `Sdd-Cur-Task: <作業番号>` であり、受け入れ条件 11 と一文字も違わない。一行目とトレーラー行のあいだに、空行以外の行は無い。トレーラー行より後ろに行は無い。

`tasks` が `done` を判定するときのデフォルトブランチ名は、`docs/canonical/git.md` と同じく、`git ls-remote --symref <remote> HEAD` の、`ref: refs/heads/` で始まる最初の行の、その接頭辞のあと空白の前までである。取れないときは、`tasks` 全体の終了コードは 1 であり、標準エラーは `デフォルトブランチを特定できません` と一文字も違わない。
