# 120 作業ブランチの用意を CLI のサブコマンドに移す

対象は [Issue #120](https://github.com/paterapatera/sdd-cur/issues/120)。SDD スキルが要件の前に行う作業ブランチの用意と、要件の前に行う今のブランチとの比較を、CLI のサブコマンド `prepare-branch` にする。設計の前に行う今のブランチとの比較は、checkout や作業ブランチの新規作成を行わず、`sdd-cur branch <番号>` の出力と現在ブランチの比較としてスキルに残す。スキルは、要求の前ではそのコマンドを実行し、終了コードが 0 以外なら止まるだけにする。

どの場合にどの git 操作をするかは、今のスキルの手順と同じである。git が失敗したときの文言も、今のスキルの手順と同じである。成功したとき、作業ブランチ名を一行出力する。

重なる課題は #91、#42、#96 である。

## 決定

サブコマンド名は `prepare-branch` である。

使い方の表示は `sdd-cur prepare-branch <番号>` である。

起動は `bun src/cli.ts prepare-branch <番号>` である。

今のブランチが作業ブランチ名と違うとき、標準エラーへ日本語の一行を書く。

その一行の字面は、設計で決める。

そのとき、用意で行った checkout は戻さない。

引数が課題番号一つでないとき、git は実行しない。

そのとき、終了コードは 1 である。

そのとき、標準出力には書かない。

引数が一つでないときは、使い方を標準エラーへ書く。

課題番号として読めないときは、標準エラーへ `番号が不正です` と一行書く。

引数が課題番号一つでないときの扱いは、`branch` と同じである。

要件の前は `prepare-branch` で用意と比較の両方を行う。

設計の前は比較のみ行う。checkout や作業ブランチの新規作成はしない。

設計の前に `prepare-branch` で用意と比較の両方を行うことは採用しない。

## 関係する課題

課題は、次を関係するとする。

- #42（作業ブランチ名を `branch` が返し、設計の前に今のブランチを見る）
- #91（レビューの分岐をコードへ移し、同じスキルを短くする）
- #96（新しい作業ブランチの起点と、課題ランナーの取り込み）

#42 は、作業ブランチ名を `branch <番号>` の標準出力とする。要件と設計のどちらでも、書く前に今のブランチがその名前であるかを見る。この要件は、その名前の規則を変えない。

#91 は、レビュー応答の分岐をコードへ移し、同じスキルのレビューの節を短くする。この要件は、その分岐を変えない。用意の節が同じスキルにあるので、#91 とは順に進める。

#96 は、作業ブランチを新しく作るときの起点を、リモートの最新のデフォルトブランチとする。課題ランナーは、実装の前と修正の前にデフォルトブランチを作業ブランチへマージし、完了処理はスカッシュマージの前に作業ブランチを push する。この要件は、新しく作るときの起点を、その定めのままにする。課題ランナーのマージと push は、この要件に含めない。

## 範囲外

次は、この要件に含めない。

- 用意の手順の中身を変えること
- このサブコマンドがマージすること
- このサブコマンドが rebase すること
- このサブコマンドが `git push` すること
- このサブコマンドが履歴を書き換えること
- 課題ランナーのブランチ操作
- レビューの分岐（#91）
- 作業ブランチ名の作り方を変えること
- `skills/sdd-cur/SKILL.md` 以外のスキルの本文を変えること
