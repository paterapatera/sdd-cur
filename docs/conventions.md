# 約束

スキルと課題ランナーが同じ規則を使う。判定の実装は `src/conventions.ts` にある。

## 課題ごとのファイル

課題番号を `<番号>` とする。十進で、先頭の零は付けない。

| ファイル | 内容 |
|---|---|
| `docs/specs/<番号>/requirements.md` | 要件 |
| `docs/specs/<番号>/design.md` | 設計 |

各ファイルの最初の非空行は、`# <番号> ` のあとに題が一つ以上ある見出しである。

## 課題コメントの種別

確認と回答は、課題のコメントだけに書く。要件、設計、コミットメッセージ、マージリクエストには書かない。

コメントの最初の非空行が、次の印と一文字も違わないとき、その種別になる。印の行の前後に空白があれば、種別は付かない。

| 種別 | 印 |
|---|---|
| お客さまへの確認 | `sdd-cur: 確認` |
| 人による回答 | `sdd-cur: 回答` |
| 受け入れ手順 | `sdd-cur: 受け入れ手順` |

印の行より後ろが本文である。確認と回答は、古いコメントから見て、未対応のうちいちばん古い確認に回答を一つ付ける。受け入れ手順は、同じ順の最後の一件を現在の手順とする。

未回答の確認があるあいだ、次の確認は投稿しない。

## 反映済みの回答

要件または設計へ取り込んだ回答は、そのファイル末尾に、取り込んだ回答コメントの `id` だけを記録する。確認文も回答文も書かない。

記録の例:

```
<!-- sdd-cur:reflected
IC_kwDOExample123
-->
```

## 未反映の回答

確認と組になった回答のうち、要件と設計のどちらの記録にも `id` が無いものが、まだ取り込んでいない回答である。
