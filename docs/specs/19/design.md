# 19 使いたくないプロジェクトではスキルを動かさない

対象は [Issue #19](https://github.com/paterapatera/sdd-cur/issues/19)。スキル `sdd-cur` が手順に入るのは、Cursor で `/sdd-cur` により明示して起動したときだけである。`/sdd-cur` で明示していない通常の依頼だけでは、どのプロジェクトでも手順に入らない。

重なる課題は #46 である。#46 が `sdd-cur` をコマンドで指定したと定めるのは、Cursor のチャットで、そのスキルを @ する、またはそのスキルのスキル呼び出しで明示して起動したときである。#46 は、そのスキルをコマンドで指定していないときは、このリポジトリ以外では手順に入らない、と定める。この課題が上書きする範囲は、スキル `sdd-cur` が手順に入る条件だけである。`sdd-cur-complete` が手順に入る条件は、設計 46 のままである。設計 46 のファイルは書き換えない。

## 受け入れ条件

- スキル `sdd-cur` が手順に入るのは、Cursor で `/sdd-cur` により明示して起動したときだけである。
- スキルを @ すること、およびスキル呼び出しで明示して起動することは、`sdd-cur` が手順に入る明示ではない。
- 「issue 7 の要件を作って」など、`/sdd-cur` で明示していない通常の依頼だけでは、`sdd-cur` は手順に入らない。
- 上の条件は、`sdd-cur` リポジトリ自身を含め、どのプロジェクトでも同じである。リポジトリによる出し分けはしない。
- `sdd-cur` リポジトリでも、`/sdd-cur` で明示していない通常の依頼だけでは、`sdd-cur` は手順に入らない。
- スキルを `~/.cursor/skills` に置いたときも、同じである。
- `/sdd-cur` で明示したときは、どのプロジェクトでも `sdd-cur` は手順に入る。

## スキル `sdd-cur`

`skills/sdd-cur/SKILL.md` のフロントマターは、現状のままである。`disable-model-invocation: true` は残す。`name` と `description` は変えない。

```yaml
---
name: sdd-cur
description: このプロジェクトの課題について、着手候補の提示、要件、設計、確認コメントの投稿、未反映の回答の取り込みを行う。着手、要件、設計、確認、回答の取り込みを依頼されたときに使う。課題の作成とクローズ、ラベルの変更、実装、受け入れ手順、完了処理はしない。
disable-model-invocation: true
---
```

`# sdd-cur` の直後、既存の導入段落の前に、次を置く。

```markdown
## 起動

手順に入るのは、Cursor で `/sdd-cur` により明示して起動したときだけである。そのときだけ、これより後ろの手順に進む。

スキルを @ すること、およびスキル呼び出しで明示して起動することは、手順に入る明示ではない。そのときは手順に入らない。

`/sdd-cur` で明示していない通常の依頼だけでは、手順に入らない。例は「issue 7 の要件を作って」である。

これは、`sdd-cur` リポジトリ自身を含め、どのプロジェクトでも同じである。リポジトリによる出し分けはしない。`sdd-cur` リポジトリであることを理由にした特別扱いはしない。

`/sdd-cur` で明示したときは、どのプロジェクトでも手順に入る。スキルを `~/.cursor/skills` に置いたときも、同じである。

手順に入らないときは、これより後ろを始めない。ファイルを変えず、サブエージェントも起動しない。
```

この節より後ろは変えない。既存の導入段落、`## 着手`、`## 要件`、`## 設計`、`## 確認`、`## 回答`、`## 禁止` は残す。

## テスト

`bun test` で実行する。一時ディレクトリを使い、終わったら消す。`gh` は起動しない。ホームディレクトリと、実行中の Cursor のスキルは触らない。

新しいテストファイルは作らない。`src/install.ts` のテストは変えない。`src/complete.test.ts` は変えない。`src/runner.test.ts` は変えない。

`src/sdd.test.ts` の `skills/sdd-cur/SKILL.md` は、先頭が上のフロントマターと一致したままである。必須文言の既存の一覧は残す。加えて、次が含まれる。いずれも `## 起動` の本文にある連続した文言である。

- `## 起動`
- `/sdd-cur`
- `により明示して起動したときだけである`
- `そのときだけ、これより後ろの手順に進む`
- `スキルを @ すること`
- `スキル呼び出しで明示して起動すること`
- `手順に入る明示ではない`
- `issue 7 の要件を作って`
- `リポジトリによる出し分けはしない`
- `リポジトリであることを理由にした特別扱いはしない`
- `どのプロジェクトでも手順に入る`
- `~/.cursor/skills`
- `これより後ろを始めない`

`## 起動` は、`# sdd-cur` より後ろ、`## 着手` より前にある。

install の検証は、既存の一時ディレクトリの試験のままである。期待の文は変えない。

- `src/sdd.test.ts` は、`bun src/cli.ts install <temp>` の終了コードが 0 であり、`<temp>/.cursor/skills/sdd-cur/SKILL.md` がパッケージのそのファイルと一致することを確かめる。

この一致が、足した `## 起動` もコピー先に含まれることを確かめる。ホームの `~/.cursor/skills` へコピーしたことの試験は足さない。

## 実装の順序

1. `skills/sdd-cur/SKILL.md` の `# sdd-cur` の直後に、この設計の `## 起動` を足す。フロントマターと、既存の導入段落以降は変えない。
2. `src/sdd.test.ts` の必須文言に、この設計の文言を足す。`## 起動` が `# sdd-cur` より後ろ、`## 着手` より前にあることを確かめる。フロントマターの先頭一致は変えない。
3. `bun test` が成功することを確かめる。install の既存試験は、コピーがパッケージ側と一致することで、足した `## 起動` がコピーされることを確かめる。
