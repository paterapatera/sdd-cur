# 95 課題ランナーの処理ごとに、かかった時間と agent の起動回数を出す

<!-- sdd-cur:form -->

対象は [Issue #95](https://github.com/paterapatera/sdd-cur/issues/95)。課題ランナーのログに、処理ごとのかかった時間と、Cursor `agent` を起動した回数を出す。

手を入れる対象は `src/run.ts`、`src/runner.ts`、`src/agent.ts` である。

重なる課題は #6、#1、#82 である。

## 受け入れ条件

- 1. 条件: `処理を開始します` を書いた処理が正常終了した 主体: 課題ランナー 結果: その処理にかかった時間と、その処理で起動した agent の種類ごとの回数を、既存の `処理を終了します` の行に足し、時間と回数のための別の行は足さない
- 2. 条件: 正常終了の行を書く 主体: 課題ランナー 結果: その行を標準出力に書く
- 3. 条件: 正常終了の行に時間と回数を足す 主体: 課題ランナー 結果: 足す時間と回数に処理の id を含めない
- 4. 条件: 正常終了の行の形 主体: 課題ランナー 結果: `処理を終了します: <id>` の末尾に空白一つと括弧を足した一行であり、括弧の中の先頭はかかった時間であり、開き括弧とかかった時間のあいだに空白は無く、閉じ括弧の直前に空白は無い
- 5. 条件: 1 回以上起動した種類がある 主体: 課題ランナー 結果: かかった時間の直後に空白一つを置き、`種類=回数` を書く。`=` の前後に空白は無い。種類が複数のとき、となりあう `種類=回数` のあいだは空白一つである。順は `quick`、`implement`、`fix` である
- 6. 条件: 起動した種類が無い 主体: 課題ランナー 結果: 括弧の中はかかった時間だけである
- 7. 条件: かかった時間が 2 分 15 秒で、`quick` が 1 回、`implement` が 2 回、`fix` が 0 回である 主体: 課題ランナー 結果: 正常終了の行は `処理を終了します: <id> (2m15s quick=1 implement=2)` である
- 8. 条件: `処理を開始します` を書いたあとで `process` が失敗した 主体: 課題ランナー 結果: 失敗の理由の日本語一行を、今どおり標準エラーに書く
- 9. 条件: `処理を開始します` を書いたあとで `process` が失敗した 主体: 課題ランナー 結果: その処理にかかった時間と、その処理で起動した agent の種類ごとの回数を、理由の一行の直後に、標準エラーの一行として、課題コメントの投稿より前に書く
- 10. 条件: 失敗のときの時間と回数の一行 主体: 課題ランナー 結果: 括弧だけであり、括弧の中は正常終了の括弧の中と同じ形であり、処理の id は含めない
- 11. 条件: かかった時間が 2 分 15 秒で、`quick` が 1 回、ほかの種類が 0 回である 主体: 課題ランナー 結果: 失敗の一行は `(2m15s quick=1)` である
- 12. 条件: 失敗の課題コメントを書く 主体: 課題ランナー 結果: 本文は失敗の理由の一行のままである
- 13. 条件: かかった時間を測る 主体: 課題ランナー 結果: `処理を開始します` を書いてから、正常終了では `処理を終了します` の行を書くまで、失敗では時間と回数の一行を書くまでである。課題コメントの投稿の待ちは含めない
- 14. 条件: かかった時間を表記する 主体: 課題ランナー 結果: 分と秒である。60 秒は 1 分へ繰り上げる。表記に使う秒は 0 以上 59 以下である。分が 60 以上のときは分を時間へ繰り上げず、単位は分と秒のままである
- 15. 条件: 分が 1 以上で秒が 1 以上である 主体: 課題ランナー 結果: 分の十進、`m`、秒の十進、`s` を空白を置かずにこの順で書く。2 分 15 秒は `2m15s` である。65 分 30 秒は `65m30s` である
- 16. 条件: 分が 0 で秒が 1 以上である 主体: 課題ランナー 結果: 秒の十進と `s` だけを書く。15 秒は `15s` である
- 17. 条件: 秒が 0 で分が 1 以上である 主体: 課題ランナー 結果: 分の十進と `m` だけを書く。2 分は `2m` である
- 18. 条件: 経過が 1 秒未満である 主体: 課題ランナー 結果: `0s` と書く
- 19. 条件: 1 秒以上の経過に 1 秒未満の端数がある 主体: 課題ランナー 結果: 端数を切り捨てる。四捨五入はしない。59.6 秒は `59s` である。59.9 秒は `59s` である
- 20. 条件: 分、秒、回数を十進で書く 主体: 課題ランナー 結果: 先頭の零を付けない
- 21. 条件: 種類と回数を書く 主体: 課題ランナー 結果: 種類は `quick`、`implement`、`fix` である。回数は、その処理の中でランナーがその種類の agent を起動した回数である。1 回以上起動した種類だけを書き、0 回の種類は書かない
- 22. 条件: 起動が失敗したあとに同じ起動をやり直した 主体: 課題ランナー 結果: やり直した起動も回数に含める
- 23. 条件: agent の中でサブエージェントが起動した、またはレビューが進んだ 主体: 課題ランナー 結果: その起動回数とレビュー回数を、種類の回数に含めない
- 24. 条件: かかった時間と回数の一行を残す 主体: 課題ランナー 結果: ファイルに書かない。GitHub に書かない
- 25. 条件: `poll` が失敗した 主体: 課題ランナー 結果: 時間と回数の一行を書かない
- 26. 条件: 失敗の時間と回数の一行を書いたあと、課題コメントの投稿が拒否された 主体: 課題ランナー 結果: 投稿の拒否の一行を、そのあとに標準エラーへ書く。終了コードは 1 である。次の `poll` は呼ばない

## ログ

`runLoop` は、`処理を開始します: ${item.id}` を `log` へ渡したあと、`now()` を一度呼ぶ。この開始の行の文言は変えない。

`process` が戻ったときは、終了の行を書く直前に `now()` を一度呼び、`agentLaunches()` を一度読む。`log` へ渡す文字列は、`処理を終了します: ${item.id}` の末尾に空白一つと、`formatProcessTiming` の戻り値を足したものである。`logError` は、この行のためには呼ばない。

`process` が拒否したときは、今の `errorLine` を先に `logError` へ渡す。続けて、時間と回数の行を書く直前に `now()` を一度呼び、`agentLaunches()` を一度読む。`formatProcessTiming` の戻り値だけを `logError` へ渡す。そのあと、今どおり `commentFailure` に仕事の `id` と理由の一行を渡す。時間と回数の文字列は渡さない。

投稿が拒否したときは、その理由の一行を `logError` へ渡し、終了コード 1 で戻る。時間と回数の行は、すでに書いてある。次の `poll` は呼ばない。`process` の失敗のあとも、今どおり終了コード 1 であり、次の `poll` は呼ばない。

`poll` が拒否したときは、今どおりその一行だけを `logError` へ渡して終了コード 1 で戻る。時間と回数の行は書かない。`commentFailure` は呼ばない。

`終了します` は、今の位置のままである。文言は変えない。

```ts
export function formatDurationMs(elapsedMs: number): string

export function formatProcessTiming(
  elapsedMs: number,
  counts: { quick: number; implement: number; fix: number },
): string
```

`formatProcessTiming` の戻り値は、開き括弧、かかった時間、1 回以上の種類があるときは空白一つと `種類=回数`、閉じ括弧である。失敗の標準エラーの一行は、この戻り値と一文字も違わない。正常終了の行は、`処理を終了します: <id>` と空白一つと、この戻り値である。

`RunLoopDeps` の `now` は `() => number` であり、省略できる。省略したときは `Date.now` を使う。

`Runner` に次を足す。

```ts
agentLaunches(): { quick: number; implement: number; fix: number }
```

`defaultRunner` と、`src/run.test.ts` の既存の仮ランナーは、三種類とも 0 を返す。新しい `test` は足さない。

## 時間

かかった時間は、二度の `now()` の差である。単位はミリ秒である。`seconds` は、この差を 1000 で割り、小数点以下を切り捨てた整数である。

`seconds` が 1 未満のときは `0s` である。それ以外は、`minutes` を `seconds` を 60 で割って小数点以下を切り捨てた整数とし、余りの秒を `seconds` を 60 で割った余りとする。余りが 0 のときは分の十進と `m` だけである。`minutes` が 0 のときは余りの十進と `s` だけである。どちらも 1 以上のときは、分の十進、`m`、余りの十進、`s` を、この順で空白を置かずに書く。分が 60 以上でも、時間の単位は足さない。十進は、その整数の十進であり、桁を零で埋めない。

ミリ秒と表記の対応は、次である。

| ミリ秒 | 表記 |
|---|---|
| 0 | `0s` |
| 999 | `0s` |
| 1000 | `1s` |
| 15000 | `15s` |
| 59600 | `59s` |
| 59900 | `59s` |
| 59999 | `59s` |
| 60000 | `1m` |
| 120000 | `2m` |
| 135000 | `2m15s` |
| 3930000 | `65m30s` |

59600 は 59.6 秒、59900 は 59.9 秒である。どちらも `59s` であり、`1m` ではない。

## 起動回数

回数を増やす場所は、`createAgent` が返す `quick`、`implement`、`fix` だけである。各メソッドは、引数の検査を終えたあと、`agent.run` を呼ぶ直前に、自分の種類を 1 増やす。検査で拒否したときは増やさない。`agent.run` が拒否したとき、終了コードが 0 以外のときも、増やした 1 は戻さない。標準出力と標準エラーは、回数のために読まない。

`createAgent` の戻り値に次を足す。

```ts
export type AgentLaunchCounts = {
  quick: number
  implement: number
  fix: number
}

launchCounts(): AgentLaunchCounts
resetLaunchCounts(): void
```

`resetLaunchCounts` は三種類を 0 にする。`launchCounts` は、その時点の三種類を返す。

`RunnerDeps` の `agent` は、この二つを省略できる。`createRunner` の `process` は、最初の文で、`resetLaunchCounts` があるときだけそれを呼ぶ。処理の途中では戻さない。返すランナーの `agentLaunches` は、`launchCounts` があるときはそれを呼び、無いときは三種類とも 0 を返す。`src/cli.ts` は、今どおり `createAgent` の戻り値を渡す。戻り値にメソッドが増えても、`src/cli.ts` の字面は変えない。

`runAgentWithHeadCheck` と、quick がそれをもう一度呼ぶ分岐は、回数を自分では増やさない。どちらも `agent` のメソッドを呼ぶ。メソッドが `agent.run` に達した回数だけが増える。先頭が変わったためにやり直しが無いときは、呼ばれなかった起動は増えない。

quick が、起動の失敗を `process` の拒否にせずに戻る既存の経路は残す。その戻りは正常終了であり、そこまでの起動は終了の行に書く。

種類が 0 の欄は、括弧の中に書かない。書く順は、起動した順ではなく、`quick`、`implement`、`fix` である。

## テスト

`bun test` で実行する。`gh`、`git`、`agent` は起動しない。ホームディレクトリと、実行中の Cursor のスキルは触らない。ファイルを作るときは一時ディレクトリを使い、終わったら消す。新しい `test` は `src/95.test.ts` だけに足す。既存の `src/*.test.ts` に、新しい `test` は足さない。

`src/run.test.ts` の既存の仮ランナーは、`agentLaunches` が三種類とも 0 を返す。失敗を `logError` の配列で見ている二つの `test` は、`now` が常に 0 を返す。`process failed` の一つは、配列が `process failed`、`(0s)` の順である。投稿が拒否される一つは、配列が `process failed`、`(0s)`、`comment rejected` の順である。コメントへ渡す文字列は、理由の一行のままである。ほかの期待は変えない。

- `formatDurationMs` は、上の表のミリ秒を、その表記にする。59900 は `59s` である。[14][15][16][17][18][19][20]
- `formatProcessTiming` は、135000 と `quick` 1、`implement` 2、`fix` 0 で `(2m15s quick=1 implement=2)` を返す。135000 で三種類が 1 のときは `(2m15s quick=1 implement=1 fix=1)` である。`=` の前後に空白は無い。三種類が 0 の 135000 は `(2m15s)` である。`quick` だけ 1 の 135000 は `(2m15s quick=1)` である。[5][6][10][11]
- `runLoop` の正常終了は、`now` が 1000 の次に 136000 を返し、`agentLaunches` が `quick` 1、`implement` 2、`fix` 0 のとき、標準出力が `処理を開始します: 42`、`処理を終了します: 42 (2m15s quick=1 implement=2)` の順の二行である。この終了の行は一行であり、`logError` は呼ばない。[1][2][3][4][7]
- `process` が `Error` の `理由` で拒否し、`now` が 0 の次に 135000 を返し、`quick` が 1 でほかが 0 のとき、`logError` は `理由`、`(2m15s quick=1)` の順である。`commentFailure` は、この二行のあとであり、渡す文字列は `理由` だけである。終了コードは 1 であり、`poll` は一回である。[8][9][10][11][12][24]
- `now` が 0、15000、そのあと 999999 を返すとき、失敗の括弧行は `(15s)` である。`commentFailure` の中で `now` を呼んでも、すでに書いた括弧行は変わらない。[13]
- 投稿が拒否されたときは、`logError` が理由、括弧行、投稿の拒否の順であり、終了コードは 1 であり、`poll` は一回である。[26]
- `poll` が拒否したときは、`logError` はその理由の一行だけであり、括弧行は無く、`commentFailure` は呼ばない。[25]
- `createAgent` は、番号が不正な `implement` では `agent.run` を呼ばず、回数は 0 のままである。`agent.run` が拒否したとき、終了コードが 0 以外のとき、終了コードが 0 のときは、いずれもその種類が 1 である。標準出力に `レビュー` が何度あっても `implement` は 1 である。`resetLaunchCounts` のあとは三種類とも 0 である。[21][23]
- 本文が `quick 対象` でラベルが無く、続けると決まった課題で、`createAgent` を agent にして `process` を走らせる。注入した `AgentRunner.run` が毎回拒否し、`headCommit` が同じ SHA を返すとき、`process` は拒否せず、`agentLaunches().quick` は 4 であり、`implement` と `fix` は 0 である。同じ agent で `implement` を一度成功させたあと、`getIssue` が状態 `closed` でラベルが無い課題を返す `process` は、回数を三種類とも 0 に戻す。[22][21]
