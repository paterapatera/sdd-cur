# 82 失敗した課題に理由を残し、人が着手前のラベルへ戻せるようにする

対象は [Issue #82](https://github.com/paterapatera/sdd-cur/issues/82)。課題ランナーの処理が失敗すると、ランナーは止まり、課題は「実装中」のまま残る。失敗の理由は課題に残らない。理由を課題に残し、人が着手前のラベルへ戻せるようにする。

人はランナーの端末を見ないと失敗に気づかない。「実装中」の課題はどのクローンの探索にも入らないので、そのまま放置される。

## 現状

`runLoop` は、`process` の失敗を標準エラーに一行書き、終了コード 1 で終わる。

`process` が失敗した課題のラベルは「実装中」のままである。課題にもマージリクエストにも、失敗の理由は書かない。

「実装中」を外して着手前のラベルに戻すコマンドは無い。人は GitHub の画面でラベルを直す。

`src/cli.ts` のサブコマンドは、`install`、`run`、`labels`、`candidates`、`show`、`branch`、`confirm`、`close`、`reflect`、`complete` である。

## 受け入れ条件

- `process` が失敗したとき、ランナーは失敗の理由の日本語一行を標準エラーに書く。
- 同じ一行を、その課題に普通のコメントとして書く。
- マージリクエストには、失敗の理由を書かない。
- そのコメントに印は付けない。確認、回答、受け入れ手順の印は使わない。
- 失敗した課題のラベルは変えない。どうするかは人が決める。
- 失敗の理由を課題に書いたあと、ランナーは終了コード 1 で止まる。
- ランナーは、次の課題へ進まない。
- 人は、CLI の一つのサブコマンドで、その課題から「実装中」を外せる。
- そのサブコマンドは、課題番号を引数に取る。
- そのサブコマンドで、その課題を着手前のラベルに戻せる。
- そのサブコマンド名は `restore` である。
- 使い方は `bun src/cli.ts restore <番号>` である。
- 着手前のラベルの決め方は、設計で決める。この要件では決めない。
- このコマンドは、ランナーを呼ばない。
- このコマンドは、スキルを呼ばない。

## 決定

「実装中」を外して着手前のラベルに戻す CLI のサブコマンド名は `restore` である。

使い方は `bun src/cli.ts restore <番号>` である。`<番号>` は課題番号である。

## 範囲外

次は、この要件に含めない。

- 失敗した課題を自動で再試行すること
- 失敗したあと、ランナーが止まらずに次の課題へ進むこと
- 着手の排他（#81）
