# 96 スカッシュマージでコンフリクトしないよう、作業ブランチを最新のデフォルトブランチに追従させる

対象は [Issue #96](https://github.com/paterapatera/sdd-cur/issues/96)。作業ブランチをリモートの最新のデフォルトブランチに追従させ、取り込みのコンフリクトで課題ランナーが止まらないようにする。

#27 は、要求と設計を作業ブランチに載せたまま実装し、実装着手時にデフォルトブランチから作業ブランチを作り直さない。この要件は、その定めを変えない。デフォルトブランチから作業ブランチを作り直さない。リモートの最新のデフォルトブランチを作業ブランチへ取り込む。

#7 の完了処理は、マージリクエストのスカッシュマージと「マージ済み」を行う。#18 は、そのスカッシュマージのときにブランチを削除する。この要件は、そのスカッシュマージの前に、リモートの最新のデフォルトブランチを作業ブランチへマージすることを足す。そのスカッシュマージの前に、作業ブランチを push することを足す。

## 現状

作業ブランチは、SDD スキルが要件を書き始めるときに用意する。どこから作るかは決まっていない。Project A の手元のブランチが古ければ、古い状態から作られる。

実装の着手では、push 済みの作業ブランチを `fetch` し、`checkout -B <ブランチ> FETCH_HEAD` する。デフォルトブランチは取り込まない。設計 27 は、デフォルトブランチから作業ブランチを作り直さないと決めている。

修正の着手も同じで、デフォルトブランチは取り込まない。

完了処理は `gh pr merge --squash --delete-branch` を呼ぶ。その前にデフォルトブランチを取り込まない。課題ランナーの完了処理と `complete` は、同じ完了処理を呼ぶ。

要件、設計、実装、受け入れテストのあいだ、作業ブランチは古いままである。そのあいだに、ほかの課題が同じファイルを変えてマージされる。

スカッシュマージがコンフリクトで失敗すると、`completeIssue` は例外で終わり、`runLoop` は終了コード 1 でランナーを止める。課題は「動作確認OK」のまま残る。ランナーを起動し直すと、ほかに処理する課題が無いとき、同じ課題で再び止まる。

## 受け入れ条件

- SDD スキルが作業ブランチを新しく作るとき、その起点はリモートの最新のデフォルトブランチである。
- 既にある作業ブランチを、デフォルトブランチから作り直さない。
- 課題ランナーは、実装の agent を起動する前に、リモートの最新のデフォルトブランチを作業ブランチへマージする。
- 課題ランナーは、修正の agent を起動する前に、リモートの最新のデフォルトブランチを作業ブランチへマージする。
- 完了処理は、スカッシュマージの前に、リモートの最新のデフォルトブランチを作業ブランチへマージする。
- 完了処理は、スカッシュマージの前に、作業ブランチを push する。
- 課題ランナーの完了処理と `complete` の両方で、このマージと push は同じである。
- 取り込みでコンフリクトしたときは、マージを取り消す。
- 取り込みでコンフリクトしたときは、作業ブランチを変えない。
- 取り込みでコンフリクトしたときは、push しない。
- 取り込みでコンフリクトし、マージリクエストが無いときは、課題コメントにコンフリクトしたファイルの一覧を書く。
- 取り込みでコンフリクトし、開いているマージリクエストがあるときは、そのマージリクエストの会話にコンフリクトしたファイルの一覧を書く。
- 取り込みでコンフリクトしても、課題ランナーは止まらない。
- 取り込みでコンフリクトした課題を、次の `poll` で繰り返し取らない。
- コンフリクトしたときの課題のラベルは、設計で決める。
- 取り込みは、作業ブランチの履歴を書き換えない。
- 取り込みで rebase はしない。
- 取り込みで force push はしない。

## 決定

取り込みでコンフリクトしたときのファイル一覧のコメント先は、次のとおりである。マージリクエストが無いときは、課題コメントに、コンフリクトしたファイルの一覧を書く。開いているマージリクエストがあるときは、そのマージリクエストの会話に、コンフリクトしたファイルの一覧を書く。

## 作業ブランチを作る

SDD スキルが作業ブランチを新しく作るとき、リモートの最新のデフォルトブランチから作る。用意は、要件を書き始める作業の中で行う。実装のランナーは、この用意をしない。

既にある作業ブランチは、デフォルトブランチから作り直さない。

## 取り込み

課題ランナーは、実装の agent を起動する前に、リモートの最新のデフォルトブランチを作業ブランチへマージする。修正の agent を起動する前も、同じである。

完了処理は、スカッシュマージの前に、リモートの最新のデフォルトブランチを作業ブランチへマージする。完了処理は、スカッシュマージの前に、作業ブランチを push する。課題ランナーが「動作確認OK」を見て行う完了処理と、`complete` から呼ぶ完了処理は、同じである。

取り込みは、作業ブランチの履歴を書き換えない。取り込みで rebase はしない。取り込みで force push はしない。

## コンフリクト

取り込みでコンフリクトしたときは、マージを取り消す。作業ブランチは変えない。push しない。

マージリクエストが無いときは、課題コメントに、コンフリクトしたファイルの一覧を書く。開いているマージリクエストがあるときは、そのマージリクエストの会話に、コンフリクトしたファイルの一覧を書く。

コンフリクトしても、課題ランナーは止まらない。同じ課題を次の `poll` で繰り返し取らない。そのときの課題のラベルは、設計で決める。

## 範囲外

次は、この要件に含めない。

- コンフリクトの自動解消
- 取り込んだあとに、テストや受け入れテストをやり直すこと
- 設計 27 の「デフォルトブランチから作業ブランチを作り直さない」を変えること
- 同時に進む課題がコンフリクトしにくいファイルの書き方（#97）
- 失敗した課題に理由を残すこと（#82）
- 「マージ済み」を付けること（#7）
- マージしたブランチの削除（#18）
- すでにマージ済みのマージリクエストを、もう一度スカッシュマージしないこと（#7）
- 「動作確認OK」を付けること。付けるのは人である
- 課題の作成とクローズ
- 受け入れ手順
- 確認と回答
- Forgejo、Jira、Backlog
