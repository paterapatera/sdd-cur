# 86 今のシステム全体を表す仕様の正本を作り、課題の差分を実装の PR で反映する

対象は [Issue #86](https://github.com/paterapatera/sdd-cur/issues/86)。課題ごとの `docs/specs/<番号>/` とは別に、今のシステムの挙動を表す仕様の正本を置く。課題の設計には正本への差分を書き、実装のマージリクエストで正本へ反映する。

仕様は課題ごとに積み上がるだけで、今の挙動を一か所で読めない。要求と設計のレビュー役は、食い違いと巻き戻りを探すため、`docs/specs/` にある既存の要件と設計を毎回読む。

手を入れる対象は、`docs/conventions.md`、正本の置き場所、設計の作成役とレビュー役、実装の作成役とレビュー役、`skills/sdd-cur-implement/SKILL.md`、#85 の検査である。

#7 の完了処理は、マージリクエストのスカッシュマージと「マージ済み」の付与を行う。この要件は、そのスカッシュマージより前に、実装のマージリクエストへ正本の変更を入れる。

重なる課題は #85 と #7（完了処理）である。

## 現状

`docs/conventions.md` が定める仕様の置き場所は、`docs/specs/<番号>/requirements.md` と `design.md` だけである。正本は無い。

`agents/sdd-cur-req-reviewer.md` と `agents/sdd-cur-design-reviewer.md` の起動時は、`docs/specs/` にある既存の `requirements.md` と `design.md` を読んで比べる。

完了処理は、マージリクエストのスカッシュマージと「マージ済み」の付与を行う。仕様をまとめ直す段は無い。

実装の作成役が書いてよいのは、作業ツリーの実装だけである。要求ファイルと設計ファイルは変えない。課題の設計に、正本への差分の節は無い。

## 受け入れ条件

- 課題ごとの `docs/specs/<番号>/` とは別に、今のシステムの挙動を表す仕様の正本を置く。
- 正本は、領域ごとのファイルに分かれる。
- 正本の各要求は、変わらない識別子を持つ。
- 正本の置き場所と、要求の識別子の形は、設計で決める。この要件では決めない。
- `docs/conventions.md` は、課題ごとの要件と設計の置き場所に加え、設計が決めた正本の置き場所を定める。
- 課題ごとの `docs/specs/<番号>/requirements.md` と `design.md` の置き場所は、今どおり `docs/conventions.md` が定める。
- 設計の作成役が書く課題の設計には、正本への差分の節がある。
- 差分は、識別子ごとの追加、変更、削除である。
- 追加は、正本に無い識別子の要求を正本へ足す。
- 変更は、正本にある識別子の要求を変える。
- 変更では、識別子を変えない。
- 削除は、正本にある識別子の要求を正本から除く。
- 実装の作成役は、コードと同じ作業ツリーで、その差分を正本へ反映する。
- 正本の変更は、その実装のマージリクエストに入る。
- スカッシュマージのあと、main の正本とコードは一致する。
- 実装レビュー役は、正本が、その課題の設計にある差分どおりに変わったかを見る。
- #85 の検査は、追加する識別子が正本にまだ無いことを見る。
- #85 の検査は、変更する識別子と削除する識別子が正本にあることを見る。
- 設計のレビュー役は、正本への差分の節の各項目が、識別子付きの追加、変更、削除のいずれかとして書かれていることを見る。
- 設計のレビュー役は、変更と削除の項目に、その識別子の要求の内容が含まれていることを見る。
- 設計のレビュー役は、差分だけで、何が変わるかが読めることを見る。
- 識別子が当時の正本に対して追加、変更、削除のどれに該当するかの機械確認は、#85 の検査が行う。
- 設計のレビュー役は、#85 の検査を通った前提で、差分が課題の受け入れ条件と矛盾しないことを見る。
- 設計のレビュー役は、#85 の検査を通った前提で、他の課題の `docs/specs/` との食い違いと巻き戻しを、従来どおり見る。
- 設計のレビュー役は、マージ後の正本が差分どおりかを見ない。
- 正本が、その課題の設計にある差分どおりに変わったかを見るのは、実装レビュー役の受け入れ条件のままである。

## 決定

設計のレビュー役は、正本への差分の節の各項目が、識別子付きの追加、変更、削除のいずれかとして書かれていることを見る。変更と削除の項目には、その識別子の要求の内容が含まれる。差分だけで、何が変わるかが読める。

識別子が当時の正本に対して追加、変更、削除のどれに該当するかの機械確認は、#85 の検査が行う。設計のレビュー役は、#85 の検査を通った前提で、差分が課題の受け入れ条件と矛盾しないことを見る。他の課題の `docs/specs/` との食い違いと巻き戻しは、従来どおり見る。

設計のレビュー役は、マージ後の正本が差分どおりかを見ない。
正本が、その課題の設計にある差分どおりに変わったかを見るのは、実装レビュー役の受け入れ条件のままである。

マージ後の正本が差分どおりかを、設計のレビュー役が見ることは採用しない。

## 決め方

正本の置き場所と、要求の識別子の形は、この要件では決めない。設計が決める。
