# 27 要求と設計が main に入り実装ブランチへ載せ直している

対象は [Issue #27](https://github.com/paterapatera/sdd-cur/issues/27)。要求と設計をデフォルトブランチへ入れず、課題の作業ブランチに載せたまま実装する。

課題が言う main は、リモートのデフォルトブランチである。

## 受け入れ条件

- 要求を書き始めるとき、作業ブランチがあり、Project A の作業ツリーはそのブランチである。
- 要求と設計は、その作業ブランチに書く。デフォルトブランチには書かない。
- 人は、要求と設計を含む作業ブランチを push してから「実装依頼」を付ける。
- クローンの実装は、push 済みのその作業ブランチの上で行う。
- 実装着手時に、リモートのデフォルトブランチから作業ブランチを作り直さない。要求と設計の差分を、そこへ載せ直さない。

## 要求と設計

要求を書き始めるとき、作業ブランチを用意する。用意は、要求を書き始める作業の中で行う。実装のランナーは、この用意をしない。

用意したとき、Project A の作業ツリーは、その作業ブランチである。要求ファイルと設計ファイルは、この作業ツリーに書く。

設計は、要求のときに用意した同じ作業ブランチで書く。設計のために、デフォルトブランチから作業ブランチを作り直さない。

push は人が行う。push するのは、要求と設計を含む作業ブランチである。

## 実装

人が作業ブランチを push し、「実装依頼」を付けてから、クローンが実装する。

クローンは、push 済みの作業ブランチを取得し、その上で実装する。要求と設計は、そのブランチに既にある。デフォルトブランチから切り直したブランチへ、要求と設計を載せ直すことはしない。

## 範囲外

次は、この要件に含めない。

- 要求や設計の時点でマージリクエストを作ること
- 要求と設計をチェリーピックで移すこと
- push。行うのは人である
- 「実装依頼」を付けること。付けるのは人である
- ラベルの変更
- 課題の作成とクローズ
- 受け入れ手順
- 完了処理
- ブランチの削除（#18）
- Forgejo、Jira、Backlog
