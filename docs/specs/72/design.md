# 72 人が依頼した課題を作るスキルを作る

対象は [Issue #72](https://github.com/paterapatera/sdd-cur/issues/72)。人が Cursor で依頼したときだけ、GitHub の課題を作るスキルを作る。

要求の決定どおり、スキルは `skills/sdd-cur-create-issue/SKILL.md` である。人が内容を渡してこのスキルを明示して起動し、起動時の作業ツリーが git リポジトリであり、渡した内容から題を決められるとき、そのリポジトリに課題を 1 件作る。題は、渡した内容をもとに、このスキルを実行するエージェントが決める。人は題を指定しない。課題の本文は、人が渡した内容である。作った課題は閉じない。

## 受け入れ条件

- 本課題で作るスキルは、`skills/sdd-cur-create-issue/SKILL.md` である。
- 人が内容を渡して `sdd-cur-create-issue` を明示して起動し、起動時の作業ツリーが git リポジトリであり、渡した内容から題を決められるとき、作られる GitHub の課題は 1 件である。
- その課題の題は、人が渡した内容をもとに、このスキルを実行するエージェントが決めた題である。人は題を指定しない。
- その課題の内容は、人が渡した内容である。
- その課題を作るリポジトリは、スキル起動時の作業ツリーの git リポジトリである。`gh` のカレントディレクトリのリポジトリと同じである。
- 課題を作ったあとは、作った課題の番号と URL をチャットで人に伝える。
- スキル起動時の作業ツリーが git リポジトリでないときは、課題を作らない。
- スキル起動時の作業ツリーが git リポジトリでないときは、git リポジトリでない旨を伝える。
- スキル起動時の作業ツリーが git リポジトリでないときは、止まる。
- 内容が欠けている起動では、課題を作らない。
- 内容が欠けている起動では、不足を伝える。
- 内容が欠けている起動では、止まる。
- 渡した内容がスペースと改行だけである起動は、内容が欠けている起動である。課題を作らない。不足を伝える。止まる。
- 渡した内容から題を決められないときは、課題を作らない。
- 渡した内容から題を決められないときは、題を決められない旨を伝える。
- 渡した内容から題を決められないときは、止まる。
- 課題を作るのは、`sdd-cur-create-issue` を明示して起動し、内容を渡したときだけである。
- 依頼が無いとき、本課題で作るスキルは課題を作らない。
- 課題ランナーは、課題を作らない。
- 本課題で作るスキルが作った課題は、閉じない。
- `sdd-cur` は、課題を作らない。
- `sdd-cur-implement` は、課題を作らない。
- `sdd-cur-quick` は、課題を作らない。
- `sdd-cur-fix` は、課題を作らない。
- `sdd-cur-complete` は、課題を作らない。

- 既存の課題との重複を調べること
- 課題コメントの投稿。ラベルの変更。受け入れ手順。確認コメント。完了処理

## スキル

`skills/sdd-cur-create-issue/SKILL.md` を新しく作る。人が Cursor のチャットで明示して起動する。課題ランナーは起動しない。`install` は、直下のディレクトリをコピーする今の手順のまま、このスキルもコピーする。`src/install.ts` は変えない。

フロントマターは、次である。

```yaml
---
name: sdd-cur-create-issue
description: 人が内容を渡して明示して起動したときだけ、起動時の作業ツリーの git リポジトリに GitHub の課題を 1 件作る。作った課題は閉じない。
disable-model-invocation: true
---
```

本文の最初の見出しは `# sdd-cur-create-issue` である。そのあとに `## 作成` と `## 禁止` を、この順で置く。

人が渡した内容は、作る課題の本文である。

`## 作成` では、次を行う。

課題を作るのは、次をすべて満たすときだけである。

- 本スキルを明示して起動している
- 人が内容を渡している
- 起動時の作業ツリーが git リポジトリである
- 渡した内容から題を決められる

人が内容を渡していない起動は、内容が欠けている。渡した内容がスペースと改行だけである起動も、内容が欠けている。内容が欠けているときは、課題を作らない。不足を伝える。止まる。`gh issue create` は実行しない。

起動時の作業ツリーが git リポジトリでないときは、課題を作る前にそれを見る。課題を作らない。git リポジトリでない旨を伝える。止まる。`gh issue create` は実行しない。

スペースと改行以外の文字を含む内容が渡されていて、作業ツリーが git リポジトリであっても、渡した内容から題を決められないときは、課題を作らない。題を決められない旨を伝える。止まる。`gh issue create` は実行しない。題は、渡した内容をもとに、このスキルを実行するエージェントが決める。人は題を指定しない。題を人に尋ねない。内容の全体が本文であり、内容を題と本文に分けない。

四つを満たすとき、カレントディレクトリを起動時の作業ツリーのままにして、`gh issue create` を 1 回実行する。内容が複数の話題でも、作る課題は 1 件である。`--repo` は付けない。題は、エージェントが決めた題である。本文は、人が渡した内容そのものである。書き換えない。要約しない。ラベル、担当者、マイルストーンは付けない。対話の編集はしない。認証は `gh` のログインに任せる。トークンも環境変数も読まない。

この実行で課題が 1 件できたとき、その番号と URL をチャットで人に伝える。伝えたあとは止まる。課題を閉じない。

依頼が無いときは、課題を作らない。明示して起動していないとき、内容を渡していないとき、および渡した内容がスペースと改行だけであるときは、作らない。

`## 禁止` には、次を書く。

作った課題は閉じない。閉じる操作はしない。依頼が無いときは課題を作らない。コメントを投稿しない。ラベルを変えない。コミットしない。push しない。マージリクエストを作らない。作業ツリーのファイルを変えない。サブエージェントを起動しない。`bun src/cli.ts` では課題を作らない。

スキルファイルには、`gh` を直接起動しない、を書かない。`issue close` を書かない。
