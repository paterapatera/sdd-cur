# 122 正本の重複と壊れた文を見つける検査を足す

<!-- sdd-cur:form -->

対象は [Issue #122](https://github.com/paterapatera/sdd-cur/issues/122)。`docs/spec/` 全体を検査するサブコマンド `spec-check` を足す。同じファイルの中で本文が近い要求、壊れた文末、空の本文、識別子の重複を見つける。

手を入れる対象は `src/cli.ts` と、新しい `src/spec.ts` である。検査の関数は `src/spec.ts` に置く。

重なる課題は #85、#86、#87 である。

## 受け入れ条件

- 1. 条件: 引数なしでサブコマンドを起動する 主体: 利用者 結果: サブコマンド名は `spec-check` であり、起動は `bun src/cli.ts spec-check` である
- 2. 条件: 使い方を表示する 主体: `printUsage` 結果: 標準エラーに、行全体が `sdd-cur spec-check` である行がある

- 4. 条件: 作業ディレクトリに `docs/spec/` が無い 主体: `spec-check` 結果: 終了コードは 0 である。標準出力は空である。標準エラーは空である
- 5. 条件: `docs/spec/` があり、読み取りに失敗した 主体: `spec-check` 結果: 終了コードは 1 である。標準エラーは `正本を読めません` の一行である。標準出力は空である。見つけたものの行は書かない

- 11. 条件: 要求の本文に空白以外の文字が無い 主体: `spec-check` 結果: その要求を一件として標準エラーへ書く。由来の行だけがある要求は、空にしない

- 14. 条件: 見つけたものが一件以上ある 主体: `spec-check` 結果: 終了コードは 1 である。見つけたものの行は標準出力には書かない

- 16. 条件: 種類が違う見つけたものがある 主体: `spec-check` 結果: 種類ごとに別の一行であり、標準エラーの順は識別子の重複、空の本文、壊れた文末、近い組である

| 項目 | 内容 |
|---|---|

| 置き場所 | 検査は `src/spec.ts` の `checkSpec`。`src/cli.ts` はそれを呼ぶ。`src/conventions.ts` は変えない |
| 引数 | サブコマンド名のうしろは、一つも受け取らない。`--help` と `-h` も引数である。最初の引数が `spec-check` のとき、`main` の先頭の使い方表示には入らない |
| 引数があるとき | 標準エラーは `引数は受け取れません`。終了コードは 1。標準出力は空。検査しない |
| 対象 | 作業ディレクトリの `docs/spec/` 直下の、ファイルであり、名前が `.md` で終わるもの。サブディレクトリは見ない。ファイル名の昇順は、符号単位の昇順である |
| ディレクトリが無い | `docs/spec` の読み取りが `ENOENT` のときは、見つけたものが無いときと同じである。終了コードは 0。標準出力も標準エラーも空 |
| 読み取りの失敗 | `ENOENT` 以外の失敗、および一覧のあとでファイルを読めないときは、`正本を読めません` の一行だけを書いて終了コード 1。見つけたものの行は書かない |
| 近さ | 由来の行を除いた本文の、隣り合う二つの符号位置の 2-gram の集合。Jaccard 係数が 5 分の 3 以上の組を近いとする。和集合が 0 の組は近くない |
| しきい値の根拠 | 今の正本で、同じ内容として挙げた段落どうしの組は 5 分の 3 以上であった。分割した箇条は未満であった。表は下 |
| 壊れた文末 | 下の「壊れた文末」の候補から、フェンスの中と、`こうである`、`そうである`、`どうである` で終わる行を除く |
| 空の本文 | 見出しの次から次の見出しの前まで（またはファイルの末尾まで）に、空白以外の文字が無いこと。由来の行は残したまま見る |
| 識別子の重複 | 同じ `## REQ-<番号>` が直下の `.md` に二度以上。識別子ごとに一件。三回以上でも一件 |
| 出力 | 見つけたもの一件につき標準エラーへ一行。標準出力へは書かない。一件以上で終了コード 1。一件も無いときは 0 |
| 使い方の行 | `printUsage` の最後に `sdd-cur spec-check` を足す。今ある行の字面は変えない |
| `switch` | `request` の次に `spec-check` を足す |
| 文書 | `docs/policy.md` の `src/cli.ts` の行へ `` `spec-check` `` を足す。構成の表へ `src/spec.ts` の行を足す。`AGENTS.md` のコマンドの例と README の開発中の起動の例へ `bun src/cli.ts spec-check` を足す。README のコマンドの表へ `spec-check` の行を足す |
| テスト | 一時ディレクトリを作業ディレクトリにして `bun src/cli.ts spec-check` を実行する。今のリポジトリの `docs/spec/` が通ることは、受け入れ条件にしない |

しきい値は、今の正本を、下の「比較」と同じ作り方で測って決めた。課題本文が同じ内容として挙げた段落どうしの組は入り、一つの段落を分割した箇条は入らない。一語だけ違う平行な文も 5 分の 3 以上になることがあり、その組も近い組として出す。今の正本がこの検査を通ることは求めない。

| 組 | 共通 | 和集合 | 5 分の 3 以上 |
|---|---|---|---|
| sdd REQ-361 と REQ-370 | 66 | 75 | 入る |
| runner REQ-517 と REQ-540 | 112 | 134 | 入る |
| sdd REQ-454 と REQ-466 | 76 | 109 | 入る |
| sdd REQ-450 と REQ-465 | 100 | 154 | 入る |
| runner REQ-519 と REQ-542 | 88 | 145 | 入る |
| runner REQ-517 と REQ-553 | 73 | 155 | 入らない |
| runner REQ-519 と REQ-557 | 47 | 159 | 入らない |

88 * 5 は 440、145 * 3 は 435 であり、REQ-519 と REQ-542 は入る。73 * 5 は 365、155 * 3 は 465 であり、REQ-517 と REQ-553 は入らない。

`checkSpec` は、作業ディレクトリの `docs/spec/` だけを読む。`gh` も `git` も呼ばない。

```ts
export async function checkSpec(root: string): Promise<string[]>
```

戻り値は、標準エラーへ書く行である。行の中に改行は無い。ディレクトリが無いときと、見つけたものが無いときは、空配列である。読み取りに失敗したときは、`message` が `正本を読めません` である `Error` を投げる。`src/cli.ts` は、その `message` だけを標準エラーへ書く。

## 比較

見出しは、行全体が `## REQ-` のあとに、十進で先頭の零の無い 1 以上の整数が続き、それ以外の文字が無い行である。識別子は `REQ-` とその整数である。ファイルの先頭が見出しでなくてもよい。

本文の行は、その見出しの次の行から、次の見出しの前までである。最後の見出しの本文は、ファイルの末尾までである。

ファイルは、`\r\n` と `\r` を `\n` にそろえてから、`\n` で行に分ける。末尾が `\n` のときは、最後に空の行が一つ残る。

由来の行は、行全体が `もとになった課題は #` のあとに、十進で先頭の零の無い 1 以上の整数、空白一つ、`である。` が続く行である。前後に空白がある行は、由来の行ではない。

比較する本文は、本文の行から由来の行を除き、残った行を、元の順で `\n` ではさんだ文字列である。残った行が無いときは空文字列である。残った行が一つのときは、その行だけであり、前後に `\n` は足さない。

2-gram は、その文字列を Unicode の符号位置の列にして、先頭から隣り合う二つを一つにしたものである。同じ二つは、集合に一つである。

二つの要求を A と B とする。A の集合と B の集合の共通の個数を n、和集合の個数を u とする。u が 0 のとき、その組は近くない。u が 1 以上で `n * 5 >= u * 3` のとき、その組は近い。組は順不同であり、同じ組は一件である。

`あいうえお` と `あいうえか` は、共通が 3、和集合が 5 であり、近い。`あいうえお` と `かきくけこ` は、共通が 0 であり、近くない。

## 壊れた文末

候補は、要求の本文の行だけである。見出しの行と、どの要求の本文でもない行は、候補にしない。

行末のスペースとタブを除いた末尾が、`ないである`、`するである`、`いるである`、`あるである`、`るである`、`うである` のいずれかであり、その直後に `。` があるか、そこで行が終わるとき、候補である。行の途中だけがこの形で、末尾が違う行は、候補ではない。

先頭の空白を除いて、バッククォート三つで始まる行は、フェンスの開閉である。開閉の行は、壊れた文末にしない。開いたあと、次の開閉の行より前の行は、フェンスの中であり、候補から除く。ファイルの先頭では、フェンスは閉じている。

末尾が `こうである`、`そうである`、`どうである` のいずれかであり、その直後に `。` があるか、そこで行が終わる行は、除く。これらは文として成り立つ。

除いたあとに残った行ごとに一件である。同じ要求に二行あれば二件である。

今の正本で、この候補に合い、除外に当たらない行は、要求の本文に残っている。フェンスの中の行と、`こうである`、`そうである`、`どうである` で終わる行は、今の正本には無い。除外は、その形を後から書いても誤って出さないための規則である。

## 空の本文

空白は、スペース、タブ、改行、復帰、全角スペースである。本文の範囲の文字が、この五種類以外を含まないとき、本文は空である。見出しの直後が次の見出しであり、範囲が空であるときも、空である。

由来の行は、この判定では除かない。由来の行だけがある要求は、空ではない。

## 出力

標準エラーの行は、次の四つである。種類が違う見つけたものは、別の行である。

識別子の重複は、`識別子が重複しています: ` のあとに識別子を書き、空白一つを置いて、出現ごとのパスを空白一つではさんで書く。パスは `docs/spec/` とファイル名を `/` でつないだものである。出現の順は、ファイル名の符号単位の昇順であり、同じファイルでは行番号の昇順である。同じファイルに二度あれば、そのパスは二度書く。三回以上でも、この一行である。識別子どうしの順は、番号の数値の昇順である。

空の本文は、`本文が空です: ` のあとにパス、空白一つ、識別子を書く。順は、ファイル名の符号単位の昇順であり、同じファイルでは見出しの行番号の昇順である。

壊れた文末は、`壊れた文末です: ` のあとにパス、空白一つ、行番号、空白一つ、識別子を書く。行番号は、改行を `\n` にそろえたあとの行の番号であり、1 から始まる十進で、先頭の零は付けない。順は、ファイル名の符号単位の昇順であり、同じファイルでは行番号の昇順である。

近い組は、`本文が近いです: ` のあとにパス、空白一つ、ファイルの中で先に出る識別子、空白一つ、後に出る識別子を書く。順は、ファイル名の符号単位の昇順、同じファイルでは先の見出しの行番号の昇順、同じ先では後の見出しの行番号の昇順である。

四種類の順は、識別子の重複、空の本文、壊れた文末、近い組である。行の中に改行は無い。標準出力へは、成功のときも失敗のときも、何も書かない。

`src/cli.ts` は、`checkSpec` の戻り値の各文字列を、`console.error` で一行ずつ書く。一件以上のときは終了コード 1 である。一件も無いときは 0 である。

## 例

近い組のファイル `docs/spec/a.md` は、末尾の改行を含めて、次である。

```
## REQ-1
あいうえお
## REQ-2
あいうえか
## REQ-3
かきくけこ
```

標準エラーは `本文が近いです: docs/spec/a.md REQ-1 REQ-2` の一行である。`REQ-3` の本文は、末尾の改行によって空の行が一つ残る。`REQ-1` とも `REQ-2` とも近くない。

近い組が無いファイルは、`あいうえお` と `かきくけこ` の二つの要求である。終了コードは 0 であり、標準出力も標準エラーも空である。

由来の行を除くファイルは、`REQ-1` の本文が `もとになった課題は #1 である。` と `あいうえお`、`REQ-2` の本文が `もとになった課題は #2 である。` と `あいうえか`、そのあとに `REQ-3` の本文 `か` がある。標準エラーは `本文が近いです: docs/spec/a.md REQ-1 REQ-2` の一行である。由来の行がどちらも `もとになった課題は #1 である。` であり、残りが `あいうえお` と `かきくけこ` の組は、近くない。

別ファイルの同じ本文は、`docs/spec/a.md` の `REQ-1` と `docs/spec/b.md` の `REQ-2` がどちらも `同じ本文です。` であるとき、近い組にしない。終了コードは 0 である。

壊れた文末が二行のファイルは、`## REQ-1` の次の行が `呼ばないである。`、その次の行が `作るである。` である。行ごとに二件である。`状態はこうである。`、`状態はそうである。`、`状態はどうである。`、`することである。` は書かない。開きがバッククォート三つだけの行、その次の `呼ばないである。`、その次の閉じがバッククォート三つだけの行、はこの一件に数えない。

空の本文は、`## REQ-1` の次が空行だけで `## REQ-2` があるときと、`## REQ-1` の次の行が全角スペースだけであるとき、`本文が空です: docs/spec/a.md REQ-1` を書く。`もとになった課題は #1 である。` だけの要求は、空にしない。

識別子が `docs/spec/a.md` と `docs/spec/b.md` に一度ずつあるときは、`識別子が重複しています: REQ-1 docs/spec/a.md docs/spec/b.md` の一件である。`a.md` に二度、`b.md` に一度あるときは、`識別子が重複しています: REQ-1 docs/spec/a.md docs/spec/a.md docs/spec/b.md` の一件である。この三つの本文は `あいうえお`、`かきくけこ`、`さしすせそ` であり、近い組にはしない。

四種類が同時にあるとき、`docs/spec/a.md` は末尾の改行を含めて次である。

```
# a

## REQ-9

## REQ-4
呼ばないである。
作るである。
## REQ-4
あいうえお
```

`docs/spec/b.md` は末尾の改行を含めて次である。

```
# b

## REQ-8
あいうえお
## REQ-7
あいうえか
## REQ-6
かきくけこ
```

標準エラーは、次の五行である。

```
識別子が重複しています: REQ-4 docs/spec/a.md docs/spec/a.md
本文が空です: docs/spec/a.md REQ-9
壊れた文末です: docs/spec/a.md 6 REQ-4
壊れた文末です: docs/spec/a.md 7 REQ-4
本文が近いです: docs/spec/b.md REQ-8 REQ-7
```

`a.md` の 1 行目は `# a`、6 行目は `呼ばないである。`、7 行目は `作るである。` である。終了コードは 1 であり、標準出力は空である。

引数が `foo`、`--help`、`-h`、または二つあるときは、壊れた文末がある一時ディレクトリでも、標準エラーは `引数は受け取れません` の一行だけである。`bun src/cli.ts --help` の標準エラーには、行全体が `sdd-cur spec-check` である行がある。

`docs/spec/` が無い一時ディレクトリは、終了コード 0 であり、標準出力も標準エラーも空である。`docs/spec` がファイルであるときは、標準エラーは `正本を読めません` の一行であり、終了コードは 1 であり、標準出力は空である。

## テスト

`bun test` で実行する。`gh`、`git`、`agent` は起動しない。ホームディレクトリと、実行中の Cursor のスキルは触らない。ファイルを作るときは一時ディレクトリを使い、終わったら消す。新しい `test` は `src/122.test.ts` だけに足す。既存の `src/*.test.ts` に、新しい `test` は足さない。

検査の結果を見る `test` は、一時ディレクトリを作業ディレクトリにして、`bun src/cli.ts spec-check` を実行する。標準出力と標準エラーを受け取る。今のリポジトリの `docs/spec/` を作業ディレクトリにして、この検査が終了コード 0 であることを確かめる `test` は、足さない。例の節のファイルを、その一時ディレクトリに置く。

### 追加 spec REQ-808

もとになった課題は #122 である。

`spec-check` は、同じ `docs/spec/<ファイル名>` にある二つの要求の組を見る。別のファイルの要求は組にしない。比較する本文は、要求の本文から、行全体が `もとになった課題は #<番号> である。` である行を除いた残りである。`<番号>` は十進で、先頭の零は無い。近さは、その残りの、隣り合う二つの符号位置を一つとする 2-gram の集合の Jaccard 係数である。同じ 2-gram は集合に一つである。共通の個数を n、和集合の個数を u とする。u が 0 のときは近くない。u が 1 以上で n * 5 が u * 3 以上のとき、その組は近い。近い組は、その組を一件として数える。

### 追加 spec REQ-809

もとになった課題は #122 である。

壊れた文末の候補は、要求の本文の行である。行末のスペースとタブを除いた末尾が、`ないである`、`するである`、`いるである`、`あるである`、`るである`、`うである` のいずれかであり、その直後に `。` があるか、そこで行が終わるとき、候補である。先頭の空白を除いてバッククォート三つで始まる行は、フェンスの開閉であり、候補にしない。開いたあと、次の開閉の行より前は、候補にしない。末尾が `こうである`、`そうである`、`どうである` のいずれかであり、その直後に `。` があるか、そこで行が終わる行は、除く。除いたあとに残った行ごとに一件である。同じ要求に二行あれば二件である。

### 追加 spec REQ-810
