# spec

## REQ-1

正本は `docs/spec/<領域>.md` に置く。`<領域>` は英小文字で始まり、英小文字と数字が続き、区切りのハイフンを含んでよい。課題ごとの要件と設計は `docs/specs/<番号>/requirements.md` と `docs/specs/<番号>/design.md` である。

## REQ-2

要求の識別子は `REQ-` に、十進で先頭の零の無い 1 以上の整数を続けたものである。同じ識別子は正本に一度だけある。変更は識別子を変えない。

## REQ-3

課題の設計には `## 正本への差分` がある。項目の見出しは `### 追加 <領域> REQ-<番号>`、`### 変更 <領域> REQ-<番号>`、`### 削除 <領域> REQ-<番号>` のいずれかである。追加は正本に無い識別子の要求を、その領域のファイルへ足す。変更は正本にある識別子の要求の内容を、項目の本文へ変える。識別子は変えない。削除は正本にある識別子の要求を正本から除く。

## REQ-4

追加、変更、削除の項目の本文は、その識別子の要求の内容である。追加と変更の本文は、正本に残す内容である。削除の本文は、正本から除く内容である。この節だけで、何が変わるかが読める。

## REQ-5

設計の作成役は、課題の設計に `## 正本への差分` を書く。正本のファイルは書かない。

## REQ-6

設計のレビュー役は、`## 正本への差分` の各項目が、識別子付きの追加、変更、削除のいずれかとして書かれていることを見る。変更と削除の項目に、その識別子の要求の内容があることを見る。差分だけで、何が変わるかが読めることを見る。識別子が当時の正本に対して追加、変更、削除のどれに該当するかは見ない。その機械確認は #85 の検査が行う。#85 の検査を通った前提で、差分が課題の受け入れ条件と矛盾しないことを見る。他の課題の `docs/specs/` との食い違いと巻き戻しは、これまでどおり見る。マージ後の正本が差分どおりかは見ない。

## REQ-7

実装の作成役は、コードと同じ作業ツリーで、設計の `## 正本への差分` を `docs/spec/` へ反映する。要求ファイルと設計ファイルは変えない。正本の変更は、その実装のマージリクエストに入る。

## REQ-8

完了処理は、マージリクエストのスカッシュマージと「マージ済み」の付与のままである。正本をまとめ直す段は無い。スカッシュマージのあと、main の正本と、同じマージリクエストに入ったコードは一致する。

## REQ-9

実装レビュー役は、作業ツリーの `docs/spec/` が、その課題の設計の `## 正本への差分` どおりに変わったかを見る。

## REQ-10

#85 の検査は、追加する識別子が正本にまだ無いことを見る。変更する識別子と削除する識別子が正本にあることを見る。見ている正本は、その差分を反映する前の正本である。
