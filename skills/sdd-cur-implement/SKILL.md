# sdd-cur-implement

## 実装

プロンプトのスキル名のあとにある課題番号と絶対パスを使う。親は作業ツリーへ実装を書かない。実装を書くのは、実装作成役と修正役だけである。

`docs/specs/<番号>/requirements.md` と `docs/specs/<番号>/design.md` を読み、その設計の受け入れ条件、決定、範囲の中だけを作業ツリーへ実装する。人がこのスキルを直接依頼したときも、課題ランナーが起動したときも、同じ手順である。`show` は呼ばない。業務ラベルでは止まらない。

サブエージェントは、次の三つを名前で起動する。作成と修正に model は渡さない。frontmatter の `model` を使う。

- `sdd-cur-implement-author`
- `sdd-cur-implement-reviewer`
- `sdd-cur-implement-fixer`

実装作成役を起動する。作業ツリーを変えないで止まったときは、レビューを起動しない。理由は `実装作成が作業ツリーを変えませんでした` である。agent は失敗で終える。終了コードは 0 以外である。理由は日本語の一行であり、標準エラーの最初の非空行、それが空のときは標準出力の最初の非空行に書く。

作業ツリーを変えたあとは、親が受け入れ手順の本文を、渡された絶対パスへ書く。サブエージェントには手順パスを渡さない。印の行は書かない。この本文が、レビュー合格後に更新してよい最初の本文である。

## レビュー

レビューはこのスキルの中で行う。課題ランナーは、レビューのために別の agent を起動しない。

実装作成のあと、レビューと修正指示を起動する。レビューはサブエージェントが実行し、そのレスポンスが指摘である。指摘はどこにも置かない。ファイルにも課題コメントにも残さない。人に確認しない。

レビューの対象は、作業ツリーの実装である。見るのは、その実装が要求どおりに作られているかと、設計通りに作られているかである。

不合格の回数は、この一回の agent 起動の中だけで数える。開始時は 0 である。ファイルにも課題コメントにも書かない。ランナーが `implement` を再試行しても、回数は引き継がない。最後の非空行が `判定: 不合格` のときに 1 増やす。1 回目と 2 回目のレビューは model を渡さない。1 回目と 2 回目が続けて不合格のとき、3回目から model に `grok-4.7-high` を渡す。合格まで渡す。10 回目も、その回が 3 以上なら high を渡してから判定を見る。

レビュー役のレスポンスの最後の非空行は `判定: 合格` か `判定: 不合格` である。親はこの一行だけで分岐する。合格のとき、この行以外の評価文は必須ではない。不合格のとき、判定行より前に、作業ツリー上のどこ（パス等）の何が、要求または設計のどの点に反するかを書く。

最後の非空行が `判定: 合格` のときは、修正を起動しない。最初の本文が実装と合わないときだけ、親が同じパスの本文を書き直す。印の行は書かない。成功で終える前の本文は、空でなく、最初の非空行は印ではない。

最後の非空行が `判定: 不合格` のときは、増やした回数が 10 のときは、修正も次のレビューも起動しない。理由は `実装レビューが不合格のまま10回に達した` である。agent は失敗で終える。

増やした回数が 9 以下のときは、人に確認しない。修正指示は変える部分の差分だけであり、全文は書かない。差分だけを修正へ渡す。修正のあと、レビューと修正指示に戻る。不合格のあと、実装作成役は起動しない。

レビューの最後の非空行が、合格と不合格のどちらでもないときは、修正も起動しない。理由は `レビューの判定がありません` である。agent は失敗で終える。

失敗で終えるとき、終了コードは 0 以外である。理由は日本語の一行であり、標準エラーの最初の非空行、それが空のときは標準出力の最初の非空行に書く。成功の完了では終えない。成功で終えたとき、ランナーは手順ファイルを読み、受け入れ手順のコメントと実装完了へ進む。

## 禁止

課題を作らない。課題を閉じない。ラベルを変えない。コミットしない。push しない。マージリクエストを作らない。スカッシュマージしない。コメントを投稿しない。`gh` を直接起動しない。要求ファイルと設計ファイルは作らない。変えない。
