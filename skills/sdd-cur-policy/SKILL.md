# sdd-cur-policy

## 起動

人がこのスキルを明示して起動したときだけ、下書きの手順を行う。
人がこのスキルを明示して起動していないときは、下書きの手順を行わない。
明示したとみなす字面の一覧は、作らない。
導入先は、このスキルを起動した作業ツリーである。

## 読む

下書きの手順は、作業ツリーのコードを読む。
作業ツリーに README があるときは、その README を読む。
作業ツリーに README が無いときは、README を読まない。
README が無いときは、README を除き、下書きの手順が読むほかの対象だけで進める。
README が無いときは、README を根拠にする記述を書かない。
下書きの手順は、作業ツリーのパッケージ定義を読む。
作業ツリーに `package.json` が一つあるときは、そのファイルを読む。
作業ツリーに `package.json` が複数あるときは、作業ツリーのルートにある `package.json` だけを読む。
下書きの手順は、作業ツリーの最上位のディレクトリ構成を読む。
下書きの手順は、テストの実行方法を読む。
根拠にするファイルは、作業ツリーの中のファイルだけである。

## 書く先

ファイルを書くとき、書くパスは、作業ツリーの `docs/policy.md` だけである。
`policyTemplate` の非空行は、次の八つである。
- `## 誰のための道具か`
- `この節には、誰のための道具かを書く。`
- `## 技術の前提`
- `この節には、技術の前提を書く。`
- `## 構成`
- `この節には、構成を書く。`
- `## 破ってはいけない原則`
- `この節には、破ってはいけない原則を書く。`
行の一致は、行全体が、この八つのいずれかと一文字も違わないことである。
作業ツリーから `policyTemplate` を読む手順は、このスキルには無い。
通常ファイルは、`stat` の結果で `isFile()` が真であるファイルである。
`docs/policy.md` が存在し、通常ファイルではないときは、そのパスの内容を変えない。
そのときは、下書きを書かない。
そのときは、理由を人に伝えて止まる。
そのときは、非空行の一致は見ない。
そのときは、人が候補を選んでも、そのファイルへは書かない。
作業ツリーに `docs/policy.md` が無いときは、そのパスへ四節の下書きを書く。
作業ツリーに `docs/policy.md` があり、それが通常ファイルであり、非空行がすべて上の八つのいずれかであるときは、そのパスへ四節の下書きを書く。
非空行が一つも無い `docs/policy.md` は、一致しない非空行が無い。
そのファイルが通常ファイルであるときも、四節の下書きを書く。
作業ツリーの `docs/policy.md` が通常ファイルであり、上の八つのどれとも一致しない非空行があるときは、そのファイルの内容を変えない。
そのときは、一つのファイルと一つの行番号がある記述のうち、その文がまだそのファイルに無いものを、人に見せる。
そのときは、そのファイルへ書かずに止まる。
このときは、人が候補を選んでも、そのファイルへは書かない。
`docs/policy.md` への書き込みが失敗したときは、下書きを完了とみなさない。
そのときは、失敗理由を人に伝えて止まる。
失敗したあとの `docs/policy.md` は、書き込みを始める前と同じである。

## 記述

下書きの、行頭が `#` である行は、この順だけである。
一つ目は `## 誰のための道具か` である。
二つ目は `## 技術の前提` である。
三つ目は `## 構成` である。
四つ目は `## 破ってはいけない原則` である。
これ以外の、行頭が `#` である行は、下書きに書かない。
下書きに書く記述は、一文である。
その文は、作業ツリーの中の一つのファイルと、一つの行番号を含む。
行番号は十進であり、先頭の零は付けない。
パスは、作業ツリーからの相対パスである。
パスは、`/` では始めない。
パスは、`./` では始めない。
根拠の表記は、全角の始め括弧、バッククォート、そのパス、バッククォート、半角空白、の、半角空白、その行番号、半角空白、行、全角の終わり括弧、の順である。
記述の行は、`#` で始めない。
根拠のファイルと行が無い点は、`docs/policy.md` に書かない。
その点は、人に質問する。
人の答えだけでは、根拠のファイルと行が無い記述を書かない。
根拠のファイルと行が無い点を質問することは、ほかの記述を下書きへ書くことを止めない。
「誰のための道具か」の記述に、ファイルと行の組が二つ以上あるときは、候補を出して人に選ばせる。
「破ってはいけない原則」の記述に、ファイルと行の組が二つ以上あるときは、候補を出して人に選ばせる。
候補は、その記述と、作業ツリー内の一つのファイルと、一つの行番号の組である。
人がまだ選んでいない候補に当たる記述は、`docs/policy.md` に書かない。
候補を出していて、人がまだ選んでいないあいだは、`docs/policy.md` を書かない。
人が選んだ組は、明示して起動したときの依頼に含まれる。
依頼に、選んだ組が無いときは、まだ選んでいない。
人が一つの候補を選び、このスキルを明示して起動しているときは、選んだファイルと行番号を、その記述の根拠にする。
そのとき、`docs/policy.md` が無い、または通常ファイルであり非空行がすべて上の八つのいずれかであるときは、選んだ記述を含めて四節の下書きを書く。
「技術の前提」と「構成」では、ファイルと行の組が二つ以上ある記述は、下書きに書かない。
その二節では、候補を出さない。
その点を人に質問する手順は、このスキルには無い。

## 禁止

課題を作らない。
課題を変えない。
ラベルを変えない。
課題コメントを書かない。
作業ツリーの `docs/policy.md` 以外のパスへは書かない。
`src/init.ts` は変えない。
