# sdd-cur-create-issue

## 作成

使い分ける課題のタイプは、ユーザーストーリー、修正、機能改善、調査の四種類である。選べるタイプはこの四種類だけである。

人が明示して起動したあと、起動時の作業ツリーが git リポジトリかを、どのタイプの課題を作るかを人に聞くより前に見る。git リポジトリでないときは、課題を作る前にそれを見て、どのタイプの課題を作るかを人に聞くより前に止まる。課題を作らない。git リポジトリでない旨を伝える。`gh issue create` は実行しない。本文用の内容がスペースと改行以外の文字を含み、渡した内容から題を決められないときは、先に git リポジトリでない旨を伝え、次に題を決められない旨を伝える。この二つの伝達は、どのタイプの課題を作るかを人に聞くより前である。本文用の内容が無いか、渡した内容がスペースと改行だけであるときは、題を決められるかを、タイプ向けの質問の答えから本文を組み立てたあとで見る。本文用の内容が無いか、渡した内容がスペースと改行だけであり、起動時の作業ツリーが git リポジトリでないときは、その組み立てより前に止まる。この停止では、題を決められない旨は伝えない。

作業ツリーが git リポジトリであるとき、質問は次の順である。`gh issue create` より前に行う。
1. どのタイプの課題を作るかを、Cursor の質問機能の選択肢で人に聞く。選択肢は四つであり、この順である。選択肢の ID は `ユーザーストーリー`、`修正`、`機能改善`、`調査` である。人が読む文言は、同じ順で、各 ID と一文字も違わない。人が選んだタイプは、選ばれた選択肢の ID である。
2. 人がその四つの ID のうち一つを選んだあと、そのタイプ向けの質問を、そのタイプの一覧の順に、一問ずつ、その一覧だけ聞く。一覧の最後の質問まで聞く。

タイプの選択で、自由記述の答えの空白除去は、採用しない。

本文用の内容をすでに渡しているときも、本文用の内容が無いときも、渡した内容がスペースと改行だけであるときも、作業ツリーが git リポジトリであるときのこの順は同じである。人が内容を渡していることは、課題を作る前提ではない。本文用の内容が無いとき、および渡した内容がスペースと改行だけであるときは、内容が欠けていることを理由に止まらない。内容が欠けていることを理由に不足を伝えない。内容が欠けていることを理由に課題を作らない、とはしない。

どのタイプの課題を作るかで選ばれた選択肢の ID が、ユーザーストーリー、修正、機能改善、調査のどれでもないときは、同じ四つの ID の選択肢で、Cursor の質問機能から選ぶよう聞き直す。その ID では課題を作らない。`gh issue create` は実行しない。聞き直したあと、その四つの ID のうち一つを選んだときは、選んだタイプ向けの質問へ進む。

タイプ向けの質問は、選んだタイプの一覧の順に、一問ずつ、一覧の最後まで聞く。各質問には、スペースと改行以外の文字を含む答えが必要である。答えが空である質問、または答えがスペースと改行だけである質問が一つでもあるときは、課題を作らない。その質問を足りない質問として伝える。止まる。`gh issue create` は実行しない。

課題の本文は、選んだタイプの見出しだけを、下に書いた順で持つ。見出しは、行頭が `## ` である行である。一つの節は、その見出しの次の行から、次の見出しの直前までである。最後の節は、その見出しの次の行から、本文の終わりまでである。質問の答えがスペースと改行以外の文字を含むとき、節の本文はその答えである。ユーザーストーリーの最初の節だけ、先の質問の答え、改行、後の質問の答え、の順である。起動時に渡した内容そのものを課題の本文にしない。本文用の内容をすでに渡して課題を作るときは、渡した内容を本文を組み立てるときの素材・参考として使う。二つのタイプが違うとき、見出しの並びは違う。

ユーザーストーリーで人に聞く質問は、次の順に、一問ずつ聞く。この一覧以外は聞かない。
1. 誰のための変更ですか？
2. 何ができるようにしたいですか？
3. 背景はなんですか？
4. 手を入れる対象はどこですか？
5. 重なる課題はどれですか？
6. 比べる相手はありますか？

ユーザーストーリーの見出しは、次の順である。これ以外の見出しは置かない。
1. `## ユーザーストーリー`
2. `## 背景`
3. `## 手を入れる対象`
4. `## 重なる課題`
5. `## 比べる相手`

`## ユーザーストーリー` の節は、「誰のための変更ですか？」の答え、改行、「何ができるようにしたいですか？」の答え、である。`## 背景` の節は、「背景はなんですか？」の答えである。`## 手を入れる対象` の節は、「手を入れる対象はどこですか？」の答えである。`## 重なる課題` の節は、「重なる課題はどれですか？」の答えである。`## 比べる相手` の節は、「比べる相手はありますか？」の答えである。

修正で人に聞く質問は、次の順に、一問ずつ聞く。この一覧以外は聞かない。

2. どの手順で失敗しますか？
3. 失敗したとき、どうなるべきですか？
4. 背景はなんですか？
5. 重なる課題はどれですか？

起動時の作業ツリーが git リポジトリであり、かつ本文用の内容が無いか渡した内容がスペースと改行だけであるときは、題は、組み立てた本文をもとに、このスキルを実行するエージェントが決める。人は題を指定しない。題を人に尋ねない。組み立てた本文から題を決められないときは、課題を作らない。題を決められない旨を伝える。止まる。`gh issue create` は実行しない。組み立てた本文から題を決められ、起動時の作業ツリーが git リポジトリであるときは、`gh issue create` を 1 回実行し、課題を 1 件作る。

起動時に本文用の内容がスペースと改行以外の文字を含むときは、題は、渡した内容をもとに、このスキルを実行するエージェントが決める。人は題を指定しない。題を人に尋ねない。渡した内容から題を決められないときは、課題を作らない。題を決められない旨を伝える。止まる。`gh issue create` は実行しない。起動時の作業ツリーが git リポジトリでなく、本文用の内容がスペースと改行以外の文字を含み、渡した内容から題を決められないときは、先に git リポジトリでない旨を伝え、次に題を決められない旨を伝える。この二つの伝達は、どのタイプの課題を作るかを人に聞くより前である。

課題を作るのは、次をすべて満たすときである。`gh issue create` は 1 回である。内容が複数の話題でも、作る課題は 1 件である。
- 本スキルを明示して起動している
- 起動時の作業ツリーが git リポジトリである
- 課題のタイプが、選ばれた選択肢の ID として、ユーザーストーリー、修正、機能改善、調査の一つである
- そのタイプ向けの質問のすべてに、スペースと改行以外の文字を含む答えがある
- 題を決められる。本文用の内容がスペースと改行以外の文字を含むときは、渡した内容から決められることである。本文用の内容が無いとき、および渡した内容がスペースと改行だけであるときは、組み立てた本文から決められることである

明示して起動していないときは、課題を作らない。依頼が無いときは、課題を作らない。起動時の作業ツリーが git リポジトリでないときは、課題を作る前にそれを見て、どのタイプの課題を作るかを人に聞くより前に止まる。課題を作らない。git リポジトリでない旨を伝える。`gh issue create` は実行しない。本文用の内容がスペースと改行以外の文字を含み、渡した内容から題を決められないときは、先に git リポジトリでない旨を伝え、次に題を決められない旨を伝える。カレントディレクトリは、起動時の作業ツリーのままである。`--repo` は付けない。ラベル、担当者、マイルストーンは付けない。対話の編集はしない。認証は `gh` のログインに任せる。トークンも環境変数も読まない。課題が 1 件できたとき、その番号と URL をチャットで人に伝える。伝えたあとは止まる。課題を閉じない。
