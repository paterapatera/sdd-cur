## レビューのループ

呼び出し側は、ループに入る直前に、次を書く。
`review-next` の第1引数。
レビュー役の名前。
修正役の名前。
レビューの前に `validate` を実行するか。
返った `model` の空文字でレビュー役の名前を切り替える段は、上級レビュー役の名前も書く。

レビューの指摘はどこにも置かない。ファイルにも課題コメントにも残さない。
段の開始時、`consecutiveFailures` は 0、`previousFindings` は空文字、`brokenStampRetries` は 0 である。ファイルにも課題コメントにも残さない。

レビュー役のレスポンスを受け取ったら、`response`、`consecutiveFailures`、`previousFindings`、`brokenStampRetries` を、呼び出し側が書いた第1引数を使い、`sdd-cur review-next` の標準入力へ、JSON 一行で渡す。
返った一行 JSON の `action`、`model`、`kind` に従う。
その分岐が `reason`、`resultLine`、`rewriteProcedure` を含むときは、そのプロパティにも従う。
次に `review-next` を呼ぶとき、`consecutiveFailures`、`previousFindings`、`brokenStampRetries` は、直前の成功の標準出力が返した同じプロパティである。
`response` は、その呼び出しで判定するレビュー応答の全文である。

`action` が `修正` のとき、修正役を起動する。差分だけを渡す。作成役は起動しない。修正のあと、レビューに戻る。
`action` が `やり直し` のとき、レビュー役をもう一度起動する。修正役も作成役も起動しない。
`action` が `合格` のとき、修正役も作成役も起動しない。
`action` が `止まる` のとき、修正役を起動しない。

`validate` の失敗は、この標準入力へ渡さない。
`validate` の失敗は連続不合格に数えない。

`kind` が `stopBrokenStampTwice`、`stopSameFindingTwice`、`stopMissingConfirmLine` のときは、レスポンスを人に見せて止まる。修正を起動しない。レビューにも修正にも戻らない。

要求系の段では、要求レビュー役の初回の起動が、呼び出し側が書いたレビュー役の名前である。
`review-next` のあと、返った `model` が空文字のときは、呼び出し側が書いたレビュー役の名前で起動する。空でないときは、呼び出し側が書いた上級レビュー役の名前で起動する。
要求レビュー役を起動するとき model を渡さない。
要求レビュー役の起動で model を渡さない。
修正役と作成役には、model を渡さない。

要求系の段では、`kind` が `stopWaitConfirm` のとき、列挙された点を人に見せる。修正を起動しない。確認コメントは投稿しない。人が答えるまで、その部分は要求へ書かない。人が答えたあとに要求レビュー役を再び起動するとき、返った `model` が空文字なら、呼び出し側が書いたレビュー役の名前である。返った `model` が空でないなら、呼び出し側が書いた上級レビュー役の名前である。この再起動は回数を増やさない。

設計系と実装の段では、`model` が空文字のときは、レビュー役に model を渡さない。空でないときは、その文字列をレビュー役の model に渡す。修正役と作成役には、model を渡さない。

設計系の段では、`kind` が `stopWaitConfirm` のとき、列挙された点を人に見せる。修正を起動しない。確認コメントは投稿しない。人が答えるまで、その部分は設計へ書かない。人が答えたあとは、返った `model` でレビューを再び起動する。この再起動は回数を増やさない。モデルは、`確認: あり` を返したそのレビューと同じである。
